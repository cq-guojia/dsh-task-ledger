# 未初始化身份时怎么走

触发：任何命令**退出码为 100**。身份是用户自己的，**不是你的决定**。

> **路径约定**：下文 `<SKILL 目录>` = 本 skill 的安装目录（即你正在读的这份 `SKILL.md` 所在目录）。**交给用户前必须替换成真实绝对路径**，不要原样把 `<SKILL 目录>` 这几个字留给用户。

## 给用户的话（照原样转述；但先把 `<SKILL 目录>` 换成真实绝对路径）

> 这台机器还没有身份。在终端运行 `<SKILL 目录>/scripts/progress init` 进入初始化引导（交互式选 / 建身份）；或打开看板「设置 → 创建身份」直接建立用户。

## 你的硬约束（你读，用户不看）

- 给用户的命令必须**保留绝对路径**（`<SKILL 目录>/scripts/progress init`）；交给用户前把 `<SKILL 目录>` 换成真实绝对路径（即本 `SKILL.md` 所在目录；不确定就用工具列出该目录确认 `scripts/progress` 的位置）。简写成 `progress init` 用户一跑就 `command not found`；若报 `Permission denied` 就改成 `sh <绝对路径> init`。
- 你**不得代跑** `init --claim` / `init --new` / 任何 `--yes`（脚本拒绝），身份必须由用户自己在终端建；不要基于「上次确认过 / 同名 / 记得 uuid」自行重建（重建会换新 uuid、断开旧任务关联）。
- **不要诊断、不要排查**：别 `ls` / `cat` identity 或读台账 / 读 skill 源码，忽略上下文里已做的排查动作；未初始化时不写任何东西；用户跑完再重跑原命令。
