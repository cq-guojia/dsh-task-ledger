# 过程文档（worklog）

> TL;DR：六节固定；前五节 agent 改，末节「执行记录」只由脚本写。改完正文必须 `log`，交付也要 `log`。老文档缺末节时脚本自动补。

## 六节结构

| 节 | 写什么 |
|---|---|
| 背景 | 为什么做：触发它的原话 / 现象 / 链接 |
| 待办 | 还没做的、没验证的、等别人给东西的 |
| 下一步 | 下一个**具体动作**（文件:行号 级别），不要写「继续推进」 |
| 过程 | 踩坑与证据：带 revision + `文件:行号` 或符号名 |
| 结论 | 做成了什么、留了什么坑；只写可验证事实，评价留给用户验收 |
| 执行记录 | 脚本维护，**禁手改** |

标题结构不能改名 —— 但**这只是纪律，脚本不校验**：它只认精确的 `## 执行记录` 这一行（改个名字就会在文末再补一节，出现两个小节）；六节名与任务标题也不做比对。建档只由 `new` 做（按 `assets/worklog.md` 模板生成骨架并写入任务对象的 `worklog` 字段）。

## 执行记录

- 一行一事件：`- 2026-10-19 12:08:33 · log · @GuoJia-Agent · 说明`。
- 类型：`new`（建）/ `claim`（认领）/ `set`（改状态、owner 变更）/ `release`（`set --status open` 释放）/ `log`（手记）/ `close`（结案）。
- **只追加、不改旧行**：`@谁` 记的是这次动手的人，不是任务现 owner —— 释放/重新认领后旧记录仍留在原负责人名下。
- 老 worklog 没有这一节：脚本第一次记时在文末自动补一节（正文不迁移），agent 不用也不许手动加。
- 过程文档丢失：`log` 报错退出（`updated` 已刷新），用 `show --id` 查路径，**不要手写这一节**。

## 编辑既有任务

1. `show --id` 拿任务 JSON + worklog 全文与路径；
2. 直接改前五节；
3. **立刻** `log --id <任务号> --note "补了…/改了…"`。

**改正文必配一条日志**：只要动过正文（哪怕一处错字、一个标题），就必须跟一条 `log`；没有日志的正文改动等于没发生过。同一次编辑动作里连改多处，只记一条。

已结案任务：worklog 已封卷、不在状态表，用 `history` 给出的回链找回，只读不改。

## 交付与封卷

- **交付（待验收）**：任务仍留 `doing`；「待办」写「待用户验收」，「下一步」写清验收看什么（哪条命令 / 哪个文件）；按收工三步记一条 `log --note "已交付待验收：…"`。
- **封卷**：`close` 打封卷标记，此后不再修改；历史行按结案时间写入 `ledger/history/<年月>.md`（存量 `ledger/PROGRESS-HISTORY.md` 只读兼容，不再写入）。
