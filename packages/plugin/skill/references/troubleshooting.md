# 排错

> TL;DR：非 0 退出就停手、原样报告，不要绕过脚本改台账 JSON 或历史层。**退出码 0 也要看输出**：提交失败会退 1，推送失败仍退 0、原因只写在输出里。并发冲突重跑一次；同步交给脚本，只有提示说脚本已回滚、或说它不替你 rebase 时，才让用户手动合并。

## 退出码

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功（同步可能失败：输出里有 `提示：` 就要读） | — |
| 1 | 业务错误（参数值 / 状态 / 权限不对；**提交失败也是 1**） | 按提示纠正后重试；改不了的报告用户 |
| 2 | 命令行参数错误（argparse 自退） | 看 `<子命令> --help` 重新拼参数 |
| 3 | 未预期的内部失败（如台账 JSON 损坏） | 上报，不要重试 |
| 130 | 被中断 | 重跑一次 |

## 常见错误 → 处置

- **「读不到 git 身份（user.email）…按兜底身份记账」**：本次用了兜底身份（系统用户名 / 主机名 / `default`），命令已成功。让用户配 `git config user.email`，否则任务记不到正确名下。
- **「任务还没人认领（在 pool.json 里）」/「不在你的分片里」**：任务在公共池或别人分片。要接手先 `claim`；换人只能「对方 `set --owner ""` 释放 → 你 `claim`」，不要绕过脚本改 JSON。
- **「池里的任务状态不一致（owner=…，status=…）」**：池里混进了已认领的任务（多半搬移崩了一半）。跑 `validate` 看全部问题，确认哪份最新后删掉多余那份，或重跑一次对应命令（幂等）。
- **「没有 N 的分片（owners.json 里也没登记）」**：`--owner` 传的身份写错了。身份是 git 邮箱，键在 `ledger/owners.json` 的 `workers` 里。
- **`log` 提示「没写进过程文档」**：worklog 路径丢失 / 不可读。命令**不失败**（退出 0，`updated` 已刷新并提交）；用 `show --id` 查路径，**不要手写「执行记录」**。
- **「文件在操作期间被改动」**（并发指纹冲突）：重新执行一次即可。
- **「格式版本是 … 当前是 …」**：纯提示，不拦，照常跑。
- **「本地有未提交的台账改动」**：写前只取本次要写的台账文件最新版，这些文件脏（手写 worklog 除外，它走 stash 通道）就先停下。先 `git add ledger/ && git commit` 再重跑；离线可加 `--no-sync`（子命令前后都能写）继续本地写。
- **「本地有 N 个台账提交还没推送」**：写前**直接中止**（没有自动补推这一步）。先 `git push`（非快进就 `git pull --rebase` / `merge` 后推），推完重跑；离线用 `--no-sync`，联网后统一提交推送。
- **「本地有 N 个你自己的提交还没推送 … 脚本不替你 rebase」**：推送被拒且本地有非台账提交。脚本故意不动它们，**不要重跑台账命令**（会二次写入）。让用户自己合并后 `git push`，台账改动已安全留在本地。
- **「没能确认本地有没有你自己的提交」**：旧版 git / 浅克隆下 `rev-list` 失败，按「可能有」保守处理。让用户 `git status` / `git log @{u}..HEAD` 自己看。
- **「本次推送会把本地 N 个你自己的提交一并推上去」/「写前把本地 N 个未推送的提交推上去了」**：纯告知，一句话带过，不要回滚、不要重推。
- **「本地已提交，但推送被拒」**：改动已安全落盘。看提示里 `git：` 那行原文：`! [rejected] ... (fetch first)` = 他人先推，脚本已自动合并过一次仍失败就手动合并台账文件；`Permission denied` / `could not read Username` = 凭据问题，找用户修。
- **「自动 rebase 未成功（已回滚到 rebase 前）」**：同一条任务被两边同时改了，仓库是干净的。按提示里的冲突原文手动合并后 `git push`。
- **「自动 rebase 冲突后回滚也失败了」**：仓库停在 rebase 中间态，**先别跑任何台账命令**。仓库根 `git rebase --abort`；仍失败看 `git status` 残留，必要时删 `.git/rebase-merge` / `.git/rebase-apply`。
- **「暂存了你的未提交改动」+ autostash 冲突**：改动在 stash 里没丢；提示点名的那几个文件带着 `<<<<<<<` 冲突标记，别当成品。解冲突后 `git stash drop`。
- **「git add 失败」/「自动提交失败」**：台账已写进本地文件只是没进 git（退 1）。按错误原话处理后手动 `git add <文件> && git commit -m "chore(ledger): ..."`。
- **「没有上游跟踪分支」/「detached HEAD」**：台账照写照提交到本地，不推送。让用户建上游或切回分支。
- **「写前快进没成功」**：通常工作区有未提交改动（git 按文件拦）。想快进先提交或 stash。
- **「worklog 正文疑似被覆盖成模板骨架」**：`validate` 对仍只有注释占位的在办任务打提示。从 git 恢复（`git checkout HEAD -- <路径>`）后重写正文，再 `log`。
- **「另一个会话正在同步同一份台账（已等 60 秒）」**：同一仓库另一个 agent 正在写。等它跑完再重跑，不要并行重试。

## validate 查什么（有问题 ⇒ 退出码 1）

problems（任一即退 1）：① 池里任务带着 owner；② 池里任务 status 不是 open/doing；③ 索引登记了身份但分片文件不在；④ 分片任务没有 owner；⑤ 分片任务 owner 与分片所属键不一致；⑥ 分片任务 status 非法；⑦ `owners/` 里有索引没登记的 `*.json`。
notices（只提示）：同号任务出现在多个文件、历史解析警告、历史有结案行但任务还在办、worklog 仍是骨架、存量 `PROGRESS-HISTORY.md` 存在、还没有 `owners.json`。
①~⑦ 里结构类的属人工裁决：读原文确认哪份是真的，删多余那份或把索引改对，**不要用脚本猜**。索引或任一 JSON 损坏 ⇒ 退 3。

## 写前取最新与写后同步（机制）

- 写命令全程持仓级锁（git 公共目录里的 `.sync.lock`，同仓库所有 worktree 共享，最多等 60 秒；`--no-sync` 也跳不过这把锁）。只读命令不排队。
- **写前**：先 guard 三查 —— scope 内非 worklog 台账文件有未提交改动 / 有未推送的台账提交 / 有未入库的同名文件，命中即中止；再定向取最新：自举 scope（`owners.json` + `pool.json` + 我的分片）加动作 scope（`new` 加目标文件与当月 worklog 目录；`claim` / `set` 还加索引里其他人的全部分片；`close` 加当月 `history/`；`tags --rename` 加整个 `worklog/`；任务没有 `worklog` 字段时退整个 `worklog/`）。干净就刷成远端最新，本地有未提交手写改动就 stash → 快进 → 叠回，冲突即中止。`worklog/` 里其余正文不动，只补本地缺的新文件。
- **写后**：只 `git add` 台账路径（带 `--no-verify`）后 commit —— 提交失败退 1；push 失败只提示、退 0，被拒时自动 `rebase --autostash` 合并一次：不同任务自动合并，同一任务两边都改留冲突标记让人定；本地有非台账提交时不 rebase。
- **回滚**：命令失败时，写前刷下来的内容按字节还原、本次新建的文件删掉；业务写的自补偿只有三处 —— `new`（删任务行 + 删文档）、`close`（三个文件按字节还原）、`tags --rename`（改过的每篇按字节还原）。
- **`--no-sync` / `TASK_LEDGER_NO_SYNC=1`**：跳过 guard、取最新、提交与推送；自举照跑；有写入时会提示「只写了本地文件、未签入 git」。
- **环境**：git ≥ 2.27（自动合并依赖 `rebase --autostash`）；没有 git 的目录自动跳过同步，台账照写。

## 硬约束

不要直接编辑 `ledger/pool.json`、`ledger/owners.json`、`ledger/owners/*.json`、`ledger/history/*.md`；不要另建 worklog；不要手写「执行记录」节。
