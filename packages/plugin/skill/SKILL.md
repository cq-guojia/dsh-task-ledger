# task-ledger

管一个工作区的任务进度：**谁在做、做到哪、什么时候建 / 结**。

- **数据落点与多人并行**：每个工作区下有一个 `ledger/` 目录，任务与进度以静态文件形式存放在里面。**多人协同必须有 git**；没有 git 只写本地，也能用。多人共用却没有 git，提醒用户。
- **任务状态**：`待认领（open）` = 建了还没人认领；`进行中（doing）` = 已认领、在做；`已结案` = 用户明确说结束后由 `close` 产生，此后只读。
- **操作方式**：台账的状态与归属只经命令改；唯一能手写的是过程文档前五节（见「手写边界」）。台账只记「建 / 做 / 结」和指向过程文档的链接；产出物本身按项目自己的约定落盘。

## 手写边界

- **唯一能手写的是任务的过程文档（worklog）前五节**（怎么写见「过程文档」节）；末节「执行记录」由脚本维护，**禁止手写、禁止手工添加**。
- **改正文前先确认任务在当前用户名下、状态 doing**：open 的先问用户，同意再 `claim`；别人名下的不动。
- **其他所有文件一律不许手改**：修改 / 删除 / 任何操作都走命令；手改台账文件即数据损坏。
- 台账看着不对劲（任务凭空少了、状态怪、分片对不上）⇒ **不要动手修**：让用户跑 `validate`（老月份的历史也要查就跑 `validate --deep`），把清单交给用户。

## 命令参考

十四个子命令：`init`（初始化本机身份，一台机器一次）+ 前五个写命令（`new`/`claim`/`set`/`log`/`close`）+ 后八个只读命令（`list` / `stats` / `owners` / `show` / `history` / `root` / `whoami` / `validate`）；何时用哪个见「任务生命周期」。参数语法看 `<子命令> --help`；下表说每个参数干什么、何时用。

只读命令里只有 `root` 特殊：**它在定位仓库之前跑**（「这个目录有没有台账」不能要求先有台账），不认 `--repo`、不读台账内容，只按结构判定。其余七个都先定位工作区根（带 `--repo` 或往上找）。

### init — 初始化本机身份

| 参数 | 含义 |
|---|---|
| （不带参数） | 只有当前仓库 `owners.json` 里已有人时才列出候选 uuid 供挑选；名册为空时直接报错 |
| `--claim <uuid>` | 认领名册里已有的 uuid（名字一起复制） |
| `--new --name "…"` | 新建身份：生成 uuid + 名字 |

干什么：写本机身份文件（`~/.taskledger/identity.json`），**一台机器只一次**，与台账无关。真终端里裸跑 `init` 是交互式选择框（↑/↓ 选、Enter 认领、末尾「+ 新建身份」输名字、Y/N 确认；每步下面都有一行灰色帮助，ESC 回上一步、Ctrl-C 取消；名字可直接写中文；哪一步退出，屏幕上自己画的那几行都会被抹掉，不留半截输入）；非终端（agent）下裸跑 `init` 只报名单，任何写操作都被脚本拒绝（Agent 不得代写/重建）。完整流程见 `references/init-identity.md`。

### new — 建任务

| 参数 | 含义 |
|---|---|
| `--title "…"` | 任务标题（必填）—— 就是「做了什么事」，一句话说清干啥，**前面不要加分类 / 类型 / 项目名之类前缀**（分类归 `--category`，别塞进标题）；它用来生成任务号和过程文件名，建议 4~20 字 |
| `--id` | 自定义任务号（一般不传；只能用小写字母、数字、汉字和连字符） |
| `--created` | 给过去漏记的任务补建时，补录实际创建日期（`YYYY-MM-DD`） |
| `--self` | 建并认领：直接归自己名下、状态「进行中」。仅当用户明确说「并开始做 / 并执行」时才用（判定见生命周期第 2 条） |
| `--category` / `--tags` | 分类 / 标签，**只在建任务时能设分类**，口径见本节末尾 |

干什么：建任务、按模板建好过程文档。不加 `--self` = 只建，落公共池等认领；加 `--self` = 建并认领。

分类 / 标签口径（`--category` 只有 `new` 有；`--tags` 三个命令都有）：`--category` 答「是什么类型」，单值，中文 ≤4 字 / 纯英文 ≤3 词，吃不准写「其他」，**建任务时给一次，之后谁都改不了**（`set` / `close` 没有这个参数，历史行里就是建任务时那个值；标题与创建时间同理，建完即不可变）。`--tags` 答「涉及什么」，0~5 个、逗号分隔，建任务时能想到就给（传空串等于没传）；在办期间用 `set --tags` 补；**结案是最该给终值的一段** —— 任务做完了、全貌最清楚，用 `close --tags` 定下来，不传就沿用原标签。**分类只进台账与历史**（`list` / `history` 看得到），**不写进过程文档**；过程文档头部只有标签行，标签可以涵盖分类（「建设」「修改」这类词直接当标签写）。查询用 tags（包含匹配，见 `list --tag`）。名词性短语、中文优先。正例：`--category 缺陷修复 --tags "镜像拉取,超时重试"`；反例：`--category 已完成登录修复`、`--tags 修 bug`。

举例：用户说「新建个任务：把发布流程走通」→ `new --title "把发布流程走通"`（只建，不认领）；用户明确说「新建个任务并开始做」→ `new --title "把发布流程走通" --self`。

### claim — 认领

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 认领哪个（必填） |

干什么：把公共池里的任务认领到自己名下，状态变「进行中」。已经在别人名下的会拒绝；已在自己名下的会提示无需重复。

举例：用户说「这活我领了」→ `claim --id 20261023-1117-把发布流程走通-7f3a`。

### set — 释放任务 / 改标签

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 哪条任务（必填） |
| `--release` | 释放回公共池（不带人） |
| `--owner <别人的uuid>` | 把任务转交给对方（预留通道，**agent 不用**，见纪律；只收 uuid，传名字当场报错） |
| `--tags <a、b>` | 改标签（顿号 / 逗号分隔，最多 5 个；写台账字段 + 过程文档头部标签行） |

干什么：两组用法，**不能混在一次调用里** ——

- `--release` / `--owner`：改归属。释放回公共池、状态回「待认领」，别人即可认领；没有单独的「改状态」入口。**这两个必须二选一、不能同给**。
- `--tags`：改标签。只改自己名下**在办**任务；给了就整组替换（没给的标签等于删掉）。同时改台账与过程文档头部那行（没有就插到最上面，有就原地改）。已结案（在历史里）的任务改不了。

**没有改分类的入口**：分类建任务时定死，`set` / `close` 都没有 `--category`。

只给 `--id` 会报错，要求你指明要做哪件事。

举例：用户明确说「把这个任务退回去」→ `set --id <任务号> --release`；「给这任务打上台账标签」→ `set --id <任务号> --tags 台账、看板`。

### log — 记一条进展

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 哪条任务（必填）—— 只能给自己名下的任务记，不在名下会直接被拒 |
| `--note "…"` | 这条记录说什么（必填；一句话，含命令 / `文件:行号` / 符号名 / 结论之一） |

干什么：刷任务的最后进度时间 + 在过程文档「执行记录」节追加一行。改正文必配一条 log（见纪律）。

举例：一轮干完 → `log --id <任务号> --note "改了认领即 doing（internal/actions/claim.go:56）；下一步同步文档"`。

### close — 结案

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 结哪条（必填） |
| `--summary "…"` | 结案摘要（必填；放弃写「放弃：原因」） |
| `--finished` | 给漏记的旧任务补用时，补录实际结案时间（`YYYY-MM-DD[ HH:MM[:SS]]`） |
| `--tags` | 覆盖标签终值（写进历史行；文档头部只写标签）。**结案时最该给**：任务做完了，最清楚涉及什么；不传则沿用原标签。分类不可改，历史行用它建任务时的值 |

干什么：结案并封卷过程文档、移出自己名下。**封卷后只读**（见生命周期第 8 条）。

举例：用户明确说「把这个任务结束掉」→ `close --id <任务号> --summary "发布流程走通，验证 25 项全过"`。

### list — 查在办

| 参数 | 含义 |
|---|---|
| `--mine` | 只看自己名下的 |
| `--pool` | 只看公共池（没人认领的） |
| `--owner <uuid>` | 看某个人的（**只收 uuid**，精确匹配；传名字直接报错；没有 `me` 缩写；不能与 `--mine` / `--pool` 同给） |
| `--owner-name <片段>` | 按显示名模糊筛（子串、不分大小写）；**只用于筛选**，不参与任何归属判定 |
| `--status open\|doing` | 按状态筛（逗号分隔可多选；合法值只有 `open` / `doing`） |
| `--category` / `--tag` | 按分类（精确）/ 标签（包含）筛 |
| `--since` / `--until` | 按创建时间筛（只给日期含当天） |
| `--stale-days` / `--overdue-days` / `--backlog-days` `<N>` | 覆盖年龄阈值（默认停滞 3 / 逾期 14 / 积压 30 天）；**可选**，不传就用内置默认 |
| `--json` | 输出 JSON（`{任务号: 任务对象}`）；**每行带 `mine`**（是不是自己名下的，只比 uuid）和下面那六个年龄派生字段 |

干什么：合并公共池 + 各人名下的任务，列出在办。**默认就是全量**，没有 `--all` 参数；收窄用 `--mine` / `--pool`。

`--json` 的每行除台账原字段外，多给六个**只读派生值**（按任务算、不落盘，界面别自己再算一遍）：

| 字段 | 含义 |
|---|---|
| `stale` | 停滞：进行中，最后更新至今 ≥ `--stale-days` 天（看 `updated`，缺则回退 `started` → `created`） |
| `overdue` | 逾期：进行中，接任务至今 ≥ `--overdue-days` 天（看 `started`，缺则回退 `created`；中途更新不洗时钟） |
| `backlog` | 积压：待认领，创建至今 ≥ `--backlog-days` 天 |
| `age_days` / `idle_days` / `waiting_days` | 上面三个判据各自的天数（给悬停文案说人话用）；用不上的那个状态是 `null`（进行中没有 `waiting_days`，待认领没有 `age_days` / `idle_days`） |

三个标记**互不覆盖**，一条可以同时中两个（进行中且既逾期又停滞）；老数据里的 `blocked` 一律按进行中判。时间取不到时天数是 `null`、标记是 `false` —— 不编造 0。人话表格里它们显示为行尾后缀（如 `… 发布流程走通 [停滞、逾期]`），不中的行不长这个尾巴。

阈值 `<N>` 给 **0** 等于把这条判据关掉（只要有这个时间戳就算命中），一般不要这么传；给正整数才是「满 N 天」。

举例：「现在该做什么」→ `list --mine`；「有哪些没人认领的」→ `list --pool`。

### stats — 在办计数

| 参数 | 含义 |
|---|---|
| `--mine` / `--pool` / `--owner <uuid>` / `--owner-name <片段>` | 与 `list` 完全同义（范围优先级也是 mine → pool → owner） |
| `--status` / `--category` / `--tag` / `--since` / `--until` | 与 `list` 完全同义 |
| `--stale-days` / `--overdue-days` / `--backlog-days` `<N>` | 同上，覆盖年龄阈值（可选） |
| `--json` | 输出 JSON（各面计数 + 本次生效的阈值） |

干什么：按**名义状态**（待认领 / 进行中）+ **年龄阈值**（停滞 / 逾期 / 积压）数出各面有多少条 —— 只数数、不吐行；要「一行一个任务」用 `list`。筛选与 `list` 同一套口径，不影响历史（范围只作用在办任务）。

`--json` 的形状：`{"total","open","doing","stale","overdue","backlog","mine","my_doing","my_stale","my_overdue","oldest_open_days","thresholds"}`。`thresholds` 回显本次实际生效的三个阈值（`{"stale_days","overdue_days","backlog_days"}`）—— 界面文案照它显示，不要自己硬编码。`oldest_open_days` 是最老一条待认领躺了多少天（没有待认领是 `null`）。`mine` = 归我的在办，`my_doing` = 归我的进行中。

举例：「我这有几条卡住了」→ `stats --mine`；「整体积压多严重」→ `stats --json`。

#### `stats --trend` — 按周期分桶的趋势

| 参数 | 含义 |
|---|---|
| `--trend <粒度>` | `day` / `week` / `month` / `quarter` / `year`（桶边界：日 00:00、**周一**、自然月、自然季、自然年，全按本机时区） |
| `--last <N><d\|w\|m\|y>` | 最近 N 个日 / 周 / 月 / 年（与 `--since` / `--until` **二选一**；默认 `8w`） |
| `--since` / `--until <日期>` | 显式区间（与 `list` 同样的本地时区口径）；首尾桶**按区间裁剪** —— 从周三起算，第一桶就只有周三起的数据 |
| `--mine` / `--owner <uuid>[,<uuid>]` | 只看自己 / 某几个人（`--owner` 可给多个 uuid，与 `--mine` 互斥） |
| `--by-owner` | 每个桶额外带按人明细（默认不返回，只给总数） |

干什么：一次遍历返回**整段桶序列**（不按桶多次调用），每桶三个数 —— `added`（该桶内新建）、`done`（该桶内结案）、`open`（该桶**结束时**仍未结案）。

口径：`added` 按 `created`、`done` 按 `finished`；`open` 由「当前在办 + 今天往前倒推」得出，天然含窗口之前遗留的基线。按人明细里 `added` 按 `creator`、`done` / `open` 按 `owner`（待认领不算任何人）。

按人的 `open` 只算**你名下**的任务，倒推时同时减去「你在那天之后新建的」（按 owner 计，与展示用的 creator 无关）—— 否则窗口之后才建、早已结案的任务会被当成那天就在办，越靠前的桶虚高得越离谱。负责人转交过的任务按**今天**的负责人归账。

**只出 JSON**（表格由界面渲染；给 `--json` 是用法错）：

```json
{
  "granularity": "week",
  "coverage": { "from": "2026-09-01", "to": "2026-10-29" },
  "buckets": [
    { "from": "2026-09-01", "to": "2026-09-06", "added": 3, "done": 5, "open": 12,
      "owners": { "<uuid>": { "name": "某人", "added": 1, "done": 2, "open": 4 } } }
  ],
  "warnings": []
}
```

- `from` / `to` 是**本地日期**（含边界）；展示标签（`第 40 周` / `2026-10` …）由前端按粒度自己生成，脚本不回任何标签。
- `coverage.from` 是实际有数据的第一天；窗口里早于它的部分没有数据（前端显示「数据不足」，不画 0）。
- `owners` 只有加 `--by-owner` 才出现；人名实时取自名册，不进缓存。
- 上限按**时间跨度**定，不按读几个文件定：一次最多 10 年（3660 天）；`day` 粒度另有 365 天上限（一天一桶没人看十年）。超了直接报错，不返回半截数据。缓存文件不计入任何上限（命中的月份根本不读源文件）。
- 已过完的本地月会落一份本机缓存（`~/.taskledger/cache/trend/`，不进 git、随时可删）；当月永远实时算。缓存不改变**能查多久**（历史文件从不清理，10 年就是 120 个文件在盘上），只决定**查得多快**。
- 缓存分两层：**整月缓存**只写你查的那几个月；另有**月度锚**（`anchors.json`，只记每个月末的未结，全局 + 按人，几十字节/月）。
  - 有左锚（上个月末的未结）⇒ 从锚往右累计，**只读那一段的月份**，查再久以前也不碰中间的月份；
  - 没有左锚（第一次查某段历史）⇒ 从今天的在办快照往回推一次，沿途把每个月的锚补上，并在 `warnings` 里告诉你读了几个月。

举例：「最近 8 周每周完成多少」→ `stats --trend week`；「今年每月按人看」→ `stats --trend month --last 12m --by-owner`。

### owners — 花名册

| 参数 | 含义 |
|---|---|
| `--json` | `{"count","owners"}`：`owners` 是 `{uuid: {file, name, joined, mine}}` |

干什么：把这个工作区里登记过的**所有人**都给出来（含当前没有任务的人），每条额外带 `mine`（是不是本机身份）。人选列表要列全时用它 —— 从 `list` 的在办任务里只能派生出「当前有任务的人」。

举例：「筛人的下拉要列全」→ `owners --json`。

### show — 看一条任务

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 看哪条（必填；谁名下的、在办还是已结案都能看） |
| `--json` | 任务字段 + 过程文档全文一起给（人话模式只给路径） |

干什么：**看一条 = 任务字段 + 过程文档全文**，一次拿全；已结案的任务同样能看，不必先查 `history`。`--json` 里 `legacy: true` 表示这些字段是回退查在办得到的（老文档没有状态行）。

举例：「这个任务到哪一步了」→ `show --id <任务号> --json`。

### history — 查已结案

| 参数 | 含义 |
|---|---|
| `--owner <uuid>` / `--mine` | 按 owner 筛（**只收 uuid**，传名字直接报错）；两者**不能同给** |
| `--owner-name <片段>` | 按显示名模糊筛（子串、不分大小写）；只用于筛选 |
| `--category` / `--tag` | 按分类 / 标签筛 |
| `--since` / `--until` | 按**结案时间**筛（只给日期含当天） |
| `--months N` | 最近 N 个自然月（与 `--since` / `--until` **互斥**，同传直接报错） |
| `--limit N` | 最近 N 条 |
| `--count-only` | 只输出 `{"count","capped"}`（与 `--json`、`--limit` 都互斥） |
| `--json` | JSON 输出；**每条记录带 `mine`**（是不是自己结的，只比 uuid） |

干什么：按结案时间倒序排列，每条一行，只列结案时间、负责人、标题，其他都不在表格里；要摘要 / 分类 / 标签 / 完整时间加 `--json`。不给时间参数 = 最近 3 个自然月；最多 13 个月，超了直接报错。

举例：「上周做过什么」→ `history --since <上周一日期>`；「今年都结掉哪些」→ `history --months 12`（超过 13 个月要分段查）。

### root — 台账根检测

| 参数 | 含义 |
|---|---|
| `--dir <目录>` | 检测哪个目录（不给 = 当前目录） |
| `--json` | `{"dir","root","repo","ledger","reason"}` |

干什么：回答「这个目录是不是已初始化的台账根」，**不读里面的台账文件** —— 判据只看结构：**直接含有 `ledger/` 就是根**（`ledger/` 本身与它下面的目录都不是），与脚本定位工作区根完全同一个口径，有没有 `pool.json` / `owners.json` 都不影响。

- `root`（布尔）：这个是最终答案；
- `repo`：顺带给出往上找到的工作区根（自己就是根时等于 `dir`，一个都没有时是 `null`）—— 拿到它就可以直接喂给其它命令的 `--repo`；
- `reason`：一句人话说明（界面直接显示它）。

它与 `whoami` 同类：**在定位仓库之前跑**，不认 `--repo`、不依赖身份、不报错退出（目录不存在也只是「不是根」，退 0）。

举例：「这个目录有台账吗」→ `root --dir <候选目录> --json`。

### whoami — 我是谁

| 参数 | 含义 |
|---|---|
| （无） | 打印本机身份：`@名字　uuid` |
| `--json` | `{"uuid","name"}`；**未初始化给双 null**（照常退 0，不是错误） |

干什么：本机身份的只读查询，**不依赖 `--repo`、不写任何文件**，回答「这台机器上我是谁」。需要自己的 uuid 时用它（转述给别人、核对 `list --owner` 的查询结果），别去解析 `~/.taskledger/identity.json`。

**它不是执行前的检查项**：跑命令前不用先跑它探一次 —— 未初始化会在你真正要跑的那条命令上当场报「这台机器还没有初始化身份。」，那时再按「身份闸门」那条分支走。

举例：「我的 uuid 是多少」→ `whoami --json`。

### validate — 台账体检

| 参数 | 含义 |
|---|---|
| `--deep` | 历史读全部月份（默认只读当月那个月文件） |
| `--json` | `{"problems","notices","checked_files","total_tasks","deep"}` |

干什么：只读体检，查公共池 + 各分片的字段格式、索引与文件对不对得上、历史格式。**不读过程文档正文**（浅度 / 深度都不读）。查出问题时退 1 —— 把清单原样交给用户，agent 不自行修。

## 怎么调用

```bash
<本 SKILL.md 所在目录>/scripts/progress <子命令> --repo <工作区根>
```

`scripts/progress` 是个薄 shell 包装，按平台 exec `scripts/bin/ledger-<os>-<arch>`（自带运行时的静态二进制；已提供 linux/amd64、darwin/arm64 与 windows/amd64）。平台或架构没有对应产物时，它会明确报错，不会静默失败。

- **不需要安装任何东西**（不装解释器、不装运行时、不往 PATH 里加命令）：直接执行上面那条绝对路径即可。
- 若报 `Permission denied`（某些安装环节会丢可执行位），前面加 `sh `：`sh <本 SKILL.md 所在目录>/scripts/progress <子命令> …`。
- **交给用户的命令必须是这个绝对路径**，不许简写成 `progress` —— 用户机器的 PATH 里没有这个命令，简写后用户一跑就是 `command not found`。

- 定位项目：`--repo <工作区根>`（**直接含有 `ledger/` 的那个目录**）给了就校验后用；不给就从当前目录逐级向上找。`ledger/` 本身、以及它下面的任何子目录都不是根，指过去会被直接拒绝（判据只看位置，不看目录里有哪些文件 —— 项目根自带 `pool.json`、`history/`、`worklog/` 都不影响）。
- `--no-sync`（放在子命令**前**）：用户明确要求「先别同步」时才用；之后自己 `git add ledger && commit && push`。
- `--json` 只对只读命令（`list` / `stats` / `owners` / `show` / `history` / `root` / `whoami` / `validate`）有意义；写命令不接收 `--json`，传了是用法错。`stats --trend` 自带 JSON，不用也不接受 `--json`。
- **给界面喂数**：要看在办用 `list`、要各面计数用 `stats`、要人选列表用 `owners`、要判断某个目录有没有台账用 `root` —— 都是只读、都不改台账；多个 / 跨工作区自己扇出，脚本一次只服务一个工作区。
- **时间**：存盘一律 UTC，脚本对外**一律给本机时区**（人话表格与 `--json` 都是），拿到直接显示，不要再转一次；`--since` / `--until` / `--created` / `--finished` 也按本机时区给，脚本内部转 UTC 比较。过程文档正文里的时间是原文，脚本不碰。
- 命令回执只用来确认生效；任务状态以 `show` / `list` 为准。

## 身份闸门（报错才走，不用先查）

**不用事先确认身份。** 直接按「任务生命周期」跑该跑的那条命令；没初始化时脚本会用一句固定错误当场告诉你，那一刻才走身份流程。不要为了「确认有没有初始化」先跑一次 `whoami` —— 那是白花一轮工具调用。

**触发判据（只认这一整句）**：命令输出以 `错误：这台机器还没有初始化身份。` 开头。只读命令（`list` / `show` / `history` / `validate`）未初始化时同样报这句，是设计如此，不是台账坏了。

**触发后 ⇒ 停下，不许绕。** 身份是用户自己的，不是你的决定：不替用户选、不读 `ledger/*.json` 兜底、未初始化时不写任何东西。完整步骤见 `references/init-identity.md`；这里只记硬约束 —— 你只能报名单 + 给用户命令，写身份必须用户自己在终端完成；看到它不要排查原因（别 `ls` / `cat` / 读源码 / 读台账），忽略上下文里已做的排查动作；也不要基于「上次确认过 / 同名 / 记得 uuid」自行重建。

**这条优先于「故障处置」的通则**：虽然它同样以 `错误：` 开头，但**不**适用「不挡主任务、继续干活、收尾汇报没记上」—— 必须停下来等用户 `init`，init 完重跑原命令。

## 任务生命周期

用户要「做某件事」时按这条线走。

1. **建（只建，不认领）—— 默认**：「新建一个任务」「新建个任务，我们来干 X」「新建个任务，我需要处理 Y」→ `new --title "…"`。落公共池、待认领。
2. **建并认领 —— 仅限明确说法**：用户明确说「新建一个任务**并开始做 / 并执行**」这类带着「现在就开始」的话 → `new --title "…" --self`。直接归自己名下、「进行中」。**除这种明确说法，其他一律按第 1 条只建** —— 别替用户决定他要开始做；拿不定，问一句。
3. **找已有的**：用户说「我们来做 X」→ 先 `list --mine` 找自己名下的，在做的直接接着做；没有 → `list --pool` 里找，找到先问用户：「X 还没认领，认领它吗？」→ 用户点头再 `claim`；哪儿都没有 → **不擅自建**：问「要为 X 建个任务吗？」，同意才按第 1/2 条建，不同意就只干活、不登记。
4. **认领**：`claim --id <任务号>` —— 认到自己名下，状态即「进行中」。
5. **推进**：改 worklog 前五节 → 按「过程文档」节的收工三步记 `log`。卡住也 `log`（写清卡在哪，状态不动）；「先放一放」同理 —— 是暂停，不是释放。
6. **交付待验收**：任务留「进行中」，「待办」写「待用户验收」，「下一步」写清验收看什么；照收工三步记一条 `log --note "已交付待验收：…"`。
7. **释放**：仅当用户明确说「退回去 / 释放掉」→ `set --id <任务号> --release`。任务回公共池，别人可认领。
8. **结案**：仅当用户明确说「把这个任务结束掉 / close 掉」→ `close --id <任务号> --summary "…"`；说得含糊（「做完了」「验收通过」）先反问「是要结束这个任务吗？」。收尾顺序：**先补完正文 + 记 log，最后才 close** —— 关了就不能再写。
9. **查询**：在办 `list` / 单条 `show` / 已结案 `history`（默认只近 3 个自然月，更早的要 `--months` / `--since`）。

## 过程文档

`new` 按模板建好六节骨架，路径由 `show` 给出；前五节是本 skill 唯一允许手写的内容。

| 节 | 写什么 |
|---|---|
| 背景 | 为什么做：触发它的原话 / 现象 / 链接 |
| 待办 | 还没做的、没验证的、等别人给东西的 |
| 下一步 | 下一个**具体动作**（文件:行号 级别），不写「继续推进」 |
| 过程 | 踩坑与证据：带 revision + `文件:行号` 或符号名 |
| 结论 | 做成了什么、留了什么坑；只写可验证事实，评价等用户验收 |
| 执行记录 | 脚本维护，**禁止手写**（见「手写边界」） |

规则：

- 「执行记录」节名一个字都别动；老文档缺这一节也不用补。
- 过程文档找不到时 `log` 只提示不失败；用 `show` 查路径，不要手写。
- 头部是四行，由脚本维护、**都不要手改**，顺序固定 `标签 → 状态 → 创建 → 封卷`，值一律 `· ` 分隔：

  ```markdown
  - **标签**：建设、DSH、台账
  - **状态**：doing · 2026-10-27 09:12:33 · @某人 · 8d557c6d-…
  - **创建**：2026-10-26 23:38:02 · @某人 · 8d557c6d-…
  - **封卷**：2026-10-27 09:20:10 · @某人 · 8d557c6d-…
  ```

  标签行与封卷行不一定有（没给标签、没结案就没有）。老文档头部可能还带着「**分类**」段，那是旧格式，不用补也不用改（脚本下次改写标签行时会一并清掉）。老文档没有状态行是合法的（`show` 回退查在办，`--json` 标 `legacy: true`），不用补。
- 执行记录行格式 `- 时间（UTC） · 类型 · @谁 · 说明`，`@谁` 是这次动手的人、不是任务现归属；只追加、不改旧行。行首「类型」是脚本内部动作名（会见到 `release`，它就是 `set --release`）；认不出就别当成新命令，按 `--help` 查。
- 只改某条任务的正文：`show --id <任务号>` 拿路径直接改，不另建 md；已结案的用 `history --months 12 --json` 找回链接（**人话输出里没有链接，必须加 `--json`**）——默认只查近 3 个月，结案久了的要显式放大窗口；只读不改。

### 收工三步（「收工」= 这一轮对用户有可见产出）

1. 改正文：这轮变化的事实都落笔，「下一步」写具体动作。
2. 跑 `log`：这一轮只要改过正文就必须记（一轮至少一条；纪律见下文）。正文没变也能记一条推进，但要同时重写「下一步」。
3. 回读末行（`tail -n 3 <路径>`）：说明 = 这轮的事。执行记录行的时间是 **UTC**（比本机本地时间早若干小时，看时差别以为没记上）。

**什么算一个节点**：明天自己想不起来、或换个人接手会看不出的事，就记一条；一次状态 / 结论变化对应一条，不对应一次工具调用。拿不准够不够格、`--note` 不会写 → 见 `references/log-note.md`。

## 纪律

### 数据完整性（脚本管不了的，违反了数据就脏）

- **执行记录禁手改**：只由脚本按 `new / claim / set / release / log / close` 追加，只增不改（**交接记的是 `set`**，看不到 `handoff` 是正常的）。
- **改正文必配一条日志**：动了 worklog 的正文（改一句、补一节、改标题、修错字都算）就必须立刻跑一次 `log`。
- **换人只能「释放 → 认领」**：`set --release` 放回公共池，对方自己 `claim`；不许替别人挂名字。`set --owner <别人>`（预留转接通道，agent 一律不用）。
- **身份由脚本从本机 identity 文件自取，agent 全程不传身份**：跑命令前不用查身份；只有当命令报出「这台机器还没有初始化身份。」时，才按 `references/init-identity.md` 引导用户跑 `init`（一台机器一次）。查自己用 `--mine`，查别人才传**对方 uuid**（`list --owner <uuid>`）；释放用 `--release`，不传身份。
- **身份只用 uuid，名字只用于显示与筛选**：认领 / 释放 / 交接 / 查「我的」一律只比 uuid；`--owner` 传名字会当场报错，要按人模糊找就用 `--owner-name <片段>`（子串、不分大小写）。名字是冗余字段（改名不影响归属），别拿它当身份用。

### 人类授权（跑之前问不问）

项目没有 `ledger/` ⇒ 先问「要不要建个台账记这活？」，不许自建。用户同意 ⇒ 直接跑第一条写命令，且**必须带 `--repo <工作区根>`**（根是直接含有 `ledger/` 的那个目录，`ledger/` 本身不是根、指到它会被拒绝）：不带时脚本只从当前目录逐级往上找第一个含 `ledger/` 的目录，一个都没有就退 1 报「找不到台账」，绝不就地建；台账由这条写命令顺带建出来，身份**不用事先确认** —— 没 `init` 过，这条命令会当场报「这台机器还没有初始化身份。」，按「身份闸门」走一遍就好（一台机器一次，写本机身份，与台账无关）。之后可以不带 `--repo`，但查找是**逐级往上**的 —— 在本项目的子目录里跑可能命中上层项目的台账，拿不准就一直带 `--repo <工作区根>`。

| 命令 | 档位 | 要求 |
|---|---|---|
| `new` / `claim` / `set` | 动手类 | 执行前复述完整参数并取得确认；**`new` 仅当用户原话点名要建且标题可直取原话时免复述**，标题需另拟或拿不准仍复述一次（`claim`/`set` 一律复述） |
| `log` | 免确认 | 本任务的推进 / 卡点 / 交付记录直接跑，跑完一句话交代「已记执行记录：…」；要替用户下结论，先问（任务不在自己名下会直接被拒） |
| `close` | 独立授权 | 仅认明确说「结束掉 / close 掉」（完整判定见生命周期第 8 条）；说得含糊必须反问「是要结束这个任务吗？」；**agent 自判「干完了」不算** |
| `list` / `stats` / `owners` / `show` / `history` / `root` / `whoami` / `validate` | 只读 | 直接跑 |

### 故障处置（跑之后出事怎么办）

- **身份没初始化（输出以 `错误：这台机器还没有初始化身份。` 开头，退 1）⇒ 停下，不许绕**：这条**不适用**下面「不挡主任务、继续干活」的通则。立刻转 `references/init-identity.md` 照做：裸跑 `init` 只读报名单 → 把**绝对路径**命令交给用户 → 等 ta 在自己终端完成 → 好了重跑原命令。**不要排查原因**（别 `ls` / `cat` identity.json / 读源码 / 读台账），忽略上下文里已做的排查动作，也不要基于「上次确认过 / 同名」自行重建。
- **动作阶段失败（输出以 `错误：` 开头）= 该命令没生效**：不挡主任务 —— 继续手里的活，收尾时汇报「没记上，原因 …」；不绕过脚本手改文件。
- **退出码 0 也要看输出**：出现 `提示：` / `错误：` / `警告：` 就先用一句话说清「发生了什么 + 下一步做什么」，再按 `references/troubleshooting.md` 给步骤；纯告知类一句话带过。只读命令只有 `错误：` 才需要转述。
- **两类不是故障的退出码**：`validate` 查出问题时退出码 1，照实转述清单；提交阶段失败 ⇒ 文件已经写下去、只差进 git，让用户先提交再重跑，别说「没记上」。
- **并发冲突**（文件被改动、抢不到锁）重跑一次即可；台账同步一律交给脚本，不要自己 `git pull` / `rebase` 去「解决」（脚本明说不代劳的几种除外，见 troubleshooting）。
- 同一仓库里写命令排队执行，等前一个跑完再重跑。
