# 分类与标签

> TL;DR：`category` 答「是什么类型」（单值，≤4 字，吃不准写「其他」）；`tags` 答「涉及什么」（0~5 个，写不出就留空）。两者口径错开；统计只认 category，查询用 tags。

为什么不设枚举：本 skill 跨所有工作区（开发 / 运维 / 个人事务 / 调研备忘），固定分类覆盖不全。分类与标签由 agent 在 `new` 时按本节口径自行总结；脚本只校验形态（≤4 字 / 纯英文 ≤3 词 / ≤5 个），不校验语义。

## 两条边界

1. **口径错开**：tags 不许写 category 的同义词 —— `category=缺陷修复` 时，tags 别再写「bug修复」。
2. **统计与查询分工**：统计只认 category（精确匹配，同值才能比较）；tags 只做查询（包含匹配，「bug」命中「bug修复」正是要的效果）。
3. **数量不设下限**：3~5 个是目标不是硬指标；设下限会逼出凑数标签。

## 写法口径

- 名词性短语，不带时态、不用动词收尾：写「缺陷修复」，不写「修复了」「修 bug」。
- 中文优先，不中英混排；纯英文 ≤3 个单词（`fix a bug` 可以，`fix a login bug` 超了）。
- 标签之间用**逗号**分隔；空格属于英文多词标签自身（`--tags "fix a bug,docker"`）。

正例：`--category 缺陷修复 --tags "镜像拉取,超时重试"`
反例：`--category 已完成登录修复`、`--tags 修 bug`

## 时机与修正

- `new` 建档时一并总结（标题 + 背景语义最全）。
- `close` 可用 `--category` / `--tags` 覆盖修正一次；终值写进 history 行的「分类 / 标签」列。
- 日常漂移：先 `tags --all` 看全量频次与低频变体，再 `tags --rename 旧 新` 归并（只改在办任务，已封卷文档不动；批量写，见写操作红线）。
