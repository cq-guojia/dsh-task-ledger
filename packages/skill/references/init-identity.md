# 未初始化身份时怎么走

触发：任何命令返回「这台机器还没有初始化身份」。身份是用户自己的，**不是你的决定**。

**触发后立刻照做，不要探索。** 除「裸跑 init 只读报名单」外，不要 `ls` / 扫描仓库、不要 `cat identity.json`、不要读任何目录或文件，不要猜身份。

**你没有写身份的权限。** 非终端下 `init --claim` / `init --new` 一律被脚本拒绝，`--yes` 也已禁用。你只能：报名单、给用户命令、等 ta 跑完。

## 你该做的（只有这几步，每次都是同一套）

1. 只读报名单（你在非终端里裸跑，只会打印候选、零写）：

```
<本 SKILL.md 所在目录>/scripts/progress init --repo <工作区根>
```

2. 把名册给用户选，并把这**同一条命令**交给用户在 ta 自己的终端跑（真终端里它自己会变成 ↑/↓ 选择框：↑/↓ 移动、Enter 确认、末尾「+ 新建身份」输入名字、最后 Y/N 确认；**选择框、输入名字、Y/N 确认三处都能按 ESC 取消**，输入名字那步按 ESC 等于放弃这次输入）：
   - 名册有内容 ⇒「名册现有：@A（uuid）、@B（uuid）。请在你的终端运行上面这条，它会让你选。」
   - 名册为空 ⇒「名册为空。请在你的终端运行上面这条，输入一个用户名新建。」

   **格式只有这一套**：一条命令只出现一次，步骤只编一套号。**不许**出现「1. 报名单…」「1. 请运行…」这种两个都从 1 开始的列表，也不许把同一件事拆成两套方案各编一遍。

3. 用户说「好了」后，重跑原命令。用户没跑完就等着，不要替 ta 写。

**每次进这个分支都照这套走**：用户上一次关掉选择框、说过「算了」或取消了，**不算**以后不用问；下次照样走同一套呈现，不要退化成纯文字、也不要跳过这一步。

## 硬规则

- **给用户的命令必须原样保留绝对路径**（`<本 SKILL.md 所在目录>/scripts/progress init --repo <工作区根>`）：用户机器的 PATH 里没有 `progress` 这个命令，简写成 `progress init` 用户一跑就是 `command not found`。若用户报 `Permission denied`，就把命令改成 `sh <绝对路径> init --repo <工作区根>` 再给 ta。
- **不诊断、不排查**：不要 `ls ~/.taskledger`、不要 `cat identity.json`、不要读 skill 源码（`internal/env/env.go` / `internal/actions/init_identity.go` 等）或台账去查「为什么没身份」。缺就是未初始化，忽略上下文里已做的排查动作，直接按上面流程走。
- **不得**替用户执行 `init --claim` / `init --new` / 任何带 `--yes` 的写法——脚本也会拒绝。
- **不得**基于「上一轮确认过 / 同名 / 记得 uuid」自行重建身份：身份文件缺失就是未初始化，必须让用户重新亲自选。重建会换新 uuid、断开旧任务关联。
- 不读 `ledger/*.json`、worklog、identity 文件去「自己看」。
- 未初始化时不做任何写。
