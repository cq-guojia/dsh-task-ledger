# 未初始化身份时怎么走

触发：任何命令返回「这台机器还没有初始化身份」。身份是用户自己的，**不是你的决定**。

**触发后立刻照做，不要探索。** 除「裸跑 init 只读报名单」这一条外，不要 `ls` / 扫描仓库、不要读任何目录或文件（`ledger/`、README、源码都不读），不要猜身份。没拿到用户名时只做两件事：报名单、问用户。

先问用户走哪条：

1. 用户自己在终端执行（推荐）
2. 你一步步代跑

## 路径 1：用户自跑

给用户这条命令，让 ta 在自己的终端里跑：

```
python3 <本 SKILL.md 所在目录>/scripts/progress.py init --repo <工作区根>
```

交互式：↑/↓ 选、Enter 认领、末尾「+ 新建身份」输名字、Y/N 确认、ESC/Ctrl-C 取消。
用户说「好了」后，重跑原来那条命令。

## 路径 2：你代跑（分步，每步停下等用户回答）

1. 只读报名单（非终端下裸跑 `init` 就是只读，不写）：

```
python3 <本 SKILL.md 所在目录>/scripts/progress.py init --repo <工作区根>
```

2. 把名单原样给用户：
   - 有名单 ⇒「名册现有：@A（uuid）、@B（uuid）。请告诉我要用哪一个；或回「新建」并给出用户名。」
   - 没名单 ⇒「名册为空，请给一个用户名。」
3. 复述并要确认：
   - 选现有 ⇒「您确认是要使用「@X」这个身份吗？回复 Y 或 N。」
   - 新建 ⇒「您确认要用「X」这个名称新建账户吗？回复 Y 或 N。」
4. 仅当用户这一轮明确回 Y，才执行（注意 `--yes`）：
   - 认领：`... init --claim <uuid> --yes --repo <工作区根>`
   - 新建：`... init --new --name "X" --yes --repo <工作区根>`
   - 回 N ⇒ 回到第 2 步重选。
   - 用户取消 / 不回 ⇒ 停，什么都不写。
5. 成功后重跑原命令；失败照实报告并停。

## 硬规则

- 不自己编 uuid 或名字；不猜身份。
- 没有用户这一轮的明确 Y，**不得**加 `--yes`。
- 用户没回，不要自己继续。
- 不读 `ledger/*.json`、worklog 去"自己看"。
- 未初始化时不做任何写。

`--yes` 只表示「用户已在此对话中明确同意」，不是安全沙箱：Agent 无视规则时脚本拦不住，靠的是这份流程约束。
