# 排错

> TL;DR：非 0 退出就停手、原样报告；**退出码 0 但输出里有 `提示：` / `错误：` 同样要读并转述**（同步失败仍返回 0）。别绕过脚本改 JSON。并发冲突重跑一次；台账同步交给脚本，只有提示说脚本已回滚、或说它拒绝 rebase 时，才让用户手动 `git pull --rebase` / `git merge`。

## 退出码

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功（**同步可能失败**：输出里有 `提示：` 就按上面那条读） | — |
| 1 | 业务错误（参数值 / 状态 / 权限不对） | 按提示纠正后重试；改不了的报告用户 |
| 2 | 命令行参数错误 | 看 `<子命令> --help` 重新拼参数 |
| 3 | 未预期的内部失败 | 上报，不要重试 |
| 130 | 被中断 | 重跑一次 |

## 常见错误

- **「读不到 git 邮箱，无法确定身份」**：`git config user.email` 没配（或 `git var GIT_COMMITTER_IDENT` 失败）。让用户配好，不要自拟身份。
- **「任务还没人认领（在 pool.json 里）」/「不在你的分片里」**：任务在公共池或别人分片。要接手先 `claim`；别人交接只能走「对方释放 → 你 `claim`」，不要绕过脚本改 JSON。
- **「池里的任务状态不一致（owner=…，status=…）」**：池里混进了已认领的任务。跑 `validate` 看全部问题，再按提示处理（多半是搬移崩了一半）。
- **「没有 N 的分片（owners.json 里也没登记）」**：查 `list --owner` 时身份写错了。身份是 git 邮箱，键在 `ledger/owners.json` 的 `workers` 里。
- **`log` 报「没写进过程文档」**：worklog 路径丢失 / 不可读。用 `show --id` 查路径；分片里的 `updated` 已刷新，不要手写「执行记录」。
- **「文件在操作期间被改动」**（并发指纹冲突）：重新执行一次即可。
- **「本地台账有未提交改动，写前取最新会覆盖它」**：写前只取本次要写的台账文件最新版（索引 / 自己分片 / 认领释放涉及的 `pool.json` / `close` 当月的 `history/`），本地这些文件脏就先停下。先提交（`git add ledger/ && git commit -m "chore(ledger): ..."`）再重跑；暂时离线可加 `--no-sync`（写在子命令前后都行）继续本地写。
- **「另一个会话正在同步同一份台账（已等 60 秒）」**：同一仓库里另一个 agent 正在写并推送，锁没抢到。等它跑完再重跑即可，不要并行重试（会把排队队列越堆越长）。
- **「本地有 N 个台账提交还没推到 …」**：写前本来会自动补推，看到这句说明**补推失败**了（多半是远端也动了、脚本不替你 rebase）。先 `git push`（非快进就 `git pull --rebase` / `git merge` 后再推），推完重跑；离线场景用 `--no-sync`（写在子命令前后都行），联网后统一提交推送。
- **「本地有 N 个你自己的提交还没推送 … 脚本不替你 rebase」**：推送被拒，且本地有非台账路径的提交。脚本故意不动它们（rebase 会改写提交号），**不要重跑台账命令**（会二次写入）。让用户自己 `git pull --rebase` / `git merge` 后 `git push`；台账改动已安全留在本地，推完重跑即可。
- **「没能确认本地有没有你自己的提交（git 数不出来）」**：旧版 git / 浅克隆下 `rev-list` 失败，脚本按「可能有」保守处理，不推也不 rebase。让用户 `git status` / `git log @{u}..HEAD` 自己看，处理完再重跑。
- **「写前把本地 N 个未推送的提交推上去了」/「本次推送会把本地 N 个你自己的提交一并推上去」**：纯告知（脚本已推或即将推），一句话带过「这次顺带把你本地 N 个提交推上去了」，不要回滚、不要重推。
- **「本地已提交，但推送被拒」**：改动已安全落盘，只是远端没收，**不要重跑台账命令**（会二次写入）。看提示里 `git：` 那行的原文：`! [rejected] ... (fetch first)` = 他人先推，脚本已自动合并过一次仍失败就手动合并台账文件；`Permission denied (publickey)` / `could not read Username` = 凭据问题，找用户修，不要反复重试。
- **「自动 rebase 未成功（已回滚到 rebase 前）」**：同一条任务被两边同时改了。脚本已 abort，仓库是干净的；按提示里的冲突原文手动合并后 `git push`。
- **「自动 rebase 冲突后回滚也失败了」**：仓库停在 rebase 中间态，**先别跑任何台账命令**。在仓库根 `git rebase --abort`；仍失败就 `git status` 看残留，必要时删 `.git/rebase-merge` / `.git/rebase-apply` 再重试。
- **「暂存了你的未提交改动」+ autostash 冲突**：你的未提交改动在 stash 里，没有丢；提示里点名的那几个文件此刻**带着 `<<<<<<<` 冲突标记**，git 不会拦你提交，别把它们当成品。解冲突后确认内容，再 `git stash drop`；只想要内容可 `git stash show -p stash@{0}` 取出。
- **「git add 失败」/「自动提交失败」**：台账已写进本地文件，只是没进 git。按错误原话处理后手动 `git add <文件> && git commit -m "chore(ledger): ..."`。
- **「没有上游跟踪分支」/「当前是 detached HEAD」**：台账照写、照提交到本地，但**不会推送**。让用户建上游（`git push -u origin <分支>`）或切回分支；离线时这样用，联网后统一推一次。
- **「写前快进 … 没成功」**：通常是工作区里有未提交改动（git 按文件拦，不看行），脚本改走「只刷新本次要写的台账文件」。想快进就先提交或 stash 那些文件。
- **「worklog 正文疑似被覆盖成模板骨架」**：`validate` 会对仍只有注释占位的在办任务打提示。从 git 恢复该文件（`git checkout HEAD -- <路径>`）后重写正文，再跑 `log`。
- **`validate` 报问题**：先按它给的文件定位读原文（结构类问题不带行号）。它查五类结构问题：① 索引登记了分片但文件不在；② 目录里有分片但索引没登记；③ 同一任务号出现在两个文件；④ 池里出现已认领的任务（`owner` 非空或 `status != open`）；⑤ 分片里的 `identity.email` 与索引登记的键不一致。另报 `pool.json` 缺失、worklog 缺失或只剩骨架、历史行是旧列数。①②③④⑤ 都属「人工裁决」：读原文确认哪份是真的，删掉多余那份或把索引改对，**不要用脚本猜**。
- **同一任务号出现在两个文件**：认领 / 释放是「先写后删」，崩在中间就会两边都有。确认哪份是最新后删掉另一份，或重跑一次对应命令（幂等）。
- **「owners/<hash>.json 没在 owners.json 里登记」**：里面所有任务对其他人都等于不存在。要么把条目补进索引，要么确认这份是废弃文件后删掉。

## 硬约束

不要直接编辑 `ledger/pool.json`、`ledger/owners.json`、`ledger/owners/*.json`、`ledger/history/*.md`；不要另建 worklog；不要手写「执行记录」节。

## 环境要求

- **git ≥ 2.27**：写前/写后的自动合并依赖 `rebase --autostash`，低于这个版本 autostash 冲突回滚不可靠。
- **没有 git 的目录自动跳过**：台账照常写入，不提交、不推送、不报错。
