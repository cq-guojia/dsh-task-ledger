# 排错

> TL;DR：非 0 退出就停手、原样报告，不要绕过脚本改台账 JSON 或历史层。**退出码 0 也要看输出**：提交失败会退 1，推送失败仍退 0、原因只写在输出里。并发冲突重跑一次；同步交给脚本，只有提示说脚本已回滚、或说它不替你 rebase 时，才让用户手动合并。

## 退出码

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功（同步可能失败：输出里有 `提示：` 就要读） | — |
| 1 | 业务错误（参数值 / 状态 / 权限不对；**提交失败也是 1**） | 按提示纠正后重试；改不了的报告用户 |
| 2 | 命令行参数错误（argparse 自退） | 看 `<子命令> --help` 重新拼参数 |
| 3 | 未预期的内部失败（如台账 JSON 语法损坏、读命令撞上冲突标记） | 上报，不要重试；冲突标记先解冲突 |
| 130 | 被中断 | 重跑一次 |

> 两类退出码 1 不是故障：`validate` 查出问题（照实转述清单）；提交阶段失败（文件已写下去，只差进 git，让用户先提交再重跑）。

## 常见错误 → 处置

引号内是提示原文的稳定片段（省略号处是变量）。按片段在输出里定位。

### 用法 / 参数类（退 1，改参数即可）

- **「set 必须二选一：--release（释放回公共池）或 --owner <对方 uuid>（交接）」**：`set` 只认这两个，没有别的用法。
- **「--release 与 --owner 不能同时给」**：释放不带人、交接不带释放，分开跑两次。
- **「--owner 只收身份 uuid（形如 …），不接受名字 / 邮箱：X」**：身份参数传了名字。改传 uuid；要按显示名找人就加到查询里：`list --owner-name <片段>` / `history --owner-name <片段>`。
- **「--owner 不能和 --mine / --pool 一起用」**：范围只能选一种。要按某个人筛就 `--owner <uuid>`，要看自己的就 `--mine`。
- **「--limit 必须 ≥ 1」**：`--limit 0` 没有意义。
- **「时间区间反了：--since（…）晚于 --until（…）」**：两端换过来。
- **「认领目标不是 uuid：X」**：`init --claim` 抄了老台账的邮箱 / 名字键。老台账先迁到 uuid 身份；这台机器先 `init --new --name=<名字>`。
- **「名册里没有 uuid=X」**：`init --claim` 抄了一个不在 `owners.json` 里的 uuid。不带参数跑一次 `init` 看可选用户再选。
- **「任务 X 的负责人是 Y，不是你（Z）」/「身上还挂着 owner / 不是 open —— 台账脏了」**：分片键与行内 `owner` 打架（`validate` 的 problem ⑤）。跑 `validate` 看清单、按人工裁决修，别用命令硬覆盖。
- **「任务号 X 不合法：只能用小写字母、数字、汉字和连字符」**：`--id` 传了大写 / 空格 / 符号。
- **「任务号 X 已经存在了（这不是重跑，是重号）」**：换个 `--id`，或不传让脚本自动生成。
- **「标题不能为空」/「--note 不能为空」/「结案要写一句「完成了什么」（--summary 不能为空）」**：必填项漏了。
- **「标题里没有可用字符（字母、数字或汉字），无法自动生成任务号。用 --id 指定一个」**：标题全是符号。
- **「标签最多 N 个，收到 M 个」/「太长：含中文时最多 N 个字」**：分类 / 标签超了上限（口径见 SKILL.md 的 new 参数节）。
- **「时间格式不对：（可用 YYYY-MM-DD、YYYY-MM-DD HH:MM、YYYY-MM-DD HH:MM:SS）」**：`--created` / `--finished` 的格式。

### 归属 / 状态类（退 1，先弄对归属）

- **「任务 X 还没有人认领（在公共池里），先 claim 再改」**：在动池里的任务。要接手先 `claim`。
- **「任务 X 不在我的分片里（只能给自己的任务记进展）」/「（只能结案自己的任务）」**：`log` / `close` 只能对自己名下的任务用；已结案的任务也会撞这条（结案后不在任何分片里）。
- **「任务 X 不在我的分片里，也没在公共池里」**：任务号打错，或任务已被别人认领。
- **「任务 X 已在 Y 的分片里（别人正在做），不能认领」/「任务 X 的负责人是 Y，不是你（Z）」**：动别人名下的任务一律拒绝。
- **「公共池里没有任务 X（已经被人认领或不存在）」**：`claim` 扑空。
- **「Y 还没在索引里登记过 ⇒ 不能交接给他」**：`set --owner <uuid>` 指向一个没在 `owners.json` 登记过的身份（对方从没成功写过台账）。新同事用 `init --new` 建的身份要**先写一条自己的任务**才会被登记（`init` 只写机器身份文件、不碰台账）；用 `init --claim` 认领老 uuid 的人一开始就在名册里。
- **「任务 X 在 Y 的分片里已经存在，且内容与本次不一致 ⇒ 拒绝交接」**：对方名下已有一份不一样的同名任务，交不过去。
- **换人只能「对方释放 → 你认领」**：`set --release` 放回公共池，对方自己 `claim`；不要绕过脚本改 JSON。

### 台账本身有问题（退 1 / 退 3）

- **「任务 X 在公共池里但状态是 S（应为 open）—— 先跑 validate 看台账是不是乱了」**：池里混进了已认领的任务（多半搬移崩了一半）。跑 `validate` 看全部问题，确认哪份最新后删掉多余那份，或重跑一次对应命令（幂等）。
- **「X 的 N 不是对象（是 T），这份台账读不了」/「任务 X 在 Y 里不是一条对象，台账可能坏了」**：结构坏了 ⇒ **退 1**（业务错），按提示用 git 恢复（`git checkout -- <文件>`），不要手改。
- **「X 不是合法 JSON（第 N 行）：…」**：语法坏了 ⇒ **退 3**。若文件里有 `<<<<<<<` 冲突标记（推送被拒后 rebase 没解完），先解冲突再重跑；`validate` 会把这种情况列为问题（退 1），别的读命令直接退 3。
- **「台账索引 owners.json 找不到了，但 owners/ 下还有任务文件」**：索引被手动删 / 改名。用 git 恢复 `owners.json` 再重试，程序不自动修复。
- **「任务号连续冲突 20 次，请检查台账是否异常」**：随机码连续撞号，先 `validate`。
- **「历史里有一条没有过程文档链接的旧行…请人工看一眼再重跑」**：`close` 时撞上解析不出来的历史行，人工确认那行后再跑。

### 写前被拦（guard 三查，退 1）

- **「本地有未提交的台账改动：… 处理：先提交它们（git add <文件> && git commit），再跑本命令」**：先提交再重跑；离线可加 `--no-sync` 只写本地。
- **「本地有未推送的台账提交：… 处理：先 git push；或者加 --no-sync 只写本地（之后要记得推）」**：没有「自动补推再写」这一步，就是让你先推。
- **「有还没入库的同名台账文件（提交会被它们挡住）」**：同名文件还没 `git add`，先入库。
- **「仓库处于中间态（rebase-merge / rebase-apply / MERGE_HEAD）：先跑 git status 看提示，完成或中止它（git rebase --abort / git merge --abort）再跑本命令」**：上次 rebase / merge 没收尾。
- **「找不到台账：从当前目录往上都没有 ledger/ 目录」**：`--repo` 指对**工作区根**（直接含有 `ledger/` 的那个目录）；第一条写命令会自动把 `ledger/` 建出来，不用先初始化。
- **「--repo 指到了台账目录本身」**：你把 `ledger/` 当成了根；它的上一级才是工作区根，按报错里给的路径改。
- **「--repo 指到了台账目录里面」**：你指到了 `ledger/` 下面的某个子目录（如 `ledger/worklog`）；工作区根是那个 `ledger/` 的上一级，按报错里给的路径改。
- **「--repo 指向的不是一个目录」**：路径写错或不存在，要指到工作区根。

### 并发 / 锁（退 1 或提示）

- **「另一个会话正在同步同一份台账（已等 60 秒），请稍后重试」**：同仓库另一个 agent 正在写。等它跑完再重跑，不要并行重试。
- **「拿不到同步锁 …（本次未做任何写入）。处理：确认 git 目录可写；只需写本地文件可加 --no-sync，之后手动提交」**：锁文件是 git 公共目录里的 `dsh-task-ledger.sync.lock`，同仓库所有 worktree 共享；`--no-sync` 也跳不过这把锁。
- **「X 在本命令执行期间被改动过（可能是编辑器或 git 操作），已中止、未写入任何内容；重跑一次即可」**：写前发现目标文件被改，重跑。（目前只有 `close` 会做这项核对。）

### 写后提交 / 推送（退 1 或提示，文件都没丢）

- **「git add 失败：… 文件还在磁盘上（本次改动没丢）」**：按错误原话处理（常见：钩子 / 权限），再手动 `git add <文件> && git commit`。
- **「git commit 失败：… 文件已暂存、本次改动没丢」**：常见是 commit 检查钩子拒了消息，按提示处理后重跑。
- **「提示：没有上游分支，本地提交已保留、未推送」**：给分支设上游（`git push -u origin <分支>`）后重跑即可推走。
- **「提示：推送被拒（远端有新提交）… 且本地还有你自己的提交 ⇒ 不自动 rebase」**：脚本故意不动你的非台账提交。手动 `git pull --rebase && git push`；重推时它们会被一并推上去，自行确认。台账改动已提交在本地，不会丢。
- **「提示：推送被拒，本次台账改动已提交在本地、未推送」**：手动 `git pull --rebase && git push`（普通文本冲突自己解；脚本的「按任务号合并」只在它自动重试时发生）。
- **「提示：推送被拒后 rebase 撞上冲突，已按任务逐个标出冲突（标记里左边是远端、右边是本机）」**：同一任务被两边同时改。编辑该文件保留要的版本 → `git add` → `git rebase --continue`；不想合就 `git rebase --abort` 回到写之前。
- **「错误：自动 rebase 后回滚也失败了，仓库可能停在 rebase 中间态」**：**先别跑任何台账命令**。`git rebase --abort`；仍失败就看 `git status` 残留，必要时删 `.git/rebase-merge` / `.git/rebase-apply`。
- **「X 的手写改动与上游的最新版本冲突，冲突标记已留在工作树里」**：逐个编辑解决冲突 → `git add <文件>` → `git stash drop`，然后重跑。**顺序不能反**：先 drop 再解决，手写的那段就没了。
- **「提示：写前拉取失败（远端连不上），本次按本地最新内容写；推送也可能失败」**：网络问题，照写；稍后联网了重跑一次同步。

### 只提示、不拦（退出码 0）

- **（「这台机器还没有初始化身份。」不在此列** —— 它是退 1 的硬拦，见「身份闸门」。）
- **「提示：格式版本是 … 当前是 …；不拦，但字段可能有出入」**：数据是旧版本写的，功能照常；想统一就按提示升版本。
- **「提示：写前把本地快进到 …（N 个提交，仅 fast-forward）」**：纯告知。
- **「提示：写前快进到 … 没成功（工作树有未提交改动），改为只刷新本次要写的台账文件」**：没碍事，照写。
- **「提示：rebase 成功，但把你的未提交改动放回工作树时冲突了」**：冲突标记只在被点名的文件里，解完 `git add` 后重跑台账命令即可。
- **「提示：只写了本地文件、未签入 git（也未推送）」**：用了 `--no-sync`；之后自己 `git add ledger && commit && push`。
- **「提示：当前目录不是 git 仓库，台账只写了本地文件」**：没有 git 也能用；想纳入版本管理就 `git init`，否则继续本地写（多人各写各的，后写覆盖先写）。
- **「提示：任务 X 没有过程文档，已跳过封卷，历史末列留空」**：老数据没有 worklog 字段，结案照常，只是没有文档可封。
- **`无需重复：这次没有新的改动。`**（`claim` / `set` / `close` 的 already_done 通道）：上次已经做成过，重跑是幂等空转；`close` 重跑还会顺手补齐上次崩在半途的封卷与移出。
- **`validate` 的 notices**（同号任务出现在多个文件、历史解析警告等）：只提示不判错，照实转述。

## validate 查什么（有问题 ⇒ 退出码 1）

两档：默认**浅度**只查格式与结构（账本 JSON + 当月历史）；加 **`--deep`** 才多读全部历史月份。**两档都不读过程文档正文**（存量可达上万篇；过程文档是附件，格式与内容不在体检范围）。

problems（任一即退 1）：① 池里任务带着 owner；② 池里任务 status 不是 open/doing；③ 索引登记了身份但分片文件不在；④ 分片任务没有 owner；⑤ 分片任务 owner 与分片所属键不一致；⑥ 分片任务 status 非法；⑦ `owners/` 里有索引没登记的 `*.json`。
notices（只提示）：历史解析警告、历史有结案行但任务还在办、还没有 `owners.json`。
①~⑦ 里结构类的属人工裁决：读原文确认哪份是真的，删多余那份或把索引改对，**不要用脚本猜**。索引或任一 JSON 损坏 ⇒ 退 3。

## 读命令只读本地（跨机器要先取最新）

- **读命令（`list` / `stats` / `owners` / `show` / `history` / `whoami` / `validate`）不会自动 `git pull`**：看到的是**这台机器上一次同步后的**台账（`whoami` 连台账都不读，只看本机身份；`root` 连台账数据都不读，只看目录结构）。
- 想看别的机器刚写的东西：先 `git pull`，或者跑任意一条写命令（写命令进入时会先取最新）。

## 写前取最新与写后同步（机制）

- 写命令全程持仓级锁（git 公共目录里的 `dsh-task-ledger.sync.lock`，同仓库所有 worktree 共享，最多等 60 秒；`--no-sync` 也跳不过这把锁）。只读命令不排队。
- **写前**：先 guard 三查 —— scope 内非 worklog 台账文件有未提交改动 / 有未推送的台账提交 / 有未入库的同名文件，命中即中止；再定向取最新：自举 scope（`owners.json` + `pool.json` + 我的分片）加动作 scope（`new` 加目标文件与当月 worklog 目录；`claim` / `set` 还加索引里其他人的全部分片；`close` 加当月 `history/`；任务没有 `worklog` 字段时退整个 `worklog/`）。干净就刷成远端最新，本地有未提交手写改动就 stash → 快进 → 叠回，冲突即中止。`worklog/` 目录只刷新本地已存在的文件（上游新增的不会自动补下来）。
- **写后**：只 `git add` 台账路径，然后 `commit --no-verify` —— 提交失败退 1；push 失败只提示、退 0，被拒时自动 `rebase --autostash` 合并一次：不同任务自动合并，同一任务两边都改留冲突标记让人定；本地有非台账提交时不 rebase。
- **回滚**：命令失败时，写前刷下来的内容按字节还原、本次新建的文件删掉；业务写的自补偿只有两处 —— `new`（删任务行 + 删文档）、`close`（三个文件按字节还原）。
- **`--no-sync` / `TASK_LEDGER_NO_SYNC=1`**：跳过 guard、取最新、提交与推送；自举照跑；有写入时会提示「只写了本地文件、未签入 git」。注意它挂在**顶层**：`progress --no-sync <子命令> …`，放子命令后面是用法错。
- **环境**：git ≥ 2.27（自动合并依赖 `rebase --autostash`）。不是 git 仓库 ⇒ 同步整体跳过、台账照写，并提示「只写了本地文件」；连 git 二进制都没装也照样写（身份只读本机 identity 文件，与 git 无关）。

## 硬约束

不要直接编辑 `ledger/pool.json`、`ledger/owners.json`、`ledger/owners/*.json`、`ledger/history/*.md`；不要另建 worklog；不要手写「执行记录」节。
