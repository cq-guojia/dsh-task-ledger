# task-ledger

台账只管三件事：**谁在做、做到哪、什么时候建 / 结**。状态只在台账 JSON（`pool.json` + 每人分片），叙事只在 worklog，**全部经脚本改**。

## 什么时候用

❌ 项目没有 `ledger/` 且只是临时一次性的事 → 先问要不要建台账（不用先初始化：第一条写命令会自动把台账建好）。
❌ 只想改某任务正文 → 用 `show` 拿路径直接改，不要另建 md；已结案的用 `history` 找链接。

## 台账文件

| 文件 | 装什么 |
|---|---|
| `ledger/pool.json` | 公共池：还没人认领的任务（owner 空、状态 `open`） |
| `ledger/owners.json` | 索引：身份（git 邮箱）→ 分片文件 |
| `ledger/owners/<hash>.json` | 每人一份分片：自己认领的任务 |
| `ledger/worklog/<年月>/*.md` | 任务正文，六节：背景 / 待办 / 下一步 / 过程 / 结论 / 执行记录（末节） |
| `ledger/history/<年月>.md` | 已结案，一行一条（首列结案时间、第二列创建时间） |

两条边界，先记住：

- **绝不能手改**：以上 4 类 JSON 与 history —— 只由脚本写，手改即数据损坏。任务字段：标题 / creator / owner / 状态 / 时间（`created` `started` `updated` `finished`）/ 分类标签 / 过程文档路径。
- **唯一可手写**：`worklog` 的前五节 —— 末节「执行记录」由脚本追加。写什么见「过程文档」节。

**一人一份**：自己只改自己分片；池里那条是未认领的登记，谁都不改 —— 要动先 `claim`。
**台账 ≠ 产出物**：成果按所在项目自己的约定落盘，台账只放「建 / 做 / 结」和指向成果的链接。

## 命令参考

十个子命令，按生命周期顺序。参数语法一律看 `<子命令> --help`，不要凭记忆编；下表只说每个参数干什么、何时用。

### new — 建任务

| 参数 | 含义 |
|---|---|
| `--title "…"` | 任务标题（必填） |
| `--self` | **建并认领**：直接进自己分片、owner=我、状态 `doing`、记 `started`。不加 = 纯新建，落公共池等认领 |
| `--id` | 自定义任务号（默认：年月日-时分 + 标题语义名 + 4 位随机码） |
| `--created` | 补录创建时间（按本地墙钟给；补录时 `updated` 一并等于该时间，之后补一条 `log`） |
| `--category` / `--tags` | 分类 / 标签，口径见本节末尾 |

干什么：建任务、按模板建好过程文档，落公共池（或 `--self` 落自己分片）。失败会自动删掉刚建的任务行和文档，不留残骸。

分类 / 标签口径（`new` 与 `close` 共用这组参数）：`--category` 答「是什么类型」，单值，中文 ≤4 字 / 纯英文 ≤3 词，吃不准写「其他」；`--tags` 答「涉及什么」，0~5 个、逗号分隔，写不出就不传（传空串等于没传）。tags 不许写 category 的同义词；统计只认 category（精确匹配），查询用 tags（包含匹配）。名词性短语、中文优先。正例：`--category 缺陷修复 --tags "镜像拉取,超时重试"`；反例：`--category 已完成登录修复`、`--tags 修 bug`。

举例：用户说「新建个任务：把发布流程走通」→ `new --title "把发布流程走通"`；用户说「建个任务，现在就做」→ `new --title "把发布流程走通" --self`。

### claim — 认领

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 认领哪个（必填） |

干什么：把公共池里的任务搬到自己分片 —— 写 owner、**状态置 `doing`**、补 `started`（接单时间）、刷 `updated`，删掉池里那行。任务在别人分片里会拒绝；已在自分片里会提示无需重复（并补删池里残留行）。

举例：用户说「这活我领了」→ `claim --id 20261023-1117-把发布流程走通-7f3a`。

### set — 改状态 / 释放 / 交接

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 改哪个（必填） |
| `--status open\|doing` | 把自己分片里任务的状态改掉（白名单外的值脚本拒） |
| `--owner ""` | **释放**：搬回公共池、owner 清空、状态回 `open`。`started` 不清 —— 逾期时钟从首次认领跑到结案，转手不重置 |
| `--owner <别人>` | 交接：写进对方分片（对方须已在 `owners.json` 登记）。看板 / 维护者通道，agent 不用 |

干什么：改自己分片里任务的状态，或按 `--owner` 释放 / 交接。注意 `--status open` 只是改状态，任务仍留在自己分片、owner 不改 —— 回公共池必须 `--owner ""`。

举例：用户说「先放一放，退回待认领」→ `set --id <任务号> --owner ""`。

### log — 记一条进展

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 哪条任务（必填） |
| `--note "…"` | 这条记录说什么（必填；一句 ~60 字，含命令 / `文件:行号` / 符号名 / 结论之一） |

干什么：刷 `updated` + 在过程文档「执行记录」节追加一行。改正文必配一条 log（见纪律）；过程文档找不到时只提示、退出 0，`updated` 已刷。

举例：一轮干完 → `log --id <任务号> --note "改了认领即 doing（claim.py:56）；下一步同步文档"`。

### close — 结案

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 结哪条（必填） |
| `--summary "…"` | 结案摘要（必填；放弃写「放弃：原因」） |
| `--finished` | 补录结案时间（按本地墙钟给） |
| `--category` / `--tags` | 覆盖分类 / 标签终值（写进 history 行） |

干什么：往当月 history 追加一行 → 给过程文档打封卷标记 → 从自己分片移除。三步原子，中途失败整体回滚。封卷后文档不再改。

举例：用户说「做完了，验收通过」→ `close --id <任务号> --summary "发布流程走通，验证 25 项全过"`。

### list — 查在办

| 参数 | 含义 |
|---|---|
| `--mine` | 只看自己分片 |
| `--pool` | 只看公共池（= 没人认领的） |
| `--owner <邮箱>` | 看某个人的（归一化精确匹配；邮箱从 `ledger/owners.json` 的 `workers` 键或 `list --json` 拿；没有 `me` 缩写，「自己」用 `--mine`） |
| `--status open\|doing` | 按状态筛（逗号分隔可多选；旧 `blocked` 读侧当 doing，`--status doing` 能捞出，`--status blocked` 反而匹配不到） |
| `--category` / `--tag` | 按分类（精确）/ 标签（包含）筛 |
| `--since` / `--until` | 按创建时间筛（只给日期含当天） |
| `--json` | 输出 JSON（`{任务号: 任务对象}`） |

干什么：合并公共池 + 所有已登记分片，列出在办任务。**默认就是全量**，没有 `--all` 参数；收窄用 `--mine` / `--pool`。

举例：「现在该做什么」→ `list --mine`；「有哪些没人认领的」→ `list --pool`。

### show — 看一条任务

| 参数 | 含义 |
|---|---|
| `--id <任务号>` | 看哪条（必填；池和所有分片都能看） |
| `--json` | 连过程文档全文一起给（人话模式只给路径） |

干什么：拿任务 JSON + 过程文档路径 / 全文。改既有任务正文前，先用它拿路径。

举例：「这个任务到哪一步了」→ `show --id <任务号> --json`。

### history — 查已结案

| 参数 | 含义 |
|---|---|
| `--owner <邮箱>` / `--mine` | 按 owner 筛 |
| `--category` / `--tag` | 按分类 / 标签筛 |
| `--since` / `--until` | 按创建时间筛 |
| `--months N` / `--limit N` | 最近 N 个月的文件 / 最近 N 条 |
| `--count-only` | 只数数 |
| `--json` | JSON 输出 |

干什么：查历史层（按月文件合并，含存量平铺文件）。一行一条，按创建时间倒序。

举例：「上周做过什么」→ `history --since <上周一日期>`。

### tags — 标签统计 / 归并

| 参数 | 含义 |
|---|---|
| `--all` | 统计过程文档的分类 / 标签 / 按人 / 按月频次（只读；对象是全部非骨架文档，含已封卷的） |
| `--rename 旧 新` | 把在办任务里的旧标签归并成新值（批量写） |
| `--dry-run` | 预览：报条数与任务号，零写盘 |

干什么：标签的统计与归并。`--rename` 只改自分片里的在办任务和对应过程文档头部，已封卷文档不动。必须带 `--all` 或 `--rename`，裸跑会报错退出。

举例：「标签太乱，两个标签一个意思」→ `tags --all` 看频次 → `tags --rename 旧 新 --dry-run` 报条数与任务号 → 用户确认后去掉 `--dry-run` 才真改。

### validate — 台账体检

| 参数 | 含义 |
|---|---|
| `--json` | JSON 输出 |

干什么：只读检查结构问题（索引 ↔ 分片不一致、同一任务号出现在两个文件、池里混了已认领的任务等）。有问题退出码 1，只报不改。

举例：台账可疑 → `validate`。

## 怎么调用

```bash
python3 <本 SKILL.md 所在目录>/scripts/progress.py <子命令> --repo <当前工作区>
```

- 定位项目：`--repo <目录>` 给了就用；不给就从当前目录逐级向上找第一个含 `ledger/` 的目录，找不到直接报错。没有 `init` —— 第一条写命令自动把台账建好。
- `tags` 必须带 `--all` 或 `--rename`。
- `--json` 只对只读命令（`list` / `show` / `history` / `validate` / `tags --all`）有意义，写命令传了也按人话打。
- 返回：`new` 给落点 + worklog 路径；`claim` / `set` 只回改了哪些字段；`log` 回一行确认；`close` 回结案摘要；`show` 人话只给路径；`list` / `history` 只回摘要。

## 任务生命周期

用户要「做某件事」时按这条线走。参数与举例见「命令参考」，此处不重复。

1. **建（不认领）**：用户只说「新建一个任务」→ `new --title "…"`。落公共池、`open`、等认领。**仅仅说「新建」不叫我的。**
2. **建并认领**：用户说「建一个任务并认领 / 我现在就做」→ `new --title "…" --self`。直接进自己分片、`doing`、记 `started`。
3. **找已有的**：用户说「我们来做 X」→ 先 `list --mine` 找自己分片，在做的直接接着做；没有 → 在公共池里找（`list --pool`），找到先向用户确认：「X 还没认领，认领它吗？」→ 用户点头再 `claim`；哪儿都没有 → 按第 2 步 `new --self` 建。
4. **认领**：`claim --id <任务号>` —— 池 → 自己分片，状态即 `doing`，记 `started`。
5. **推进**：改 worklog 前五节 → 按「过程文档」节的收工三步记 `log`。卡住也 log（写清卡在哪，不改状态）。
6. **交付待验收**：任务留 `doing`，「待办」写「待用户验收」，「下一步」写清验收看什么；照收工三步记一条 `log --note "已交付待验收：…"`。
7. **释放**：`set --owner ""` → 回公共池（`started` 不清，逾期时钟继续跑）。
8. **结案**：用户明说「做完了 / 验收通过 / 不做了」才 `close --summary "…"`。此后文档封卷，只读。
9. **查询**：在办 `list` / 单条 `show` / 已结案 `history` / 标签 `tags --all` / 体检 `validate`。

## 过程文档

**全部数据文件里，唯一允许手写的就是它（前五节）**。`new` 按模板建好六节骨架，路径写进任务对象。

| 节 | 写什么 |
|---|---|
| 背景 | 为什么做：触发它的原话 / 现象 / 链接 |
| 待办 | 还没做的、没验证的、等别人给东西的 |
| 下一步 | 下一个**具体动作**（文件:行号 级别），不写「继续推进」 |
| 过程 | 踩坑与证据：带 revision + `文件:行号` 或符号名 |
| 结论 | 做成了什么、留了什么坑；只写可验证事实，评价等用户验收 |
| 执行记录 | 脚本维护 |

规则：

- 直接改前五节；**标题不许改名**（脚本不校验，但「执行记录」这个节名动一个字，脚本就会在文末再补一节）。
- 头部只有创建时间 / 创建人、封卷标记、分类 / 标签行 —— **状态与 owner 以台账 JSON 为准，别从头部读**。
- 老文档没有「执行记录」节：不用补，脚本第一次记时自动在文末补；文档找不到时 `log` 只提示、退出 0，用 `show` 查路径，不要手写。
- 执行记录行格式 `- 本地时间 · 类型 · @谁 · 说明`，`@谁` 是这次动手的人、不是任务现 owner；只追加、不改旧行。
- 改既有任务：`show --id <任务号>` 拿路径 → 直接改前五节 → 按收工三步记 log。

### 收工三步（「收工」= 这一轮对用户有可见产出）

1. 改正文：这轮变化的事实都落笔，「下一步」写具体动作。
2. 跑 `log`：这一轮只要改过正文就必须记（一轮至少一条；纪律见上）。正文没变也能记一条推进，但要同时重写「下一步」。
3. 回读末行（`tail -n 3 <路径>`）：说明 = 这轮的事。执行记录行的时间是**本机本地时间**（台账 JSON、任务号、文件名、历史行才是 UTC），别当成没记上。

**什么算一个节点**：明天自己想不起来、或换个人接手会看不出的事，就记一条；一次状态 / 结论变化对应一条，不对应一次工具调用。不记：读文件、跑 `list`、改错别字、依赖锁文件变更。拿不准够不够格、`--note` 不会写 → 见 `references/log-note.md`。

## 纪律

### 数据完整性（脚本管不了的，违反了数据就脏）

- **执行记录禁手改**：只由脚本按 `new / claim / set / release / log / close` 追加，只增不改。
- **改正文必配一条日志**：动了 worklog 的正文（改一句、补一节、改标题、修错字都算）就必须立刻跑一次 `log`。脚本不校验，别指望它兜底。
- **换人只能「释放 → 认领」**：`set --owner ""` 放回公共池，对方自己 `claim`；不许替别人挂名字（`set --owner <别人>` 是看板 / 维护者通道，agent 不用）。
- **owner 只能来自 git**：脚本自己取（`git var GIT_COMMITTER_IDENT`，退回 `git config user.email`），不能外部传入；读不到走兜底身份并出一条提示，命令照常跑完 —— 看到提示让用户配 git，否则任务记不到正确名下。
- **状态只有 `open` / `doing`**：`done` 只能由 `close` 产生；没有 `blocked`，卡在哪写进正文。逾期（`started` 满 14 天）/ 停滞（`updated` 满 3 天）/ 积压（`created` 满 30 天仍 `open`）都由看板按时间算，台账里不存、不手改 —— 别改状态去表达。

### 人类授权（跑之前问不问）

| 命令 | 档位 | 要求 |
|---|---|---|
| `new` / `claim` / `set` | 动手类 | 执行前把完整参数复述给用户并取得确认 |
| `log` | 免确认 | 本任务的推进 / 卡点 / 交付记录直接跑，跑完一句话交代「已记执行记录：…」；要替用户下结论、或替别人记，先问 |
| `close` | 独立授权 | 只认用户明确的验收 / 结案 / 放弃指令；**agent 自判「干完了」不算** —— 那是交付，停在 `doing` 等用户回话 |
| `tags --rename` | 批量写 | 先 `--dry-run` 拿到条数与任务号，报给用户确认，再去掉 `--dry-run` 才真改 |
| `list` / `show` / `history` / `validate` / `tags --all` | 只读 | 直接跑 |

### 故障处置（跑之后出事怎么办）

- **非 0 退出就停手**、原样报告，不要绕过脚本手改台账 JSON 或历史层。
- **退出码 0 不等于没事**：写命令的提交失败会退 1；推送失败仍退 0、原因只写在输出里。写命令跑完必看输出，出现 `提示：` / `错误：` / `警告：` 就先用一句话说清「发生了什么 + 下一步做什么」，再按 `references/troubleshooting.md` 给步骤；纯告知类一句话带过。只读命令只有 `错误：` 才需要转述。
- **并发冲突**（文件被改动、抢不到锁）重跑一次即可；台账同步一律交给脚本，不要自己 `git pull` / `rebase` 去「解决」。
- 同一仓库里写命令**排队**执行（最多等 60 秒），并发时不要重试轰炸，等前一个跑完再重跑。
