## 二、页面结构（`main` keyed 槽整页）

- **头部**：左 = 「← 返回会话」（`selectPanel(null)`）+ 标题「任务台账」；右 = Segmented 两 tab：**任务 / 统计**（名称占位，用户未最终定稿）。

### 任务 tab（首页）

**2026-10-17 下午改版定稿**（专家组讨论：产品 / 项目 / 开发 / 数据 / UI 五方；依据本机 `dsh-task-dispatch-table` 设计系统与 `dsh-context`「上下文洞察」页）。三条主线：**统计卡换成有决策面的指标 + 右侧趋势图**、**列表分两区（我的 / 按工作区）**、**控件样式与高度全站统一**。

#### 1. 统计卡区：左 8 块（2 行 × 4 列）+ 右趋势图

**布局照参考图（dsh-context「上下文洞察」）**：左侧 8 张卡排成 2 行 × 4 列，右侧一张趋势图卡，两栏**完全等高**（cards 两行 `minmax(0,1fr)` 均分 + 卡 `height:100%` + 图表绘图区 flex 拉伸）。列数写死 4 → 2（媒体查询），**绝不给 3 列**——3 列会排出 3+1 的非对称（用户 2026-10-17：「一定要上下对称…不能这么断」）。

**页宽**：`max-width` 1120 → **1280**（用户 2026-10-17 二选一：加宽 vs 全屏）。取**加宽**：下面是两区长列表，全屏会让行宽过宽、扫读困难；参考插件是纯仪表盘才适合全屏。若宿主面板本身更窄，1280 只是上限、不会破版。

**主数字字号**：宿主字号族最大 16px，看板主数字偏小 ⇒ 单开一档 `--dtl-font-stat: 26px`（2026-10-17 用户：「数字有点太小」）。口径小字保持 `--dtl-font-xs`。文案全员书面化（「最老一条躺了 M 天」→「最长未认领 M 天」、「别人在做 M」→「其他成员负责 M 条」）。

**第一行 · 操作台**（回答「我现在要干什么」，**可点**联动下方列表筛选）：

| 卡 | 主数字 | 口径小字 |
|---|---|---|
| 我的待办 | 我的进行中 | 超期 M 条（>0 才显） |
| 待认领 | open | 最长未认领 M 天 |
| 进行中 | 全部进行中 | 其他成员负责 M 条 |
| 积压 · 超期 · 停滞 | 三者合计（积压 = 待认领满 30 天 / 超期 = 接任务满 14 天 / 停滞 = 最后更新满 3 天） | 三段拆开报数（积压 M ｜ 超期 M ｜ 停滞 M） |

**第二行 · 统计台**（回答「项目健康度」，**不可点**——首页列表已不含已结案，点了也没东西可筛；要下钻去统计 tab）：

| 卡 | 主数字 | 口径小字 |
|---|---|---|
| 本周完成 | 本周（周一至今）结案数 | 新增 M 条 |
| 上周完成 | 上周结案数 | 新增 M 条 |
| 本月完成 | 本月结案数 | 新增 M 条 |
| 上月完成 | 上月结案数 | 新增 M 条 |

- **核心数字永远是「完成」**：新增只作小字对照——完成 > 新增 = 在消化，反过来 = 在堆积（2026-10-17 用户定稿：「核心还是完成嘛」）。
- **窗口用自然周期**（本周 / 上周 / 本月 / 上月），不叫 7 天 / 30 天（用户 2026-10-17 定稿）。周一边界由 host 算，hover 卡片给出**具体日期区间**（`from ~ to`），用户不用猜「本周」从哪天起。
- **0 显示「—」，不显示 0**（用户定稿）：空周期打一横杠，避免「0」被读成「没数据 / 出错了」。
- 已结案列表不在首页 ⇒ 统计台卡不可点；「本周完成」的旧口径（`--since` 按创建时间）已废，现按**结案时间**落桶。

**趋势图**（右侧卡，与左边 8 块**完全等高**；信息密度照参考图：y 轴刻度 + 网格线 + 柱顶数值 + 图例 + hover 浮卡）：

- **三根细柱 / 周**：完成（蓝）+ 未结（琥珀）+ 新增（灰），8 周 24 柱；柱宽 **5px**、组内间距 1px、**无圆角**（用户 2026-10-17：「太粗、不要圆弧」）。颜色见 `--dtl-business` / `--dtl-chart-remaining`（琥珀）/ `--dtl-chart-created`（灰）。
- **「未结」= 该周截止时仍未结案**（在办任务数）：host 逐任务对每周截止日判「创建 ≤ 周末 且（未结案 或 结案 > 周末）」，天然含窗口前遗留任务的基线 ⇒ 无需快照库、口径自洽（smoke 校验：基线单调不增且 ≥ 0）。
- y 轴三档刻度（0 / 半峰 / 峰，千位压缩成 `1.2k`）+ 淡网格线；底部 1px 基线；**x 轴标周末日期 MM-DD**（数据按截止日判，故标周截止而非周一；当前周=今天）。
- **柱顶数值只标「完成」**（核心指标）；未结 / 新增走 hover——三系列 × 8 周数值会糊成一片。
- **hover**：整列三根柱一起 `brightness(1.18)` 提亮 + 浮卡（日期 + 完成 N / 未结 M / 新增 K）；原生 `title` 太慢且长相不一，故自绘。用户 2026-10-17：「移上去应该两个都变色，不是只蓝的一根」⇒ 现三根同亮。
- **没有**均值线、没有长注释行（用户 2026-10-17：均值不要、注释太长不要、标题「近 8 周」冗余——轴上有日期）。
- 右上角**一个「只看我的」小复选框**（替掉分段切换）：勾上 = 我的，不勾 = 所有；host 一次算回两个范围 ⇒ 勾选零请求。**口径统一 = `owner` 是我（我负责的）**，完成 / 未结 / 新增三系列同口径，不会混「我做的」与「我提的」；**只作用于图表**，不动统计台卡。
- 柱高必须用百分比（绘图区随卡 flex 拉伸）；pair 容器 `top/bottom` 双锚给确定高度，否则子元素百分比被忽略 ⇒ 一根柱都看不见、只剩数字（2026-10-17 真机：改百分比后整列柱消失）。非零柱 `min-height:2px`，大基数下小值不消失。
- 宿主无图表件 ⇒ 自绘 div 柱（`ui.ts::GroupedBarChart`），无新依赖。

**数据来源（2026-10-18 拆端点）**：列表 / 操作台卡走**快路径** `/board/snapshot`（只读 `progress.json`），趋势图 / 统计台四卡走**慢路径** `/board/trend`（读 history）；两段独立请求、首屏不等趋势（20 万条实测：合并端点 4.4s → 快路径 527ms）。

| 趋势状态 | 界面表现 |
|---|---|
| 未到（待发 / 在途） | 图表区占位「趋势读取中…（列表已就绪，统计稍后到）」；周期卡主数字留「—」、小字整条不显示（不拿 0 充数） |
| 读挂（含旧宿主 404） | 图表区兜底文案 + 原因原文；列表照常可用，不白屏 |
| 就绪 | 正常画图 / 真空态「近 8 周没有记录」 |

两段各自的降级工作区（`op: list` / `op: history`）合并进同一条红色横幅，不因分段而漏报。

#### 3. 任务列表：两区结构（已结案**不在首页**）

混排读不出项目 ⇒ 分两区（2026-10-17 专家组否决「纯平铺 + 工作区标明显」，也否决「完全按工作区分组」——后者要把所有块滚完才找齐自己的事）：

- **第一区「我的待办」**：跨工作区平铺，**工作区升为一列**（图标 + 工作区名，定宽，不再是和标签混在一起的小 chip）。仅当非空时渲染。
- **第二区「按工作区」**：每个工作区一个分组小标题（`标题 ｜ 进行中 N ｜ 待认领 M`），组内排序 = 别人的进行中 → 待认领，各自按创建时间倒序；**组可折叠**，组内 > 30 条默认折叠。工作区按标题排序。
- 第一区与第二区**不重复**：进了第一区（我的进行中）的条目不再出现在第二区。
- **已结案彻底移出首页** ⇒ 统计 tab 按时间查。这一步同时解决「几百条太恐怖」：首页只装「正在办 + 待认领」。
- 行件不变：`StateDot` 状态语义 open=idle / doing=ongoing / 积压·超期·停滞=warning·overdue·danger（按时间算，不是状态）；标题 + 谁 + 何时（悬停全量时刻）+ 分类 / 标签 chip；行展开 = 过程文档路径 + 正文（`MarkdownText`）。
- 任务动作按钮（认领 / 继续 / 移交 / 结束 / 放弃）见 §三：写入路径已拍板，**按钮界面尚未实现**（结束任务的 host 方法已落地）。

## 三、任务按钮矩阵（按任务状态）

| 状态 | 主按钮 | 次按钮 | 落点 |
|---|---|---|---|
| `open` 待认领 | **认领并开始** | — | host 代跑 `claim`（立即生效）→ 起会话发「认领通知」提示词 → 跳转 |
| `doing`（owner=我） | **继续** | 移交 / 结束任务 | 继续 = 起会话发预置提示词；移交 = host 代跑换 owner；结束 = 弹框留言 → 起会话；积压/超期/停滞只是显示标记，不改变这里的动作 |
| 已结案（history） | — | 过程文档（链接） | 只读 |

各动作语义（**2026-10-18 用户拍板：按动作分流**，见 [`architecture.md`](../architecture.md) 不变量 1）：

- **认领并开始**：host 先代跑 `claim`（前置：任务 `open` 且无人认领；已被别人认领 ⇒ 报人话错误、不起会话），状态**立即**变；随后起会话发「认领通知」（B 案通知式模板，见 session-handoff §三）。
- **释放 / 放弃**：host 代跑脚本把 owner 置空 / 结案，**不起会话**（用户：「释放了就完了，就没有人了」「不能让他再开多少框，太麻烦了」）。无判断量，不需要模型。
- **移交**：host 代跑换 owner（与释放同一条写路径）；用户未单独表态，实现时按字面确认。
- **继续**：新会话首条 = 「用户准备继续任务 X，过程文档在 \<path\>，请读『下一步』继续执行」。台账不记会话 id（progress.json 无此字段）⇒ 每次继续都是**新会话**，不追溯旧会话。
- **结束任务**（本次已落地方法，界面未做）：
  1. 弹框收两样东西：**用户留言**（可空，多行）+ **模型选择**（默认 = 宿主默认模型）；
  2. 提交后 host `POST /close`：建会话（挂 preset、定模型）+ 首条消息 = 预置提示词 + 「用户现在处理结束，以下是用户的留言：…」（留言放**最末**）；
  3. 提示词里写明三条硬约束：**不要新建会话 / 不要子 agent**（这是收尾，不是新任务）、**读完过程文档直接收尾、不要回头提问**（用户已留言）、写台账只经 skill 脚本；
  4. 返回 `sessionId` 供 `openSession` 跳转；**任务在模型真正 close 前仍留在列表**，界面需明示「模型确认后关闭」。

## 四、交接链路（技术约束，已核实）

浏览器半**没有**往会话发自由文本的官方 API；按钮的统一形态：

```
浏览器 POST host 路由 → host ctx.agents.create() 起会话 + agent.send() 发预置提示词
                    → 浏览器 uiWorkspace.openSession(新会话 id) 跳转
```

host 是否还代跑 skill 脚本写台账 —— **已定：认领 / 释放 / 移交由 host 代跑，结束 / 继续起会话**（不变量 1）。与参考插件 dsh-task-dispatch-table「立即执行」按钮同构（`src/dispatch.ts:519-548`、`:627-634`）。逐条 API 事实与提示词模板见 [`dsh-session-handoff.md`](../external/dsh-session-handoff.md)。

现成落点：`POST /api/task-ledger/close`（`host/routes.ts::registerSessionRoutes` + `host/services/session.service.ts`），请求体 `{ ws, id, message?, provider?, model? }`，响应 `{ sessionId, warning? }`；同源守卫 + 请求体 64KB 上限。

## 五、数据与硬约束

1. **数据全部真实**：界面任何数字 / 时间 / 状态来自各工作区 `ledger/` 真文件经 host 聚合，不编造、不占位（DSH 插件规则「数据真实」）。
2. **写台账只经 skill 脚本**：插件不得手改 `progress.json` / `history` / worklog。按钮写入路径已定（不变量 1）：认领 / 释放 / 移交 = host 代跑同一个 `progress.py`；结束 / 继续 = 起会话由 Agent 跑脚本。底线不变：用户点击按钮即 skill 红线认可的「明确指令」（close 只能由用户明确的结案指令触发 —— 按钮即该指令，结束再额外要求留言作为**内容**而非授权）。
3. **刷新归前端**（用户 2026-10-17 拍板）：后端只提供按需查询，**不做 watcher / SSE / 轮询**；前端最低配 = 打开面板首读 + 手动刷新按钮。浮标角标点开时随手刷新，关闭期间不后台轮询（个人 / 中小项目场景，一天看一会儿，计数过期无感；将来要 freshness 也是前端加慢轮询，后端不用动）。
4. **空态三分**：未就绪（不渲染）/ 真空（虚线引导卡）/ 筛选空（小字）。
5. **样式硬约束**（明暗判据、token、无表格件）见 [`ui-style.md`](../ui-style.md)；列表行自绘已在本文 §二 定稿。
6. **量级边界**（2026-10-17 实测拍板）：在办路径（`progress.json`）与历史量无关，永远 <0.5s；历史路径有界——统计卡数行封顶（毫秒级）、已结案列表默认近 13 个月 + 500 条/页。实测基准（4 核）：单仓 5 万行全量 = 1.18s / 30MB JSON；10 仓 × 5 万并行 = 6.7s / 298MB ⇒ 不可用，上述窗口 + 封顶后首屏 <0.3s。20 人团队 4 万条/年场景覆盖；单仓十万级以上的首次全量搜索按秒计（loading 明示）。
