> **来源**：用户需求原话（2026-10-16 深夜对话：入口形式 / 首页构想 / 任务按钮逻辑）+ 需求讨论结案任务结论

## 一、入口：右上角浮标（`shell.overlay`）

**唯一入口**，不占侧栏（参考插件的侧栏条目形式被用户明确否决「太显眼」）。

| 项 | 定论 |
|---|---|
| 槽位 | `shell.overlay`（list / root，0.2.0-rc.2 亲验）：全帧浮层，官方注释 "a badge, a toast stack or a status pill all belong here"；第三方条目**并排添加**不替换 |
| 形态 | 自绘小图标按钮（用户提供的插件图标），`position:absolute; top:var(--dsh-frame-overlay-top); right:12px`；浮层默认 `pointer-events:none`、子元素自动恢复，**不挡下方应用** |
| 角标 | 我名下（owner = 当前 git 身份）`doing` + `blocked` 计数，>0 才显示；0→n 跳变时一次脉冲动画，不自动消失 |
| 通知 | 宿主**无**推送通知 API（grep 两包无 notification）⇒「通知」= 角标计数，不用系统通知。**不用 SSE**：2026-10-17 拍板后端纯按需 ⇒ 角标与整页共用同一份快照（首读 + 手动刷新） |
| 点击 | `ctx.layout.selectPanel(<看板 id>)`，且列表落到「我的待办」筛选态 |
| 备选（未采用） | `sidebar.panellist` 条目 `order` 放大沉到侧栏底部「设置」旁；真机用一周仍找不到入口再补（加一条 list 注册约十几行） |

## 二、页面结构（`main` keyed 槽整页）

- **头部**：左 = 「← 返回会话」（`selectPanel(null)`）+ 标题「任务台账」；右 = Segmented 两 tab：**任务 / 统计**（名称占位，用户未最终定稿）。
- **非 `conversation` 键不绑 Session**：看板不消费会话上下文，无需处理会话状态。

### 任务 tab（首页）

**2026-10-17 下午改版定稿**（专家组讨论：产品 / 项目 / 开发 / 数据 / UI 五方；依据本机 `dsh-task-dispatch-table` 设计系统与 `dsh-context`「上下文洞察」页）。三条主线：**统计卡换成有决策面的指标 + 右侧趋势图**、**列表分两区（我的 / 按工作区）**、**控件样式与高度全站统一**。

#### 1. 统计卡区：左 8 块（2 行 × 4 列）+ 右趋势图

**布局照参考图（dsh-context「上下文洞察」）**：左侧 8 张卡排成 2 行 × 4 列，右侧一张趋势图卡，图表卡与两行卡**等高拉伸**（`align-items:stretch`）。列数写死 4 → 2（媒体查询），**绝不给 3 列**——3 列会排出 3+1 的非对称（用户 2026-10-17：「一定要上下对称…不能这么断」）。

**第一行 · 操作台**（回答「我现在要干什么」，**可点**联动下方列表筛选）：

| 卡 | 主数字 | 口径小字 |
|---|---|---|
| 我的待办 | 我的 doing+blocked | 其中阻塞 M（>0 才显） |
| 待认领 | open | 最老一条躺了 M 天 |
| 进行中 | doing+blocked | 别人在做 M |
| 阻塞 · 停滞 | 阻塞数 | **停滞** M 条（红字，>0 才显） |

**第二行 · 统计台**（回答「项目健康度」，**不可点**——首页列表已不含已结案，点了也没东西可筛；要下钻去统计 tab）：

| 卡 | 主数字 | 口径小字 |
|---|---|---|
| 本周完成 | 本周（周一至今）结案数 | 新增 M 条 |
| 上周完成 | 上周结案数 | 新增 M 条 |
| 本月完成 | 本月结案数 | 新增 M 条 |
| 上月完成 | 上月结案数 | 新增 M 条 |

- **核心数字永远是「完成」**：新增只作小字对照——完成 > 新增 = 在消化，反过来 = 在堆积（2026-10-17 用户定稿：「核心还是完成嘛」）。
- **窗口用自然周期**（本周 / 上周 / 本月 / 上月），不叫 7 天 / 30 天（用户 2026-10-17 定稿）。周一边界由 host 算，hover 卡片给出**具体日期区间**（`from ~ to`），用户不用猜「本周」从哪天起。
- **0 显示「—」，不显示 0**（用户定稿）：空周期打一横杠，避免「0」被读成「没数据 / 出错了」。
- 已结案列表不在首页 ⇒ 统计台卡不可点；「本周完成」的旧口径（`--since` 按创建时间）已废，现按**结案时间**落桶。

**趋势图**（右侧卡，可切范围；信息密度照参考图：y 轴刻度 + 网格线 + 柱顶数值 + 图例 + hover）：

- **分组柱**：每周两根细柱 —— 完成（蓝）+ 新增（灰），8 周 16 柱；柱宽 8px、组内间距 2px。
- y 轴三档刻度（0 / 半峰 / 峰，千位压缩成 `1.2k`）+ 淡网格线；底部 1px 基线；周标签 MM-DD。
- **柱顶数值只标「完成」**（核心指标）；新增的数走 hover——16 个数值标签会糊成一片。
- 完成数**平均值虚线**（浅，带「周均 N」小签）。
- 右上角**很小的分段切换**：`所有 / 我的`，默认「所有」；host 一次把两个范围都算回来 ⇒ 切换零请求。口径写进图注：「我的 = owner 是我」；切换**只作用于图表**，不动统计台卡。
- 宿主无图表件 ⇒ 自绘 div 柱（`ui.ts::GroupedBarChart`），无新依赖；列 / 柱 / 标签全部相对 104px 绘图区绝对定位，与刻度同一基准。

#### 2. 筛选行（一行，控件全同高 28px、间距 8px）

| 控件 | 取值 | 说明 |
|---|---|---|
| 范围 Segmented | 我的 / 全部工作区（默认全部） | 「我的」时隐藏第二区 |
| 状态 Segmented | 全部 / 进行中 / 待认领 / 阻塞 / 停滞 | 「进行中」= doing+blocked |
| 工作区下拉 | 全部工作区 + 各工作区（定宽 180） | **本次新增**：五六个项目混排时最核心的那个筛选项 |
| 搜索框 | 关键字（占满剩余宽度） | 标题 / 任务号 / 人 / 分类 / 标签 |
| 刷新按钮 | — | 手动刷新，不轮询 |

**撤掉的两个**：时间范围下拉（时间只作用于统计卡与趋势图，列表不受理）、标签下拉（用户 2026-10-17 明确：要按标签找就打字搜索，不值得占一个控件位）。

#### 3. 任务列表：两区结构（已结案**不在首页**）

混排读不出项目 ⇒ 分两区（2026-10-17 专家组否决「纯平铺 + 工作区标明显」，也否决「完全按工作区分组」——后者要把所有块滚完才找齐自己的事）：

- **第一区「我的待办」**：跨工作区平铺，**工作区升为一列**（图标 + 工作区名，定宽，不再是和标签混在一起的小 chip）。仅当非空时渲染。
- **第二区「按工作区」**：每个工作区一个分组小标题（`标题 ｜ 进行中 N ｜ 待认领 M`），组内排序 = 别人的 doing/blocked → 待认领，各自按创建时间倒序；**组可折叠**，组内 > 30 条默认折叠。工作区按标题排序。
- 第一区与第二区**不重复**：进了第一区（我的 doing/blocked）的条目不再出现在第二区。
- **已结案彻底移出首页** ⇒ 统计 tab 按时间查。这一步同时解决「几百条太恐怖」：首页只装「正在办 + 待认领」。
- 行件不变：`StateDot` 状态语义 open=idle / doing=ongoing / blocked=warning；标题 + 谁 + 何时（悬停全量时刻）+ 分类 / 标签 chip；行展开 = 过程文档路径 + 正文（`MarkdownText`）。
- 任务动作按钮（认领 / 继续 / 移交 / 结束 / 放弃）见 §三，**写入路径拍板前不画**。

#### 4. 空态三分（不变）

未就绪不渲染 / 真空引导卡（一个台账工作区都没有，或一条任务都没有）/ 筛选空小字。

### 统计 tab

分类分布、按人完成数、本周 / 累计趋势、时间线 —— 全部同源聚合。**本文不预设其布局**，随「统计报表 tab」任务展开（用户原话：右上角滑动功能先占位）。

## 三、任务按钮矩阵（按任务状态）

| 状态 | 主按钮 | 次按钮 | 落点 |
|---|---|---|---|
| `open` 待认领 | **认领并开始** | — | 起会话发预置提示词 → 跳转（提示词模板见 [`dsh-session-handoff.md`](../external/dsh-session-handoff.md) §三） |
| `doing`（owner=我） | **继续** | 移交 / 结束任务 | 起会话发预置提示词 → 跳转 |
| `blocked`（owner=我） | **继续** | 移交 / 结束任务 | 起会话发预置提示词 → 跳转 |
| 已结案（history） | — | 过程文档（链接） | 只读 |

各动作语义：

- **认领并开始**：新会话首条消息 = 认领通知模板。claim 由谁执行见下方「写入路径待定」。
- **继续**：新会话首条 = 「用户准备继续任务 X，过程文档在 \<path\>，请读『下一步』继续执行」。台账不记会话 id（progress.json 无此字段）⇒ 每次继续都是**新会话**，不追溯旧会话。
- **移交**：弹层选新 owner（候选 = history 中出现过的 git 身份 + 手输），选定后起会话发移交提示词（模板见 session-handoff §三）。
- **结束任务**：确认框（内嵌折叠展示将发送的提示词全文，intent-and-confirmation）→ 起会话，首条 = 结案指令模板；**任务在模型真正 close 前留在列表**，Toast 明示「模型确认后关闭」。
- **放弃**：确认框（可选填原因）→ 起会话发放弃提示词（模板见 session-handoff §三），由会话里的 Agent 执行 close。与「结束」分开的理由：放弃无判断量，不需要模型判断、只需执行。

> ⚠️ **写入路径待定**（architecture.md 不变量 1，2026-10-16 深夜挂起）：上表「落点」列写的是**全会话制**（方案 A）——五个按钮全部只起会话，写台账由会话里的 Agent 经 skill 脚本完成。曾设计的**混合制**（方案 B：认领 / 移交 / 放弃 / blocked 解阻由 host 代跑 `progress.py`、状态立即生效）与「插件对台账只读」的原口径冲突，两案未决。**「任务按钮与会话交接」任务开工第一件事就是拍这个板**；拍板前本节视为未定稿，实现不得先斩后奏。

## 四、交接链路（技术约束，已核实）

浏览器半**没有**往会话发自由文本的官方 API；按钮的统一形态：

```
浏览器 POST host 路由 → host ctx.agents.create() 起会话 + agent.send() 发预置提示词
                    → 浏览器 uiWorkspace.openSession(新会话 id) 跳转
```

host 路由是否还代跑 skill 脚本写台账（混合制）——**待定**，见不变量 1。与参考插件 dsh-task-dispatch-table「立即执行」按钮同构（`src/dispatch.ts:519-548`、`:627-634`）。逐条 API 事实与提示词模板见 [`dsh-session-handoff.md`](../external/dsh-session-handoff.md)。

## 五、数据与硬约束

1. **数据全部真实**：界面任何数字 / 时间 / 状态来自各工作区 `ledger/` 真文件经 host 聚合，不编造、不占位（DSH 插件规则「数据真实」）。
2. **写台账只经 skill 脚本**：插件不得手改 `progress.json` / `history` / worklog。按钮引发的写入**路径待定**（不变量 1）：A 案 = 按钮只起会话、由 Agent 跑脚本；B 案 = host 代跑同一脚本。两案共同的底线：用户点击按钮即 skill 红线认可的「明确指令」（close 只能由用户明确的结案指令触发 —— 按钮即该指令）。
3. **刷新归前端**（用户 2026-10-17 拍板）：后端只提供按需查询，**不做 watcher / SSE / 轮询**；前端最低配 = 打开面板首读 + 手动刷新按钮。浮标角标点开时随手刷新，关闭期间不后台轮询（个人 / 中小项目场景，一天看一会儿，计数过期无感；将来要 freshness 也是前端加慢轮询，后端不用动）。
4. **空态三分**：未就绪（不渲染）/ 真空（虚线引导卡）/ 筛选空（小字）。
5. **样式硬约束**（明暗判据、token、无表格件）见 [`ui-style.md`](../ui-style.md)；列表行自绘已在本文 §二 定稿。
6. **量级边界**（2026-10-17 实测拍板）：在办路径（`progress.json`）与历史量无关，永远 <0.5s；历史路径有界——统计卡数行封顶（毫秒级）、已结案列表默认近 13 个月 + 500 条/页。实测基准（4 核）：单仓 5 万行全量 = 1.18s / 30MB JSON；10 仓 × 5 万并行 = 6.7s / 298MB ⇒ 不可用，上述窗口 + 封顶后首屏 <0.3s。20 人团队 4 万条/年场景覆盖；单仓十万级以上的首次全量搜索按秒计（loading 明示）。
