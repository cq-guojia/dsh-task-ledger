## 一、入口：左侧栏条目（sidebar.panellist）+ main 整页

当前实现只有两个注册点（见 architecture.md 不变量：无浮标）：左侧栏条目 `sidebar.panellist` + `main` 整页，代码只注册这两者，**没有** `shell.overlay` 浮标。

| 项 | 定论 |
|---|---|
| 侧栏条目 | `sidebar.panellist`（list / root，0.2.0-rc.2 亲验）：*"Global panel icons. Each list id addresses the matching main panel"*；条目元数据 `{ id: MainPanelId, order: 30, label }`，**行按钮 / 点击 / 激活态全由侧栏与布局服务托管**，组件只画图标（颜色走 currentColor 自动跟随选中态）。label 在渲染期求值 ⇒ 模块级 t 席位（`locale.bind`）|
| 整页 | `main`（keyed / root，0.2.0-rc.2 亲验）：保留键 `conversation`，其他键**不绑 Session**；看板两 tab（任务 / 统计）在此自绘 |
| 点击 | `ctx.layout.selectPanel(<看板 id>)`（id 与 `main` 槽 key 同一 MainPanelId；未注册会抛错并保持当前选择，`null` 回会话）|

> 📝 **右上浮标（`shell.overlay`）未落码**：宿主提供该浮层槽位（带「我的待办」角标有通知价值），曾作为候选入口，但截至本版代码未注册，不实现。是否落地待用户真机体验后再定；若实现，宿主事实见 [`../external/client-ui-layout.md`](../external/client-ui-layout.md) §二（浮层 `pointer-events:none`、定位用 `--dsh-frame-overlay-top`）。

## 二、页面结构（`main` keyed 槽整页）

- **头部**：左 = 「← 返回会话」（`selectPanel(null)`）+ 标题「任务台账」；右 = Segmented 两 tab：**任务 / 统计**（名称占位，用户未最终定稿）。

### 任务 tab（首页）

**2026-10-17 下午改版定稿**（专家组讨论：产品 / 项目 / 开发 / 数据 / UI 五方；依据本机 `dsh-task-dispatch-table` 设计系统与 `dsh-context`「上下文洞察」页）。三条主线：**统计卡换成有决策面的指标 + 右侧趋势图**、**列表分两区（我的 / 按工作区）**、**控件样式与高度全站统一**。

#### 1. 统计卡区：左 8 块（2 行 × 4 列）+ 右趋势图

**布局照参考图（dsh-context「上下文洞察」）**：左侧 8 张卡排成 2 行 × 4 列，右侧一张趋势图卡，两栏**完全等高**（cards 两行 `minmax(0,1fr)` 均分 + 卡 `height:100%` + 图表绘图区 flex 拉伸）。列数写死 4 → 2（媒体查询），**绝不给 3 列**——3 列会排出 3+1 的非对称（用户 2026-10-17：「一定要上下对称…不能这么断」）。

**页宽**：`max-width` 1120 → **1280**（用户 2026-10-17 二选一：加宽 vs 全屏）。取**加宽**：下面是两区长列表，全屏会让行宽过宽、扫读困难；参考插件是纯仪表盘才适合全屏。若宿主面板本身更窄，1280 只是上限、不会破版。

**主数字字号**：宿主字号族最大 16px，看板主数字偏小 ⇒ 单开一档 `--dtl-font-stat: 26px`（2026-10-17 用户：「数字有点太小」）。口径小字保持 `--dtl-font-xs`。文案全员书面化（「最老一条躺了 M 天」→「最长等待 M 天」、「别人在做 M」→「他人在办 M」）。

**按列成对排布**（2026-10-19 用户选 A）：8 块仍是 2 行 × 4 列，但 CSS 用 `grid-auto-flow:column` 按**列**填充（`ui.ts` `.dtl-stats__cards`），每列上下是同一对象的两个视角 ⇒ 子集关系一眼可见，窄屏 2 列时同样成对：

| 列 | 上格 | 下格 | 读法 |
|---|---|---|---|
| 1 | 我的待办 | 进行中 | 我的 vs 全部 |
| 2 | 待认领 | 积压 | 全集 vs 其中「满 30 天没人接」的 |
| 3 | 逾期 | 停滞 | 进行中的两类风险（接任务满 14 天 / 满 3 天没更新） |
| 4 | 本周完成 | 上周完成 | 环比 |

**关键结构事实**：三块风险卡全是**子集**——积压 ⊂ 待认领、逾期 / 停滞 ⊂ 进行中。小字因此一律给**本卡独有的增量信息**，不重复全集（2026-10-19 用户：「进行中共 14 条，进行中共 14 条，这不重复吗？」）：

| 卡 | 小字 | 规则 |
|---|---|---|
| 我的待办 | 逾期 M ｜ 停滞 N | 两项各自 >0 才出现；都为 0 则整条不显示 |
| 待认领 | 最长等待 M 天 | 无待认领 ⇒ 不显示 |
| 进行中 | 他人在办 M | 全是我名下 ⇒ 「均为我负责」 |
| 积压 | 占待认领 M% | 0 条 ⇒ 不显示 |
| 逾期 | 占进行中 M% | 0 条 ⇒ 不显示 |
| 停滞 | 占进行中 M% | 0 条 ⇒ 不显示 |
| 本周 / 上周完成 | 新增 M | 趋势全挂 ⇒ 显示 —（0 也显示 —，不拿 0 充数） |

三块子集卡**一律用占比、不用极值**（2026-10-19 用户定稿：「用占比，不用极值」）：占比只靠已有的分子 / 分母在前端算（`board-home.ts::share`），host 不需要额外字段，也不存在「0 条时报 0 天」的别扭。悬停各有阈值说明（`statBacklogTitle` / `statOverdueTitle` / `statStaleTitle`）。

- **核心数字永远是「完成」**：新增只作小字对照——完成 > 新增 = 在消化，反过来 = 在堆积（2026-10-17 用户定稿：「核心还是完成嘛」）。
- **窗口用自然周期**（本周 / 上周），不叫 7 天 / 30 天（用户 2026-10-17 定稿）；两块必须成对才可环比，7 日 / 30 日量级差 4 倍、不可比，且与右侧周趋势图对不上（2026-10-19 讨论结论）。周一边界由 host 算，hover 卡片给出**具体日期区间**（`from ~ to`），用户不用猜「本周」从哪天起。
- **「上月完成」已撤**：长窗吞吐由右侧周趋势图承担（2026-10-19 用户拍板选 A）。
- **0 显示「—」，不显示 0**（用户定稿）：空周期打一横杠，避免「0」被读成「没数据 / 出错了」。
- 全部卡片**均不可点**（首页列表已不含已结案，点了没东西可筛；2026-10-19 讨论中「拆开后恢复点击联动筛选」未被采用）；「本周完成」的旧口径（`--since` 按创建时间）已废，现按**结案时间**落桶。

**趋势图**（右侧卡，与左边 8 块**完全等高**；组件 `client/trend-chart.ts`；数据随 `/board/snapshot` 一起下发）
**2026-10-30 改版**（用户原话「跟历史里面那个图表差不多」）：每周**两根柱 + 一条新增曲线**，画法对齐历史页。

- **两根柱 / 周**：左 = **结案**（`done + cancelled`），一根柱里两段 —— **底蓝（business）= 完成、顶红 = 取消**（没有取消就只是一根蓝柱；2026-10-30 用户把完成色从绿改成 business 蓝）；右 = **未结**，一根柱里也是两段 —— **底琥珀 = 待认领、顶绿 = 进行中**（进行中 = 各人未结之和，待认领 = 未结 − 进行中；2026-10-30 用户：「跟左边那个一样，用不同颜色表现」）。「结案 = 完成 + 取消」是 2026-10-29 定的上位词。「新增」不再占柱，改走**中性灰**曲线（`--dtl-chart-line`，只看自己的峰值归一化，不跟柱共用量程；柱子已经占了蓝，曲线再用蓝分不清）。图例给三枚（**已结案** / **未结** / 新增）：前两枚是**上下两半的小方块**（已结案 = 取消红在上 / 完成蓝在下，未结 = 进行中绿在上 / 待认领琥珀在下），与柱里分段同向（用户 2026-10-30）。单色的那枚（新增曲线、「只看我的」时的进行中、浮卡里的单色行）**颜色直接上在方块本身**——两色的才拆子块，子块没尺寸会渲染成空方块（2026-10-30 踩过）。
- **数字全部来自 skill**（`stats --trend week --last 26w --by-owner`）：完成按 `finished`、新增按 `created`、「未结 = 该周结束时仍未结案」由 skill 用「当前在办 + 往今天倒推」算，天然含窗口前遗留任务的基线 ⇒ 无需快照库。插件只做**跨工作区按周求和**（`services/trend.service.ts`），不自己数、不解析台账。
- 尺寸（2026-10-30 用户逐条给数）：柱宽 **11.25px**（原 7.5 的 1.5 倍，**固定**——某周没有未结时只剩一根柱也不许拉宽）、同组间距 **1px**、组间 **10px**（3 → 6 → 10，真机一路嫌挤）、柱顶 **2px 圆角**。
- 柱面带 **45° 斜纹**（`--dtl-chart-stripe`：卡底色 **8%** 透明的 2px 细条、条间柱色 4px）：不改本色、只加质感，明暗主题自动跟随。2026-10-30 三轮定稿：加一点 → 柱色部分加粗、斜条调淡（32% → 18% → **8%**）。
- **两个图表的柱子只留一种实现**（用户 2026-10-30 拍板）：历史页与首页柱子同一条规则 —— 父级 `position:relative` + `border-radius:2px 2px 0 0` + `overflow:hidden` 把内部分段的方角**裁**成圆角，斜纹由父级 `::after` 覆盖层画一次（`.dtl-hist__bar::after,.dtl-trend__bar::after`），不写在各分段上（分段底色怎么改都不会吃掉斜纹）。首页「取消」段是绝对定位叠层，圆角同样交给父级裁，自己不画。
- **两张图表各写各的**（2026-10-30 用户拍板：先别动；2026-10-31 加了首页的日 / 周切换后控件差异只剩「只看我的」vs「多一个月档」）：首页这份与历史页 `history-chart.ts` 的数据形状（快照里的 `TrendView` vs 独立请求的 `HistoryTrendPayload`）和取数时机都不同，暂不抽公共图表组件，等样式定型再议；当前共用只有 tokens、`format.ts` 与 CSS 里同款的写法。
- **一屏几格按卡片实宽算**（`ResizeObserver`，组宽 23.5px + 组间 10px），不往右铺空柱；右上角**左右箭头一次翻 10 日 / 4 周**（与历史页同口径；往前不设边界，翻出数据窗口就是空槽）。箭头与粒度切换**绝对定位**在卡片右上角，不跟图例挤一排（放一排会把整行文字撑高，用户 2026-10-30）。窗口因此从 8 周放宽到 **26 周**（`host/repositories/trend.repository.ts::TREND_WEEKS`）。
- **日 / 周切换（2026-10-31 用户要）**：右上角 `Segmented`（核心件，与历史页那档同款 `size="sm"` + `tone="business"`），**只要「日」「周」两档、默认日**（历史页是日 / 周 / 月三档，这里不要「月」；用户在收尾时把默认从周翻到日）。切档**不换画法**：日档就是「一天一组两根柱」，柱宽 / 组内间距 / 组间距 / 配色 / 图例 / 浮卡结构与周档逐字一致；变的只有一格跨几天（日 1 / 周 7）与翻页步长（日 10 / 周 4）。
  - **两档桶都随 `/board/snapshot` 一次下发**（`stats --trend week --last 26w` 与 `--trend day --last 182d`，都带 `--by-owner`，host 跨工作区求和）⇒ **切档零请求**，与「只看我的」同一条取舍。日档窗口取 26 周的天数（182 天）⇒ 两档可翻范围一致；skill 的 day 粒度上限 365 桶，在线内。
  - 取数**先周后日**（`getBoardHome` 里串行）：冷缓存时周档顺手把月度缓存写下去，日档再读就是命中 —— 两段窗口覆盖同一批月份，并行跑等于把同一批历史文件读两遍。
  - 浮卡首行：日档只写**当天日期**（起止同一天，写成区间是废话），周档仍是 `from ~ to`；x 轴标签两档都标**周期截止日 MM-DD**（日档 = 当天）。
  - 图例那排加了 `padding-right:160px` 给右上角这排控件让位：它绝对定位飘在图例上方，不预留就会跟「只看我的」叠在一起。
- 卡内留白不对称：**顶 10px / 图例与图之间 12px**（用户 2026-10-30：图例离顶太远、离图太近，先 8 再 +2）。
- y 轴五档（峰 / ¾ / ½ / ¼ / 0，`formatCount`）：顶部不画线、**中间三档全虚线**、底部 1px 基线（用户 2026-10-30：「中间的线都用虚线，不要有实线」）。
- **x 轴标周期截止日 MM-DD**（数据按截止日判，故标周截止而非周一；当前周 = 今天，日档 = 当天），间距不够时隔一个标一个。

- **hover**：整组两根柱一起提亮 + 外面套一个**虚线框**（框的是一组、不是一根），纯 CSS 无 React 状态。
- **浮卡自绘**（2026-10-30 定稿）：官方 `Tooltip` 只吃纯文本、色块全丢，试过一轮后用户否掉（「还是还回来你定制的那个」）⇒ 保留色块 + 分隔线 + 右对齐数字的自绘卡片，纯 CSS hover、无 React 状态。凡是别处的短提示仍走 `Tip`（官方）。

- 柱高用百分比 ⇒ 祖先链必须有确定高度（`plot` 绝对铺满 + `col` flex）；否则子元素百分比被忽略、一根柱都看不见只剩数字（2026-10-17 真机教训）。非零柱 `min-height:2px`，大基数下小值不消失。

- 趋势读挂了**不拖垮整板**：`trend.service.ts` 自己吞「全部失败」（其余三块照常 200），失败进 `degraded`（`op: "trend"`）。

**数据来源（2026-10-31 现状）**：只有一条读端点 `/board/snapshot`（每工作区 `stats --json` + `list --json` + `owners --json` + `stats --trend week --last 26w --by-owner` + `stats --trend day --last 182d --by-owner`，后两档供趋势图的日 / 周切换）。「本周完成 / 上周完成」不再单独查 history —— 直接取趋势桶的最后两个（少两次脚本调用，口径与图表一致）；`history` 从此只负责列表。

**与 skill 的两条口径对齐（2026-10-26）**：

- **日期一律落在「脚本人话那一天」**：台账存盘时间是 UTC，只有人话输出才转查看者本地（`core/time.go::FmtLocal`）。host 侧 `services/dates.ts` 因此按本机时区取窗口边界（现在只剩周窗口），否则东八区每周一早上（UTC 还停在上周日）会整体错一天。

## 三、任务按钮矩阵（按任务状态）

| 状态 | 主按钮 | 次按钮 | 落点 |
|---|---|---|---|
| `open` 待认领 | **认领并开始** | — | host 代跑 `claim`（立即生效）→ 起会话发「认领通知」提示词 → 跳转 |
| `doing`（owner=我） | **继续** | 移交 / 结束任务 | 继续 = 起会话发预置提示词；移交 = host 代跑换 owner；结束 = 弹框留言 → 起会话；积压/逾期/停滞只是显示标记，不改变这里的动作 |
| 已结案（history） | — | 过程文档（链接） | 只读 |

各动作语义（**2026-10-18 用户拍板：按动作分流**，见 [`architecture.md`](../architecture.md) 不变量 1）：

- **认领并开始**：host 先代跑 `claim`（前置：任务 `open` 且无人认领；已被别人认领 ⇒ 报人话错误、不起会话），状态**立即**变；随后起会话发「认领通知」（B 案通知式模板，见 session-handoff §三）。
- **释放 / 放弃**：host 代跑脚本把 owner 置空 / 结案，**不起会话**（用户：「释放了就完了，就没有人了」「不能让他再开多少框，太麻烦了」）。无判断量，不需要模型。
- **移交**：host 代跑换 owner（与释放同一条写路径）；用户未单独表态，实现时按字面确认。
- **继续**：新会话首条 = 「用户准备继续任务 X，过程文档在 \<path\>，请读『下一步』继续执行」。台账任务对象无此字段 ⇒ 每次继续都是**新会话**，不追溯旧会话。
- **结束任务**（本次已落地方法，界面未做）：
  1. 弹框收两样东西：**用户留言**（可空，多行）+ **模型选择**（默认 = 宿主默认模型）；
  2. 提交后 host `POST /close`：建会话（挂 preset、定模型）+ 首条消息 = 预置提示词 + 「用户现在处理结束，以下是用户的留言：…」（留言放**最末**）；
  3. 提示词里写明三条硬约束：**不要新建会话 / 不要子 agent**（这是收尾，不是新任务）、**读完过程文档直接收尾、不要回头提问**（用户已留言）、写台账只经 skill 脚本；
  4. 返回 `sessionId` 供 `openSession` 跳转；**任务在模型真正 close 前仍留在列表**，界面需明示「模型确认后关闭」。

## 四、交接链路（技术约束，已核实）

浏览器半**没有**往会话发自由文本的官方 API；按钮的统一形态：

```
浏览器 POST host 路由 → host ctx.agents.create() 起会话 + agent.send() 发预置提示词
                    → 浏览器 uiWorkspace.openSession(新会话 id) 跳转
```

host 是否还代跑 skill 脚本写台账 —— **已定：认领 / 释放 / 移交由 host 代跑，结束 / 继续起会话**（不变量 1）。与参考插件 dsh-task-dispatch-table「立即执行」按钮同构（`src/dispatch.ts:519-548`、`:627-634`）。逐条 API 事实与提示词模板见 [`dsh-session-handoff.md`](../external/dsh-session-handoff.md)。

⏸ **原落点已删除（2026-10-28）**：`POST /close`（`routes.ts::registerSessionRoutes` + `services/session.service.ts`）、`POST /claim` `/release`（`routes.ts::registerWriteRoutes` + `services/ledger-write.service.ts`）连同客户端 `api.ts::requestClaim / requestRelease / requestClose` 一并移除。接回时**按 skill 方法重写**：写命令统一走 `repositories/runner.ts` 的 spawn 入口（本轮 `runLedgerCommand` 也已删除，需要时按「不解析 JSON、直接带 stderr 人话」的形状补回），成功后调 `cache.invalidate(workspaceId)`。

## 五、数据与硬约束

1. **数据全部真实**：界面任何数字 / 时间 / 状态来自各工作区 `ledger/` 真文件经 host 聚合，不编造、不占位（DSH 插件规则「数据真实」）。
2. **写台账只经 skill 脚本**：插件不得手改 `pool.json` / 分片 / `history` / worklog。按钮写入路径已定（不变量 1）：认领 / 释放 / 移交 = host 代跑同一个 `scripts/progress`；结束 / 继续 = 起会话由 Agent 跑脚本。底线不变：用户点击按钮即 skill 红线认可的「明确指令」（close 只能由用户明确的结案指令触发 —— 按钮即该指令，结束再额外要求留言作为**内容**而非授权）。
3. **刷新归前端**（用户 2026-10-17 拍板）：后端只提供按需查询，**不做 watcher / SSE / 轮询**；前端最低配 = 打开面板首读 + 手动刷新按钮。面板打开时随手刷新，关闭期间不后台轮询（个人 / 中小项目场景，一天看一会儿，计数过期无感；将来要 freshness 也是前端加慢轮询，后端不用动）。
4. **空态三分**：未就绪（不渲染）/ 真空（虚线引导卡）/ 筛选空（小字）。**首屏未初始化 ≠ 空结果**：`board === null` 时列表位什么都不画，并在打开面板时弹一条核心 Toast「数据正在初始化中，请稍后。」（2026-10-28）；核心 Toast 无关闭句柄，靠 `durationMs` 自退，故只在未初始化时弹一次，刷新不再弹。
5. **样式硬约束**（明暗判据、token、无表格件）见 [`ui-style.md`](../ui-style.md)；列表行自绘已在本文 §二 定稿。
6. **量级边界**（2026-10-17 实测拍板，**2026-11-01 修订**）：在办路径（pool.json + 分片）与历史量无关，永远 <0.5s；历史路径**按选中的那个自然月取数、条数不设上限**（原「近 13 个月 + 500 条/页」已作废），前端只渲染窗口内的行 ⇒ DOM 行数与总条数无关。实测基准（4 核）：单仓 5 万行全量 = 1.18s / 30MB JSON；10 仓 × 5 万并行 = 6.7s / 298MB ⇒ 不可用。**单月 6 万条**是设计目标：首次进入该月要付一次脚本解析（秒级，loading 明示），切回来靠 60 秒本地缓存与 host 1.5s 读缓存。单仓十万级以上的首次全量搜索按秒计。
