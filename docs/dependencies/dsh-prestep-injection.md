# 宿主 pre-step 注入链路

- 用途：host 半经 `agent/pre-step` 把一段规则文案送进会话首轮上下文所依赖的生命周期事件与消息契约。
- 适用版本：宿主 0.2.x 版本线为本项目目标；本机可读取的解包产物是 0.1.2-alpha.2 与 0.2.2-rc.1 的客户端 / 启动层，与目标版本线不完全对应。`snapshotEvents()` 自 alpha.4 起提供，此说法来自参考实现注释而非宿主源码核实。
- 版本真源：同栈已实机跑通的两个宿主插件实现（规则注入插件的 host 入口、记忆插件的 dsh 适配器）；本机解包产物仅作旁证；最终以会话控制器、agent、指令装配与 V4 会话格式各包的 `lib/*.js` 和 `lib/types/*.d.ts` 为准。
- 复核日期：2026-11-10

## 限制 / 坑

- 本项目尚未解包核对宿主实现本体。必须 `npm pack` 读实现才能定论的有：pre-step 事件负载与 decision 形状、V4 会话格式对注入消息 source kind 的校验与 producer 命名、指令装配包有无插件级注入口。
- 「V4 会话格式」与 `plugin:` 回退命名目前只来自参考实现注释，不是宿主源码结论。
- 本机 0.1.2-alpha.2 解包产物里没有 `snapshotEvents()`，旧宿主用 `events`。两者都缺时补回判据走「不可读」而不补回，长会话里文案可能淡出。
- 参考实现的事件日志只扫最近 30 条、按标记判存在：块滑出窗口、或压缩把它改写成语义仍在的摘要，都会假「消失」。注入判据照参考实现原样，不自加限次或窗口外判据。
- 每轮注入会重复计费并破坏提示缓存。参考实现每轮注入是因为内容随 prompt 动态检索，静态文案不可照搬该频次。
- 注入消息是 user 角色，不是 system prompt；任何「往 system 区注入」的设想都不成立。
- 宿主的指令装配包在本机解包里是默认停用的独立 cordis 插件，是否提供插件级静态区注入口不可判，不押注其上。
- 设置值由插件自有文件读写，不经宿主 settings 服务；宿主插件详情页配置区与本功能无关。
- 注册 skill 不等于注入常驻提示词；两者不共用同一份文案真源。

## 复核方式

1. `npm view` 取与宿主一致版本，`npm pack` 解包会话控制器、agent、指令装配与 V4 会话格式包。
2. 读实现本体：pre-step 事件负载与 decision 形状、source kind 校验与 producer 命名、`snapshotEvents` 契约、指令装配包有无插件级注入口。
3. 真机开一个会话，确认首轮注入一次、后续轮不追加、压缩后只在两条证明都成立时补一次。
