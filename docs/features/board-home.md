# 看板首页

## 一、入口与三段视图

侧栏条目 + `main` 整页面板。页面内是三段切换的视图：`active`（在办）、`history`（历史）、`settings`（设置）。没有独立浮标入口。

首屏数据一次拿全量：`GET /api/task-ledger/board/snapshot`（统计、在办、趋势、工作区、身份）；历史页趋势与列表分别走 `GET /history/trend`、`GET /history/list`。路由语义见 [host-data-plane.md](../architecture/host-data-plane.md)。

## 二、统计区

- 左侧 8 张统计卡（两行四列），右侧趋势图位；首屏无数据时只画标题与破折号，不填 0 冒充数据。
- 统计台卡显示**结案数**（完成 + 取消），有取消时以小字拆出「完成 X · 取消 Y」。
- 有 `tab` 的卡片可点：点一下把下方列表切到对应档位，并清空其余筛选；无 `tab` 的卡片不伪装可点。
- 卡片底色、边框、hover 一律由核心控件提供；插件侧只吃核心 token，不自绘卡片皮肤。

## 三、趋势图

`TrendChart` 真实渲染：日/周两档切换，周档叠加累计曲线；「只看我的」按当前身份过滤。数字全部来自 skill 的 `stats --trend`，插件不本地推算、不补占位。趋势取不到时不画线，保留已有的完成数。

历史页另有按粒度缓存的趋势与列表数据（`historyByGran`），切换档位时优先用已缓存值，避免闪烁。

## 四、筛选与在办列表

- 左侧菜单七档：`mine` / `all` / `open` / `doing` / `backlog` / `overdue` / `stale`，角标是当前工作区、执行人、搜索范围内的各档计数。
- 工作区、执行人、搜索框、刷新按钮是真实过滤与重新拉取；刷新带 `fresh=1` 清缓存。
- 列表按工作区分组；单人台账不显示多余分组标题。行内展示任务状态与异常标签，删除的历史行不再混入在办。
- 空态、加载态、错误态各有独立呈现；`degraded` 的工作区标红并保留其他工作区数据。

## 五、任务动作

任务行按钮统一走 `POST /task/action`：认领、继续、完成、释放、取消、删除；完成与取消经确认弹窗，危险动作与中性动作不同色。「继续」另走 `POST /task/continue` 起会话。动作成功后触发快照重读，避免界面停在旧数据。

## 六、边界

- 界面展示的任何计数、时间、状态都来自宿主或自有存储的真实值，禁止占位与模拟。
- 只有用户明确要求做效果展示时才允许 mock，且必须在代码与交付说明里标注。
