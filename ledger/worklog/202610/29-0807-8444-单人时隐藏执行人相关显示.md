## 过程

- 首版判定 `rows.ts::isSoloLedger` 把「任务上的 `owner`/`creator`」也算进并集，且 `degraded` 非空直接返回 false —— 真机上没生效。`ledger.repository.ts:74` 说明名册为空的工作区会进 `degraded`，任一工作区读挂就把整板拽回多人形态，判定太脆。
- 改口径（用户原话为准）：**只看执行人下拉的候选**（`workspaceOwners` 合并去重，与 `ownerGroups` 同一份），≤ 1 人即单人；不再看任务上的旧 uuid、不再因 `degraded` 放弃判定。
- 第二次真机（构建编码 `261029-163912-590`）：下拉、「只看我的」、行内 owner 名都消失了，**但行首徽仍带名字**。查源码发现上一轮那处创建徽的编辑**没落进文件**（`task-row.ts:217-223` 仍是旧的一行式），生产物里自然也没有 —— 已重改，并 grep 产物确认含 `solo ? '[{age}]' : '[@…]'` 分支。
- `board-home.ts`：执行人 `Select` 条件渲染；`TrendChart` 传 `me: solo ? null : …`（组件在 `me === null` 时本就不画「只看我的」）；`TaskRowView` 加 `solo` 入参。
- `task-row.ts`：创建徽单人只留 `[创建于 {age}]`；第二行 `whoNode` 归 null；`detailTip` 的 `{who}` 传空串并去掉留下的前导换行。
- 验证：`packages/plugin` 下 `npm run verify`（build + typecheck）通过；`progress owners --json` 五个台账（plugin-core / session-title-pattern / task-dispatch-table / task-ledger / rulemux）各 count=1。
- 文档：`docs/design/features/board-home.md` §二 筛选行新增「单人台账」段，趋势图「只看我的」条目补一条。

## 结论
