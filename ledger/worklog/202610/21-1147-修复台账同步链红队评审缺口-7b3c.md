## 结论

同步语义已实测并两处修口（2026-10-21 下午）：

- `--no-sync` 原先只挂在主 parser，`new --no-sync` 直接 usage 报错（退出码 2，命令不执行）；现每个子命令也认，前后位置均可（`build_parser` 末尾 `sub.choices` 循环，`default=SUPPRESS` 防止子命令默认值覆盖主 parser 已解析的 True）。
- `git_sync` 的 ignore 判定改 `check-ignore --no-index`：忽略规则对已跟踪文件同样生效，默认形态只报未跟踪文件，漏判后 `git add` 撞「paths are ignored」并打出「请手动提交 ledger/」的瞎提示（照做也提交不了）。改后该情形与「一开始就 ignore」一样静默跳过。
- 实测 8 条同步路径（无 git / 无上游 / 两种 `--no-sync` / 环境变量 / 前置 ignore / 后置 ignore / 推送被拒自动 rebase / 自有提交不 rebase / 重试仍被拒）+ 2 条回归，全部符合 `packages/skill/README.md:124-129` 的承诺。
- 第二轮回检 11 项全过、**未发现新缺口**：两种位置的参数解析、12 个子命令 `--help`、部分忽略（只忽略 worklog/ 时 progress.json 照常提交）、`.git/info/exclude` 忽略、detached HEAD（本地提交不推送）、本地分支名 ≠ 上游名、持锁时 `--no-sync` 与只读不排队 / 普通写等满 60 秒报错、远端不可达（两处提示 + rc=0）、autostash 正常放回、autostash 放回冲突（改动留 stash、工作树带冲突标记、无 rebase 中间态）、pre-commit 拒提交后 `--no-verify` 兜底、台账在子目录（`proj/ledger`）。
- 两个待用户拍板的行为点（均非本次引入）：① 写前 `merge --ff-only` 会把整个仓库（含业务代码）快进到远端，等同替用户执行了一次 `git pull --ff-only`；② autostash 放回冲突时工作树会留冲突标记，需用户手动解冲突后 `git stash drop`。
- **第二轮抓到的真 bug（已修）**：`_rebase_retry` 用 `"Applying autostash resulted in conflicts"` 判「改动放回冲突」，而 git 2.27+ 的措辞是 `Your local changes are stashed, however applying them resulted in conflicts` —— 字符串永不命中，于是**冲突被误报成「rebase 后已放回」**（工作树实际带着 `<<<<<<<` 标记、stash 未消费）。改为看 rebase 成功后的 index 未合并项（`git diff --diff-filter=U`），冲突时点名文件并说明别当成品提交。实测：冲突 → 点名 `code.txt`；无冲突 → 仍说已放回。
- **第三轮抓到 2 个真 bug（已修）**：① `_run_once` 的 `BrokenPipeError` 分支直接 `return 0`，跳过了 `git_sync` —— 输出被 `| head` 截断时台账写成功却**没提交**，下一笔写被 guard 拦成「本地台账有未提交改动」，用户只能手动提交或 `--no-sync`（实测 commits 2→2、工作树脏）。修法：该分支照常 `git_sync`（stdout 先接 /dev/null）。② `git_sync` 的「会一并推走你自己的提交」提示只在 `foreign > 0` 时打，`_foreign_commits` 数不出来时返回 -1（fail-closed 的反面）→ 用户提交被静默带走；补 `foreign < 0` 的提示。实测：截断后 2→3 笔、工作树干净、后续写入不再被拦；unborn HEAD / 无 git 身份 / 上游是本地分支 三个边界均符合预期。
- **一条未处理的 B 类风险（待用户定）**：插件 `WRITE_TIMEOUT_MS = 120s`，而脚本最坏链路是 fetch30 + ff30 + push30 + rebase30 + push30 + push30 + fetch30 + rebase30 + push30（每次 git 调用独立 30s 超时），理论上限约 270s。极端网络挂起时界面会先报超时，而台账其实已写入 → 用户重试即二次写入（`new` 会建出重复任务）。建议提到 180s（可见代价：真挂死时 UI 多等 60 秒），属 B 类，未动代码。
- **第四轮（专家团三路并行 + 设计级审查）修掉 8 处**：① `_presync_guard` 的领先计数/脏检查/未入库检查在 git 返回失败时 `None → 空` 被当成「干净」放行（fail-open），与 `_foreign_commits` 的 -1 fail-closed 相反 —— 改为失败即 `Fail`；② `git_sync` 上游是本地分支时 `_push` 把分支名当 remote 用（`git push main HEAD`），补与 presync 一致的守卫；③ `_rebase_retry` 的 rebase 超时（30s）会逃出所有 except、留下 rebase 中间态，改 60s 且超时就地 `--abort` 并点名 stash；④ `--abort` 会把 autostash 重新 apply，这一步也可能冲突，abort 后检查未合并项与 stash 并点名文件；⑤ 提交失败不清 index，用户下一次裸 commit 会卷进台账文件 → 失败时 `git reset -- <paths>` 并在提示里说明；⑥ 台账被 `.gitignore` 全排除时改为提示一次原因（原为静默，后续写被 gate 报成「有未提交改动」）；⑦ 锁目录从 `--absolute-git-dir` 改 `--git-common-dir`，链接工作树共用一把锁；⑧ 口径修正：历史层「升级为 8 列」两处文案改 9 列、逾期天数注释 7→14 天、skill README 补 9 列说明与 ignore 提示说明。插件写超时按用户拍板提到 180s。
- 第四轮验证：8 项用例全过（非法 id 拒绝且未越界、标题/note 换行不污染、坏 JSON 给可读错误、同任务双改 rebase 冲突干净 abort、链接工作树提交推送、含空格路径、本仓 validate）；`npm run verify` 30 项；`koc-codelint` 六层。
