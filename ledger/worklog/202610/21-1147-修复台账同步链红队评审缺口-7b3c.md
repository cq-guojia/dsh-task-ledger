## 待办

### A 类：判定无副作用即直接修

1. **A1 提交吞掉别人的暂存区**：`git_sync` 把 `chore(ledger)` 提交到**整个 index**（`progress.py:437` 只 add 精确文件，但 `:445` 的 `diff --cached --quiet` 与 `:450` 的 `commit` 都是全 index 级）。用户/IDE 已 `git add` 的业务文件会被塞进台账提交并推送。
   修法：`git commit --only -m msg -- <本次台账文件>`，判定同样带 pathspec。
2. **A2 回滚失败却报成功**：`_rebase_retry` 不看 `git rebase --abort` 的返回码（`:401`），`:403` 直接宣称「已回滚到 rebase 前」。abort 失败（锁文件/权限）时仓库卡在 rebase 中间态，`progress.json` 可能带冲突标记，后续读写全废。
   修法：查返回码；失败打印 `git status` 摘要与手动命令，成功才说已回滚。
3. **A3 预同步覆盖无回滚**：`:733` 覆盖写之后没有恢复路径，命令随后被业务校验 Fail 或 Ctrl-C（`:2672`）时，工作树留着远端内容，下次 guard②（`:594`）把它误报成「本地未提交改动」。
   修法：覆盖前备份原字节，`Fail`/`KeyboardInterrupt` 统一恢复；文案标明来源。
4. **A4 冲突现场可进入**：`git_presync`（`:660`）入口不检测 merge/rebase 中间态，presync 照跑、guard 失效、命令写进冲突文件。
   修法：入口查 `MERGE_HEAD` / `rebase-merge` / `rebase-apply`，命中直接 Fail。
5. **A5 补下的 worklog 会永久残留**：`:743` 的 `track=True` 只把文件挂进 `CHANGED_FILES`，主命令 Fail 时 `main` 不调 `git_sync`（`:2686`），文件永久未跟踪；guard③（`:601`）的 managed 又不含 worklog，无人兜。
   修法：区分「presync 补下的」与「本次写入目标」，失败路径也把前者提交掉。
6. **A6 原子写改文件属性**：`mkstemp` 建的临时文件是 0600，`os.replace`（`:279`）后文件权限从 644 变 600；`progress.json` 是符号链接时会被替换成普通文件。
   修法：写前继承原 mode（新建取 644）；目标是符号链接直接拒绝。
7. **A7 CI 漏掉最常发生的提交**：`.github/workflows/verify.yml:9-15` 的 `paths` 不含 `ledger/**`，而本仓日常提交恰恰只动 `ledger/`。
   修法：补 `ledger/**`。
8. **A8 smoke 有两处假阳性隐患**：`smoke.mjs:803` 硬编码 `origin/master`，fixture 却是 `git init -q`（`:722`，分支名随 `init.defaultBranch`）；`:197`/`:201`/`:207` 断言本仓真实台账（近 13 月 ≥3 条、owner `GuoJia-Agent`、category `建设`）。
   修法：前者改用 `origin/${branch}`；后者搬进合成 fixture。
9. **A9 文档自相矛盾**：`SKILL.md:118` 与 `references/troubleshooting.md:3` 说「不要用 git pull / rebase 解决」，`troubleshooting.md:23` 却教「`git pull --rebase` 再推」；`README.md:123` 漏掉「补下本地缺的 worklog」。
   修法：以实现为准统一 `troubleshooting.md:23`，README 补一句。
10. **A10 零散但确定的边界**：历史 .md 读编码不统一（`:1314`、`:1045`、`:1070`、`:1095` 用 `utf-8`，`:241`、`:1249` 用 `utf-8-sig`）；detached HEAD / 无 upstream（`:469`、`:691`）静默只写不提交；shallow clone 取不到 blob（`:638`）被当成「远端没这文件」；upstream 无 remote 前缀时 remote 名取错（`:694`）。
    修法：统一 `utf-8-sig`；三处静默补 stderr 并区分「不存在」与「取不到」。

### B 类：待用户拍板，本任务不实施

- **B1 并发锁粒度**：整段 `presync→写入→commit/push` 持仓级锁才能堵住「查完到覆盖之间被别人写」（`:589`→`:733` 的 TOCTOU，会静默丢改动）。代价：同 clone 写命令排队，前一个在 push 时后面的要等。推荐整段持锁 + 拿锁最多等 60s 后明确报错。
- **B2 推送被拒时工作树脏**：`:393` 的干净检查是仓库级，任何业务改动都会让自动 rebase 永不执行 → 台账提交堆积 → 下次写被 guard①（`:570`）锁死。推荐 `git rebase --autostash @{upstream}`；代价是会短暂动工作树，极小概率 pop 冲突留 autostash。
- **B3 插件 10s 超时**：`runner.ts:12` 默认 `10_000`，`ledger-write.service.ts:13` 未覆盖，而脚本内最坏 fetch30+push30+rebase30+push30。后果是界面报超时但台账已改，重试即二次写入。选项：超时提到 120s，或写命令走 `TASK_LEDGER_NO_SYNC=1`。
- **B4 离线写补偿**：离线连写后联网，第一笔写被 guard① 拦。可选做 pending 标记自动补推；推荐不做，文案写清「联网后先 git push」。
