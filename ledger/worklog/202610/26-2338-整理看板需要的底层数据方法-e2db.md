2026-10-27 实测 python 调用成本（本机 4 核，warm，`subprocess` 计时 12 次取均值）：

| 命令 | 平均 | 最小 |
|---|---|---|
| `python3 -c pass`（纯解释器） | 51.3ms | 48.3ms |
| `progress.py --help`（含 import 全量） | 151.4ms | 137.2ms |
| `list --json` | 154.4ms | 145.7ms |
| `history --json` | 158.1ms | 141.7ms |

- **数据量几乎不花时间**：`list` / `history` 与 `--help` 只差 3ms ⇒ 150ms 全是解释器（51ms）+ import（~100ms）；
- import 大头（`python3 -X importtime`，累计）：`ledgerkit.shell.cli` 118.5ms —— 其中 `actions.registry` 54.7ms、`site` + `sitecustomize` 36.5ms、`actions.atom` 11.9ms、`shell.gitops` 9.5ms、`dataclasses` 9.7ms；
- fan-out 墙钟（4 核，并行跑 N 个 `list`）：1 区 153.7ms、3 区 187.0ms、5 区 331.6ms、10 区 753.6ms ⇒ **超过核数即按批叠加**；
- 结论：首页慢的根因是「每请求起 N 个 python 进程」，**不是读文件慢**；`/board/trend` 与 `/filters` 各自再跑 list+history，重复放大这一点（缓存 TTL 1.5s 只挡瞬时）。
- 换语言（Go/Rust ≈ 5-10ms/次）能省 140ms/次，但要把 pool/分片/锁/git 同步/历史解析/validate/模板整套重写 ⇒ 不划算；先做「一个进程接多个 `--repo`」（B）+「砍 import」（C）。
