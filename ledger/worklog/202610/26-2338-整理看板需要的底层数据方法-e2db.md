### 决议（2026-10-27）：worklog 头部加状态行，`show` 改为只读详细

**格式**（放在「创建」行正下方，同一引用块内）：

```
> **状态**：doing · @GuoJia-Agent（8d557c6d-7c93-43ac-8c73-5d623e82e1c6） · 更新 2026-10-27 08:28:22
```

取值只有三种：`open` / `doing` / `closed`。uuid 与名字都写（uuid 权威、名字给人看）。

**状态词统一英文（2026-10-27 定）**：实测全链路本来就是英文——分片存储、`--status` 入参、`--json` 输出、人话表格（`shell/render.py:82` 直接打 `{row.status}`）、连执行记录的 note 都是 `认领 → doing`（`actions/claim.py:75`）。唯一的中文在**插件界面文案表**（`client/locales.ts:204` `statusActive: "进行中"`），那是 UI 翻译层、不是数据。所以 worklog 状态行也写英文：**零映射、与既有文档一致**；中文只在界面翻译。

**谁改它**（都在原本就要写盘的那一次里顺手替换，零额外 IO）：

| 动作 | 状态行变成 |
|---|---|
| `new` | 待认领（带 `--self` 时「进行中」） |
| `claim` | 进行中 · 认领人 |
| `set --release` | 待认领 |
| `set --owner`（交接） | 进行中 · 新负责人 |
| `log` | 状态不变，只刷「更新」时间 |
| `close` | 已结案 · 结案人 · 结案时间 |

**代码落点**：

1. `assets/worklog.md` 模板：创建行下加一行 `> **状态**：待认领 · 更新 <created>`；
2. `core/worklog_md.py`：加 `STATUS_RE` + `rewrite_status_line()`——照 `rewrite_label_line:194` 的「有就就地替换、没有就插到创建行后」，`_insert_after_head:149` 已现成；
3. 六个写动作各调一次：`actions/new_task.py`、`claim.py`、`set_task.py`（含 release / handoff）、`log_progress.py`、`close_task.py`；
4. `actions/show_task.py`：**只读详细**——按任务号 `WorklogStore.find(tid)` 读文档 + 解析状态行，**砍掉 `load_task` 的反向找索引**；
5. `actions/validate.py`（`core/worklog_md.py:format_problems`）：加一条「文档状态行 vs 分片状态不一致」。

**权威与兼容**：分片 / 池是权威，文档状态行是镜像；**老文档不回填**（用户之后统一批量处理），`show` 读不到状态行时回退读分片，并在返回里标明「旧格式」。

**批量仍读分片**：`list` / `history` 不扫文档——文档只是「单条的完整快照」。

### 实现步骤方案（6 步，2026-10-27 定稿，等指令再动手）

**第 1 步 · 状态行的读写原语**（`core/worklog_md.py`，纯函数、无依赖，先把这层做对）

- `STATUS_RE`：认 `> **状态**：<status> · @<name>（<uuid>）· 更新 <when>`；
- `render_status_line(status, name, uuid, when) -> str`；
- `rewrite_status_line(text, ...) -> str`：有就就地替换、没有就插到「创建」行后（照 `rewrite_label_line:194`，`_insert_after_head:149` 现成）；
- `read_status(text) -> (status, uuid) | None`；
- `format_problems` 加一条：**状态行存在但值不在 `open/doing/closed`** 时报错；**缺状态行不报错**（老文档合法）。

*验证*：几个断言（写入 → 读回 → 替换 → 再读回；缺行时插入位置正确）。

**第 2 步 · 把状态行挂到写盘入口**（`store/worklog_store.py`，零额外 IO 的关键）

- `append_exec(path, line, *, status=None)`：加**一个可选参数**，内部在 `append_exec_log` 之后紧接 `rewrite_status_line`，**同一次读改写落盘**——这是「不多写一次文件」的全部秘密；

*验证*：`new` → 文档头部有状态行；`claim`/`release`/`log`/`close` 后那行随之变化，且执行记录与状态行在同一次写里更新。

**文档缺失的处理（2026-10-27 用户确认）**：**跳过 + 明说**，不报错拦下、也不自动补建空文档。
- 认领 / 释放 / 交接 / 记进展时文档没了 ⇒ 照常改分片，返回里带一句「过程文档没找到，跳过记录」（`claim.py:71`、`log_progress.py:40` 现状即如此）；
- 结案时文档没了 ⇒ 照常结案，历史行文档链接留空；
- `show` 时文档没了 ⇒ 明确说「这条没有过程文档」，不显示成空白。

理由：分片是权威、文档是附件——为一份附件拦下认领等于让台账不可用；但静默跳过会让人误以为写了记录，所以必须有一句提示。不自动补建的理由：会给老任务凭空造出一堆只有头部的空文档，掩盖「文档确实丢了」的事实。

由此推出：`validate` **只报「有状态行但不一致」（文档说 `doing`、分片说 `open`），缺状态行不报**（老文档合法）。

**明确不动**：老文档不回填（用户后续统一批量处理）；`list --search` 先不做；插件侧代码（要整体重构，不在此任务）。
