切到「日」图表显示格式跟现在一模一样。要求全程无人值守、一次做完再汇报。

## Process

- **两档数据一起下发，不新增端点**（`packages/plugin/src/host/services/stats.service.ts::getBoardHome`）：
  首页趋势图原本就有一个「一次拿两套数 ⇒ 零请求」的先例（`--by-owner` 供「只看我的」），照同一条取舍走：
  `/board/snapshot` 多带一份 `trendDay`。比新增 `/board/trend` 端点少一整套 api 函数 + 页面侧的
  fetch / error / 缓存清空状态；代价是快照多一次脚本调用（冷缓存时约翻倍）。
- **取数先周后日**（不是 `Promise.all` 并行）：两段窗口（26 周 vs 182 天）覆盖的是**同一批月份**，
  并行跑等于把同一批历史文件读两遍；串行则周档顺手把 skill 的月度缓存写下去，日档再读就是命中。
  ⚠️ 写成 `Promise.all([...(async () => await A())(), (async () => await B())()])` **不串行** ——
  两个 IIFE 同步启动，必须放在一个分支里 `await` 两次。
- **skill 侧零改动**：`stats --trend day --last 182d --by-owner` 本来就支持（`actions/trend.go`；
  day 粒度上限 `TrendMaxDayBuckets = 365`，182 在线内）。实测本仓台账：182 桶、coverage 与周档一致、
  结案合计 日档 49 / 周档 49 ⇒ 两档口径对得上。
- **画法一处没动**：`trend-chart.ts` 里只把「一格 7 天」抽成 `span`（日 1 / 周 7）、翻页步长抽成
  `STEP`（日 10 / 周 4，与历史页同口径）。柱宽 / 组内间距 / 组间距 / 配色 / 图例 / 浮卡结构 / y 轴五档
  全部原样 —— 这是「切到日档显示格式要跟现在一模一样」的字面要求。
  一处例外：浮卡首行日档只写当天日期（`periodOf`），写成 `2026-10-31 ~ 2026-10-31` 是废话；
  历史页 `titleOf` 也是这么分的。
- **列 key 补上粒度**（`${gran}:${shift}:${from}`）：不带粒度时，切档前后若 `shift` 同为 0 会有大半列 key 相同，
  React 复用 DOM ⇒ 柱子的入场动画不重放（历史页 `history-chart.ts` 已踩过并这么修）。
- **`FALLBACK_SLOTS` 不能按粒度给**：它是「宽度还没量到时先按几格排」的兜底，组宽与粒度无关
  （日 / 周一样宽 33.5px）⇒ 两档共用 13。一度写成 `{ day: 30, week: 13 }`，日档首帧会排出 1005px 溢出一屏。
- **右上角控件不与图例抢位**：`.dtl-trend__nav` 是绝对定位飘在图例那排上方的，加 Segmented 后宽约 156px，
  不给 `.dtl-trend__legend` 留 `padding-right` 就会跟「只看我的」叠在一起（图例本身 `flex-wrap`，
  留了内边距最多换成两行，不会压字）。
