## 过程

### 2026-10-17 动码：client 半从零搭起（工程化 → 样式 → 文案 → 取数 → 页面 → 入口）

- **工程化**（`packages/plugin/`）：`tsconfig.client.json`（target ES2022 + DOM + `allowImportingTsExtensions`）、
  `tsdown.client.config.ts`（产物 = CJS 闭包工厂 `window.__ModuleLoader__.load({id,factory})`，平台模块保留 `require()`）、
  `package.json` 加 `./client` 出口 + `dsh.client.inject`（locale / ui-renderer / ui-layout）+ `build:host` / `build:client` 两条；
  devDeps 加 `tsdown` + `@types/react`（react 由宿主模块表提供，不进依赖）。
- **宿主接口先核实再动手**（DSH 插件规则二）：`npm pack` 拉 `dsh-client-ui-layout@0.2.0-rc.2` 与
  `-primitives@0.2.0-rc.2`，逐条确认 `shell.overlay` 是 list/root 槽（无 owner props）、
  注册项元信息只有 `key`（keyed）/ `id` + `order` + `label`（list）/ `locale`（合成 `t` 席位），
  并确认 `Button` / `StateDot` / `SegmentedControl` / `MarkdownText` 在 rc.2 的真实签名后照抄落地，
  没有凭方法名猜。
- **踩坑 1（类型）**：自绘元件返回 `unknown` 通不过 React 的 `h()`（`FC` 要求 `ReactNode`）⇒ 统一改 `ReactNode`；
  原生 `select` / `input` 的 `onChange` 必须写 `ChangeEvent<HTMLSelectElement>`，写 `{target:{value}}` 结构字面量过不了类型检查。
- **踩坑 2（冒烟直测）**：Node 原生剥类型**不认无扩展名的相对导入**（`./format` 找不到）⇒ client 侧相对导入一律带 `.ts` 扩展名
  （`allowImportingTsExtensions` 已开，tsdown 与 Node 都认）；并把纯筛选逻辑从 `store.ts` 拆到 `rows.ts`
  （它不引 `api.ts`，冒烟才能直测档位 / 时间窗 / 标签 / 关键字四组过滤）。
- **踩坑 3（旧的失败断言）**：冒烟里「本仓在办应 ≥6 条」被日常结案打穿（实际 5）⇒ 改成「≥1 + 结构断言」——
  条数是数据不是契约，卡死数字会让冒烟随台账内容随机红。
- **后端加法**：前端要按 owner 判「我的待办」，而 git 身份只有 host 取得到 ⇒ `BoardSnapshot` 增 `identities`
  （工作区 id → `git config user.name`，取不到 null），前端 `rows.ts::isMine` 按它筛（与 host 统计同口径）。
- **验证**：`tsc --noEmit`（host + client 各一次）过；`npm run build` 出 `dist/client.js`（48KB，只 require `react` 与
  `@deepseek-ai/dsh-client-ui-primitives`）；`npm run smoke` **15/15**，新增三条断言（产物契约 / 中英键对齐 / 筛选逻辑）。
