## Background

## Process

- 排序与切组全在 `rows.ts`：`selectView` 排序键 = 工作区注册序 → `rankOf` → 时间倒序；`groupRows` 只把连续同区的行切段（纯函数，不重排）。
- 组顺序取 `board.workspaces` 的宿主注册顺序（`rows.ts` 的 `wsOrder`），不按任务数/最近活动 —— 任务增减不导致整页跳动。
- 组头 = 核心 `SectionHead`（`dsh-plugin-core/ui`，props `icon/title/right`），经 `ui.ts` re-export。
- 组头第二轮（用户 2026-10-30）：图标（`IconFolderCloseRegular`）不好看 ⇒ `icon` 槽改一条 3×14 的竖线（`.dtl-group__rule`）。
- 组头第三轮（用户 2026-10-30）：单个「N 条」改成分档计数「待认领 1 · 进行中 1 · 积压 · 逾期 · 停滞」，` · ` 分隔；**0 的档 JS 直接不渲染**（不显示 0、也不显示 —），全 0 时整段不出现；**不列「我的待办」**。口径与左侧六档菜单同一个 `tabHit`，数字与列出来的行对得上（`rows.ts` 的 `GroupCounts`）。
- 组头第四轮（用户 2026-10-30）：竖线补圆角（`--dtl-radius-xs`，与任务行左缘色条同款）；组头整条（竖线 + 工作区名 + 计数）右移 4px —— 外层 `.dtl-group__head` 的 `padding-left:var(--dtl-space-1)`，只包组头，任务卡不动。
- 组间距只加 `.dtl-group + .dtl-group{margin-top:var(--dtl-space-4)}`（`ui.ts` 的 UI_BASE_CSS），组头自带 12px 下边距。
- 任务行内容一行未改（工作区 Chip 仍留在行内，用户本轮要求先不动）。
- `LIST_LIMIT` 仍按整体 100 条截断后再分组 ⇒ 超限时靠后的工作区可能整组不出现。
- 页脚留白（用户 2026-10-30：滚到最底最后一条贴着浏览器底边）：底部留白从滚动容器的 `padding-bottom` 移到**内容末尾的实体块** `.dtl-page-foot`（`board-home.ts` 的 pageStyle 改为 `padding:"24px 22px 0"`）。滚动容器未必是我们这一层（宿主 main 槽也可能是滚动者），挂在这层的 padding-bottom 会落空；实体块跟着内容走，谁滚动都在。
- 行内改造（用户 2026-10-30 第四轮，原来「先不动每一条」的解禁）：① 执行人名从第二行最左挪到右侧，占**原工作区徽标那一格**、走核心 `Button` link 档（品牌蓝、无标签皮，点了仍按这个人筛）；工作区 Chip 从行内删掉（组头已写着）。② 状态标签从标题行挪到第二行、且**恒为第一位**：`statusTags` = 状态本身（待认领 / 进行中）+ 异常标记（积压 / 逾期 / 停滞）再接 `#标签`；以前只在标题行摆异常标记、状态本身反而没露。
- 趋势图（用户 2026-10-30 第四轮）：未结柱拆两段 —— 底琥珀 = 待认领、顶绿 = 进行中（`--dtl-chart-doing` 新增，取 `--dtl-success`；`split` 由 `owners` 各人未结算出，"只看我的"时整根都算进行中）。图例由四个色块改成三枚：已结案（取消红在上 / 完成蓝在下）、未结（进行中在上 / 待认领在下）、新增曲线；上下两段用 `.dtl-trend__dot--split`（8×8 flex 竖排，两片等分）。
- 浮卡跟着合并（用户：总数一行、下面拆开）：已结案 → 注脚「完成 X · 取消 Y」；未结 → 注脚「进行中 X · 待认领 Y」（只看我的不出注脚）。原来是一条 完成、一条 取消、一条 未结。

## Conclusion

在办列表已按工作区分组（组头 = 细竖线 + 工作区名 + 分档计数，0 的档不列、不显示「我的待办」；组内「我在做 → 别人在做 → 积压待认领 → 其余待认领」，同档时间倒序；组间按工作区注册顺序）；行内改为「状态标签打头 + 异常标记 + #标签」，执行人名（蓝字）挪到右侧原工作区徽标的位置，工作区不再在行内重复。首页趋势图未结柱拆成「待认领 / 进行中」两段、已结案与未结的图例改为上下两段的方块，浮卡给总数 + 拆分注脚。typecheck + build 通过，dist 已重建；交付前 koc-codelint 全过。
