## 背景

**触发**：用户嫌每次命令都要等，原话「一个命令可能会调 N 个脚本去执行……多来几个命令，等待打开的时间可能直接就一两秒」。要求换成编译好的二进制，拷进 skill 直接调用，且用户本机不得有任何安装成本。前序讨论见 `ledger/worklog/202610/27-0554-讨论-task-ledger-skill-是否改用-go-重写-ebdb.md`。

**现状**：skill 每条命令都起一个新 Python 进程（`python3 scripts/progress.py <sub> --repo <根>`，见 `packages/skill/scripts/progress.py:15-20`），进程启动与模块导入的成本按次付。

**实测（本机 4 核 Linux 容器、Python 3.13.5、20 次均摊）**：

| 环节 | 单次 |
|---|---|
| 裸解释器 `python3 -c pass` | 59 ms |
| 加导入全部模块 | 171 ms |
| 加真实干活 `list` | 178 ms（业务本身约 7 ms） |

即 **96% 的时间在启动与导入**，代码优化救不了。15 个并发同时起（看板一次刷新会到这个量级）实测 1.18s wall / 2.87s CPU。

**看板一次刷新的 spawn 次数**：snapshot 每工作区 2 次（`packages/plugin/src/host/services/home.service.ts:34-37`）+ trend 每工作区 3 次（`trend.service.ts:42-46`），两段串行（`packages/client/store.ts:105-140`）。

## 过程

**Go 产物的四项实测（不是推断）**：

| 检查 | 结果 |
|---|---|
| darwin/arm64 体积 | 2737 KB（`-trimpath -ldflags="-s -w"`，带 json/regexp/exec 的标准库 CLI） |
| darwin/arm64 签名 | 解析 Mach-O load command：`LC_CODE_SIGNATURE(0x1d)` 存在、`LC_UUID(0x1b)` 存在 —— Go 内部链接器自动 ad-hoc 签名 |
| M 芯片实跑 | 用户 Mac 上执行，输出 `binary ok: {"arch":"arm64","os":"darwin"} (startup=536µs)` |
| linux/amd64 | `ldd` → `not a dynamic executable`（连 libc 都不依赖） |
| windows/amd64 | 2967 KB；`objdump -p` 导入表**只有 `kernel32.dll`**（无 vcruntime140/ucrtbase/msvcrt）；`MajorOSystemVersion 10.0` ⇒ Win10+ |

**权威依据**（均为 go.dev 官方域名）：

- `go.dev/doc/faq`：「The linker in the gc toolchain creates statically-linked binaries by default. All Go binaries therefore include the Go runtime…」
- `go.dev/doc/install/source#environment`：`windows/amd64`、`darwin/arm64`、`linux/arm64` 均在官方有效组合内；「In effect, you are always cross-compiling.」
- `go.dev/wiki/WindowsCrossCompiling`：「cross-compiling of pure Go executables has become very easy」；「cgo is disabled when cross-compiling … you need to have a C cross-compiler（仅用 cgo 时）」。

**skill 带二进制是否有先例**：官方 spec（`agentskills.io/skill-creation/using-scripts`）通篇只讲源码脚本 + 内联依赖，**未提二进制，属文档空白（非禁止）**；生态里已有成熟范式：`contentful/skills` 的 skill-authoring 明文「Scripts can be anything executable: bash, Python, **compiled binaries**…只要求 `chmod +x`」，并定义 `scripts/` 放薄包装、`bin/` 放编译产物；另有 `AsperAdAstra/stock-tracker-skill`（`bin/` 直接入库）、`scagogogo/osv-schema-skills`（Go CLI + skill bundle）等实例。

**踩坑**：`write_to_file` 首次写临时 `main.go` 落成 0 字节（工具报成功、文件为空），重写后正常 —— 以后写文件后要 `wc -c` 复核再编译。

**与本任务无关但同轮确认的事**：本地 `file://` 打开 HTML 无法直接调二进制，换任何语言都一样 —— 浏览器没有启动本机程序的 API，且 `file://` 下 `fetch` 被 CORS 拦（origin 为 `null`）；要本地 HTML 拿到台账数据只有「起本地 HTTP 服务」或「浏览器扩展」两条路。
