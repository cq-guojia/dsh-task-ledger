证据（全部读源码得出，未跑真机）：

- 翻过的页永远留在 DOM：`history-list.ts:279-283`（`visible = 所有页 flat()`，只增不减）。
- 核心 `Table` 逐行渲染、没有虚拟化：`dsh-plugin-core/dist/ui/table-shared.js:104-144`。
- 每次 render 重建全部行元素（点行、开预览都会触发）：`history-list.ts:405-451`。
- 打开预览会改主区宽度、触发整表换行与行高重排：`board-home.ts:244-247` → core `openFilePreview`。
- host 取的是近一年，前端才按月过滤：`history.service.ts:202-204` + `history-list.ts:274-277`；上限在 `history.service.ts:190-192`。
- skill 每次调用都解析整个月文件、在解析**之后**才按 limit 早停：`packages/skill/src/internal/actions/query_history.go:161-175` ⇒ 不能靠「游标小页翻」解决（120 页 = 120 次解析）。
- 6 万行按每行 8~14 个节点推算 ≈ 60~80 万 DOM 节点。

外观 1:1 的做法：**不**换成「div 列表 + 吸顶表头」，而是保留一张 `<table>`，首尾各一个空行占位撑住滚动高度，只渲染窗口内行；每天仍画一行日期头（`SectionHead`），列宽仍 `minmax(0,1fr)/175/140/185` 交给 table 布局算。吸顶日期头本次不做；将来要做也不是「粘住第一行」（屏幕外的行根本没画），而是在顶部单独画一条「当前滚到哪天」的日期条。

落码记录（2026-11-01）：

- `host/routes.ts` `/history/list` 读 `ym`；`host/services/history.service.ts` 新增 `monthRange()`，`getHistoryList` 按月取、`capped` 恒 false；`host/repositories/history.repository.ts` 的 `limit` 改成可选（不传 = 整月全量）。
- `client/api.ts` `fetchHistoryList` 必带 `ym`。
- `client/history-list.ts` 重写渲染半边：`buildItems()` 拍平成 day / ws / rec 三种行，`offsetsOf()` 算行起点表，`rowAt()` 二分查窗口；滚动监听挂在 `.dtl-page`（`board-home.ts` 的 `scrollRef` 经 `scrollContainer` 传进来），rAF 合并、ResizeObserver 兜住 dock 挤压。
- `client/ui.ts` 历史页表格样式自绘（`.dtl-histlist__table / __cell / __headcell / __row / __dayrow / __spacer`）；`client/tokens.ts` 新增 `--dtl-border-faint` / `--dtl-table-head-bg` / `--dtl-table-row-hover`（alias 核心 token）。
- 核对：`progress history --json --since "2026-10-01 00:00:00" --until "2026-10-31 23:59:59"`（不传 `--limit`）能正常回整月 50 条 ⇒ host 现在下发的时间参数形状可用。
- `npm run verify`（build + 两侧 typecheck）通过；`koc-codelint` 六层全过。

顺手修的真机 bug（用户 2026-11-01）：点图表里某天，列表滚过去；切到「在办」再切回来，又滚一次。原因是列表切走会卸载、组件内 `lastScrollToken` ref 归零，而页面层 `histScroll` 还留着旧 token ⇒ effect 再触发一次。改法：token 由 `board-home.ts` 的递增器发号，列表滚完回调 `onScrolled` 让页面层把 `scrollTo` 清空（`board-home.ts:222-233`、`history-list.ts:330-337`、`357-362`）。

## Conclusion

2026-11-01 已落码（未提交，等用户看效果）：

- **取数按月**：`/history/list` 加 `ym`，`getHistoryList` 只读该月（`--since 月初 --until 月末`，不传 `--limit`），删掉一年窗口与 5000 条封顶；前端删掉按月过滤，改按 `ym` 请求 + 60 秒本地缓存。
- **渲染窗口化**：一天一张表 → **一张表 + 每天一行日期头**，只渲染窗口内的行；屏幕外用首尾两个等高占位行撑住滚动高度。分页 / 按天切片 / 滚动加载全部删除。
- **外观自绘**：表格结构与皮肤落在 `ui.ts`（`--dtl-*` 消费，表头底与行悬浮底在 `tokens.ts` 里 alias 核心 token），逐条对齐原核心 Table plain 皮肤：四边外框、灰底表头 + 下边线、行间极淡底线、行悬浮、选中淡蓝底 + 左竖条。
- **行高定死**：首帧先按自然高度画前 40 行量出三类行高（日期头 / 工作区段头 / 记录），之后每行钉死，无标签的行等高占位。
- 滚到某天改成按行号算位置（不再查 DOM、不再扩页）。

未做：吸顶日期头（用户 2026-11-01 明确先不做）。

**真机第一轮反馈修的问题**（用户 2026-11-01）：点图表某天，滚过去后目标日上方还露出一截。根因是定位基准取错 —— `base` 用的是包住「筛选条 + 表格」的外层 `.dtl-histlist` 的顶边，而行号偏移是从**表格**顶边算的，中间差了筛选条那一截（控件行 + 12px margin）。改法：`tableRef` 挂到 `<table>` 上，`recompute()` 与「滚到某天」都用表格的 rect 算基准。同一处偏差也影响虚拟窗口的起点（被 overscan 盖住了，所以只是跳转看着不准）。
