## 结论

三个标记全部改为时间实时判定，`progress.json` 里不存任何标记字段：

| 标记 | 条件 | 起算 | 阈值 | host 字段 |
|---|---|---|---|---|
| 积压 | `open` | `created` | 30 天 | `backlog` / `BACKLOG_DAYS` |
| 超期 | `doing` | `started`（中途更新不影响） | 14 天 | `overdue` / `OVERDUE_DAYS` |
| 停滞 | `doing` | `updated` | 3 天 | `stale` / `STALE_DAYS` |

- 行标签优先级：停滞 > 超期 > 积压 > 待认领 > 进行中。
- 实心色阶梯：灰（待认领）→ 黄（积压）→ 橙（超期，新增 token `--dtl-overdue`，宿主无橙色 ⇒ warn+error 现算）→ 红（停滞）。
- 统计卡保持一行 4 张：原「阻塞 · 停滞」合并卡改为「积压 · 超期 · 停滞」，主数字三者合计、小字三段拆开，**布局零变动**。
- 调试态：第二区第一条任务行摆出全部五枚标签（`DEBUG_TONES`），供用户一次看全配色；确认后删。
  **2026-10-19 用户要求先保留**，看完才删。
- 发布：plugin 0.0.57 / skill 1.2.3。

### 悬停解释（2026-10-19 第二轮）

- 五枚状态标签**一律**带悬停文案（`Tag` 新增 `tip` 属性：始终挂 title，不被 20ch 截断条件挡住）；文案书面化、全角标点。
- 待认领：创建于何时 + 尚未认领；积压：创建于何时 + 无人认领已满 N 天；进行中：谁 + 何时开始 + 最后更新；
  超期：进行中那条 + 任务已开始 N 天；停滞：进行中那条 + 已停滞 N 天。
- 天数不前端推算：host 新增下发 `idleDays`（updated 至今）与 `waitingDays`（created 至今，仅 open），
  加上原有 `ageDays`（started 至今），分别供停滞 / 积压 / 超期使用（`home.service.ts:33-45`）。
- 调试态那一行摆的不是本任务状态 ⇒ 悬停改给**阈值口径**（`statBacklogTitle` / `statOverdueTitle` / `statStaleTitle`），
  不拿本任务数据硬套。
- 发布：plugin 0.0.58。

### 提示换行（2026-10-19 第三轮）

- 用户确认就用 `h`（React `createElement`）透传的元素原生 `title` 属性，不另写自定义气泡；`Tag` 的 `tip` 属性最终落到 `title` 上。
- 文案按字段拆行：身份/开始时间一行、最后更新一行、天数（超期/停滞）再一行；原生 `title` 认 `\n` 即多行显示。
- 发布：plugin 0.0.59。

### 提示改用 data-tip 浮层（2026-10-19 第四轮）

- 用户指出按钮（继续/结束/释放）的提示是 **CSS `data-tip` 浮层**（`.dtl-minibtn::after`，鼠标一上去立刻出、可多行），
  我之前给状态标签用的是原生 `title`（慢半拍、换行难看）。改为与按钮同源：`.dtl-tag[data-tip]::after`（`white-space:pre-line` 认 `\n`）。
- `Tag` 不再叠原生 `title`，`tip` 走 `data-tip`；只挂了 `data-tip` 的标签才出浮层（截断的 #标签/执行人照旧）。
- 文案格式对齐按钮样例：`{who}` / `开始执行：{started}` / `最后更新：{updated}` / `任务已开始 {d}`，时间带秒、全角冒号。
- 发布：plugin 0.0.60。

### data-tip 不显示 bug 修复（2026-10-19 第五轮）

- 原因：`.dtl-tag` 上有 `overflow:hidden`（给文字做省略号），而 `::after` 浮层定位在标签**下方**，被父级 `overflow:hidden` 裁掉 ⇒ 完全不显示（按钮没这属性所以正常）。
- 修法：省略号裁切移到内层 `.dtl-tag__txt`，`.dtl-tag` 本体去掉 `overflow:hidden`（只留 `position:relative`）。`Tag` 渲染包一层 `dtl-tag__txt`。
- 发布：plugin 0.0.61。
