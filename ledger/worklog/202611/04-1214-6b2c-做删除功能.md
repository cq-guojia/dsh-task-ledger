## Background

用户 2026-11-04 提出（原话）：「历史记录里有很多确实是建错了的任务，或者是一些垃圾任务，我想把它清掉」。

最初摆了三个方向：

1. **直接硬删除**：把历史记录连同它的历史和文件一起删掉；
2. **单独做一个「删除」标记**：历史记录里带删除标记的，所有台账自动忽略、不读；
3. **把「删除」和「取消」算作同一个标记**：取消了就默认不读。

经多轮讨论收敛，否决理由（证据在 Process）：

- **方向 3 否决**：取消是业务事实，不是数据错误。`cancelled` 已被全站统计当真值消费，「结案 = 完成 + 取消」是 2026-10-29 定的口径；把 cancelled 从读侧剔掉会让未结数永久虚高。而且 `close --cancel` 只对在办任务生效，清不了已经在 history 里的垃圾。`SKILL.md:333` 也规定只有用户明确说「取消 / 作废」才触发。
- **方向 1 否决（作为日常功能）**：删 worklog 文档会解除任务号查重闸门，号可被复用、日后 `close` 误判 `already_done` 变僵尸；历史表「只追加、没有删除、不原地改行」是写死的数据契约。硬删只保留为「连 git 历史都不该留」时的一次性维护手段，且 worklog 文档一律不删。
- **方向 2 的独立清单方案作废**：用户澄清删除后所有记录都收敛到 history 一张表，不再需要第二处存储来记标记。

用户 2026-11-04 的两次关键澄清（本任务的定稿依据）：

1. 「不管是在历史里面删除，还是在未认领里面删除，还是从自己的片区里删除，都把它移到历史里面，然后变成删除」⇒ **删除是一类统一的结案动作**，无论任务原来在 `pool.json` / `owners/<hash>.json` / `history/<年月>.md`，最后都落到 history 里成为一行「已删除」。在办任务走 `close` 那条写序移进去，不是留在任务表里打标记。
2. 「你直接去改那个状态，那一个东西它不加列，那原来我成功的和我直接删除的，怎么区分？我这个东西执行完了，但是我把它删除了，和我直接删除了，怎么区分？」⇒ **不能把 `Result` 直接盖成 `deleted`**。「结果」（done / cancelled / 从未完成）与「是否删除」是两个正交维度，必须**增加一列**，`Result` 原值保留。

方案演进：独立清单 → 收敛到 history 一张表 → `Result` 盖成 `deleted` → **加一列（定稿）**。
