## Background

讨论中推翻了两个方案，都有代码依据：

1. **后端发广播**——不成立。`BroadcastChannel` 是浏览器 API，宿主进程没有；`dsh-plugin-core/src/runtime/notify.ts:171-182` 在无该全局时直接返回 `null`。

## Next

先定通用执行器的形状，再动代码。核心只需三类执行体 + 一个注册表：

- `shell`：`child_process.spawn(command, args, { cwd })`，stdout 逐行转进度，退出码即结果。node / python / bash / 任意二进制同属此类，不再细分（`exec` 不是另一类，只是同类的另一种底层实现，且缓冲输出、不适合长任务）。
- `executor:<name>`：使用方在 host 侧注册 Node 函数，前端只传短名 + 参数；核心按调用方插件补前缀（`dsh-task-ledger:tidy-files`），并校验「只能调自己注册的」。
- `agent`：起 DSH 会话（`workspace` + `prompt`），会话流式输出由核心转发。
- 前端永远只能传「名字 + 参数」；函数不能跨进程（`dsh-plugin-core/src/adv/tasks/pool.ts:83-102`：`run` 是函数，不进池、不过线）。
- **进度不做心跳**：执行器主动上报（`ctx.progress()` / stdout 行），宿主写进记录并由 SSE 推给页面。保活心跳属 SSE 层（`: ping` 注释行），使用方不实现，也不需要固定函数名。

## Process

- SSE 形态：`/follow` 是 `text/event-stream`，每个页面一条独立连接，宿主 `store.subscribe` 后逐条 `res.write`（`dsh-plugin-core/src/host/task-center.ts:136-162`）。
- 记录真源在内存 Map，不落盘；终态保留 10 分钟（`session-job.store.ts:29`），宿主重启即清空（`:156-161` 注释说明是刻意的）。
- Toast 由页面渲染，后台不参与：`dsh-plugin-core/src/ui/feedback/notify.ts:2-7`（纯投递，界面靠 `mountToasts()` 挂）。
- 广播型 Toast 不能带按钮：`dsh-plugin-core/src/ui/feedback/toast-queue.ts:68-79`（`actions?: never`，函数跨不了页）。
- 核心自带的广播接收端不按项目过滤——`notify-bridge.ts:49-58` 只取 title/level/detail，`message.project` 被丢掉，所以 `connectToasts()` 是全量收。
- 执行器注册表必须是宿主级单例（浏览器侧 `claimTaskNotifications` 用 `Symbol.for` 收口是同一手法），否则每个插件副本各一张表，跨插件调不到。
- 进度链路：执行器上报 → 记录 → SSE → 每个开着的页面各自渲染；页面关了就断，不做补投递（与终态通知同口径）。
- 前端不直连 agent 或脚本：会话归宿主持有，页面只是订阅者；现有 `session.service.ts:360-404` 已经是这个形状，缺的只是把 executor/shell 接进同一条记录链路。
- 任务列表按钮与 Toast 按钮**机制上没有区别**：都是 `id + 参数 → handlers[id](task)`。
  - 现状差异只是历史包袱：列表按钮多存了 `ServerTaskAction`（token/version + `/invoke`），而服务端只做校验并回 `detail`、不执行动作（`session-job.store.ts:319-330`）。
  - 页面本来就有完整记录（`status`、`detail`），可以自己按状态决定画哪些按钮，**后端不必存按钮**。
  - 结论：token/version/invoke 可删；统一为「后端存状态，页面画按钮」。

/* ───────── 0. client/nav.ts：按钮实现表（列表与 Toast 共用同一份） ───────── */
import type { TaskNotificationRecord } from "dsh-plugin-core/adv/tasks";

export const buttonHandlers: Record<string, (task: TaskNotificationRecord) => void> = {
	// 打开这条任务对应的会话
	"open-session": (task) => {
		const detail = task.detail as { sessionId?: string } | undefined;
		if (detail?.sessionId !== undefined) openSession(detail.sessionId);
	},
	// 打开这次执行的日志
	"open-log": (task) => {
		const detail = task.detail as { logPath?: string } | undefined;
		if (detail?.logPath !== undefined) void openFile(detail.logPath);
	},
	// 重跑一次（复用下面的 startCloseTask）
	"retry": (task) => {
		const detail = task.detail as { taskId?: string; workspace?: string } | undefined;
		if (detail?.taskId !== undefined && detail.workspace !== undefined) {
			void startCloseTask({ taskId: detail.taskId, workspace: detail.workspace });
		}
	},
};

/* ───────── 1. client/index.ts：入口挂载（整个插件一次） ───────── */
import { mountTaskToasts } from "dsh-plugin-core/ui/task-toast";
import { buttonHandlers } from "./nav";

export function apply(ctx: ClientContext): void {
	// ...原有 setDefaultTaskProject / setTaskBackend / connectHost ...

	mountTaskToasts({
		project: TASK_PROJECT,          // 只收本插件
		groups: [JOB_GROUP],            // 只收 session 分组
		onSettled: (task, outcome) => {
			if (outcome === "done") void refresh();   // 结束后刷新看板
		},

/* ───────── 2. client/close-task.ts：发起（每次点击） ───────── */
import { startTask } from "dsh-plugin-core/adv/tasks";

export function startCloseTask(input: {
	taskId: string;
	workspace: string;
	note?: string;
}) {
	return startTask({
		title: `结案 ${input.taskId}`,       // 会话名 + 列表显示名
		key: `close:${input.taskId}`,        // 业务键（判重）
		group: JOB_GROUP,
		kind: "executor:close-task",         // 调到 3 那个执行器
		args: input,                          // 纯数据，进记录
		notify: {
			toast: true,                       // 弹不弹
			success: { title: "任务已结案" },
			failure: { title: "结案未完成" },
			button: { id: "open-log", text: "看日志" },   // id 对应 handlers 的键
		},
	});
}

/* ───────── 3. host/executors/close-task.ts：执行器（Node 侧） ───────── */
registerExecutor("close-task", async (args, ctx) => {
	const { taskId, workspace, note } = args as {
		taskId: string;
		workspace: string;
		note?: string;
	};

	ctx.progress(1, 4, "读取台账");
	const task = await runSkill(workspace, ["show", "--id", taskId, "--json"]);

	ctx.progress(2, 4, "核对在办列表");
	const listing = await runSkill(workspace, ["list", "--json"]);
	if (!isOpen(listing, taskId)) throw new Error("任务已不在办");

	ctx.progress(3, 4, "写入结案记录");
	await runSkill(workspace, ["close", "--id", taskId, "--summary", note ?? "已完成"]);

	ctx.progress(4, 4, "提交台账");
	await gitCommitAndPush(workspace);

	return { taskId, workspace };   // 进 record.result；detail 里的 taskId/workspace 由核心合并

/* ───────── 4. 任意 UI 组件：列表 + 进度 + 按钮（可选） ───────── */
import { useTasks } from "dsh-plugin-core/adv/tasks";
import { buttonHandlers } from "./nav";

function TaskRows() {
	const { tasks } = useTasks({ project: TASK_PROJECT, groups: [JOB_GROUP] });

	return tasks.map((task) => {

## Conclusion

已定稿（十二条）：

1. 后台只存状态，**不发通知**；没有「后端发广播」这回事。
2. 页面订阅 SSE 长连接拿终态，**各自**渲染 Toast；开 3 个页面就各弹 1 条，不用抢、不用广播。
3. 调用时传 `notify` 配置（`toast` 开关、成功/失败文案、按钮 id），存进宿主记录。
4. 按钮是本页函数，**本页没注册就不画**；别的页面天然不受影响。
5. 刷新后的可点性 = 记录还在 + 初始化代码重跑（重新注册 handlers），不存「已展示」标记。
6. 使用方只写两处：`mountTaskToasts`（一次，监听 + handlers）、`startTask`（每次，传 notify）。
7. **进度不用心跳**：执行器主动上报，核心只转发；三类执行体的进度统一成「行/百分比 + 日志尾部」。
8. 前端只订阅核心，不直连 agent 或脚本；会话与进程都属于宿主，页面只是观众。
9. 报不报进度由执行器决定：不报也能跑完、也能通知，代价只是长任务看起来像卡住。
10. 广播降级为可选通道：主通知走 SSE；广播只服务跨 window / iframe / 非 SSE 消费者，且启用时必须解决 N×N 重复。
11. 消费端最终只写 2 处必选（入口挂载 + 发起调用），执行器注册或脚本二选一，UI 展示可选。
12. 列表按钮与 Toast 按钮**无机制区别**：都是 `id + 参数 → handlers[id](task)` 同一段程序。后端只存状态，不存按钮、不存 token；页面按 `task.status` 决定画哪些按钮。

执行侧未定：只有 agent 会话一种执行体，通用后台任务（shell / 自定义执行器）尚无实现。
