## 三处代码（以这版为准）

### 1. `client/task-ui.ts` —— 本页接线一次

```ts
/**
 * 本页接线一次，只干两件事：
 *   ① 注册「按钮 id → 本页怎么处理」—— 列表和 Toast 按钮都查这一份；
 *   ② 订阅终态：弹卡、跑 onSettled。
 * 不写这段：任务照样跑，但本页收不到终态、按钮点了没反应、结束也不刷新。
 */
import { mountTaskUI } from "dsh-plugin-core/ui/task-ui";
import type { TaskNotificationRecord } from "dsh-plugin-core/adv/tasks";
import { TASK_PROJECT, JOB_GROUP } from "./api";
import { openSession } from "./nav";
import { openLogPanel, refreshBoard } from "./board-home";
import { startCloseTask } from "./close-task";

/** detail 是松散 JSON：直接点属性编译不过；取不到/不是字符串就当没有，调用方什么都不做。 */
function field(task: TaskNotificationRecord, name: string): string | undefined {
	const detail = task.detail as Record<string, unknown> | undefined;
	const value = detail?.[name];
	return typeof value === "string" ? value : undefined;
}

/** 列表和 Toast 共用这一份；本页没注册的 id 两边都不画。 */
export const taskHandlers: Record<string, (task: TaskNotificationRecord) => void> = {
	"open-session": (task) => {
		const sessionId = field(task, "sessionId");
		if (sessionId !== undefined) openSession(sessionId);
	},

	"open-log": (task) => {
		const logPath = field(task, "logPath");
		if (logPath !== undefined) openLogPanel(logPath);
	},

	// 重跑：参数从记录取，不从闭包取 —— 记录可能是别的页面发起的
	"retry": (task) => {
		const taskId = field(task, "taskId");
		const workspace = field(task, "workspace");
		if (taskId === undefined || workspace === undefined) return;
		void startCloseTask({ taskId, workspace });
	},
};

export function mountLedgerTaskUi(): void {
	mountTaskUI({
		project: TASK_PROJECT,   // 写 null / 不写 = 收所有插件（跨项目）
		groups: [JOB_GROUP],
		handlers: taskHandlers,
		onSettled: (_task, _outcome) => {
			refreshBoard();       // 刷本插件自己的台账数据，不是刷核心任务列表
		},
	});
}
```

入口 `client/index.ts` 的 `apply()` 里加一行：`mountLedgerTaskUi();`

**`onSettled` 为什么要有**：核心刷自己的任务列表，不用我们管；结案改的是**我们的台账文件**，
核心不知道这个文件存在，所以看板数据得我们自己重读一遍。如果我们没有任何自己的数据要刷，
这个回调整块不写就行。

### 2. `client/close-task.ts` —— 每次发起

```ts
/**
 * 发起一次结案。干什么、弹什么卡、发什么通知、列表行给哪些按钮，全在这里配。
 * 全是纯数据跟着记录走，别的页面也按同一份配置渲染。
 */
import { startTask } from "dsh-plugin-core/adv/tasks";
import { TASK_PROJECT, JOB_GROUP } from "./api";

export interface CloseTaskInput {
	readonly taskId: string;
	readonly workspace: string;
	readonly note?: string;
}

export async function startCloseTask(input: CloseTaskInput): Promise<void> {
	await startTask({
		project: TASK_PROJECT,
		group: JOB_GROUP,
		title: `结案 ${input.taskId}`,
		key: `close:${input.taskId}`,      // 同一任务再点 = 就地更新
		kind: "executor:close-task",
		args: input,                       // 纯数据，函数过不了进程边界

		// ① Toast：弹什么卡。能跨页、跨项目，每态各配一个 scope。
		//    all    = 每个开着的页面都弹（含别的项目；按钮只在发起页显示，核心自己处理）
		//    origin = 只有发起页弹
		toast: {
			success: {
				title: "任务已结案",
				button: { id: "open-log", text: "看日志" },
				scope: "all",
			},
			failure: {
				title: "结案未完成",
				button: { id: "retry", text: "重跑" },
				scope: "origin",
			},
		},

		// ② 通知：发一条消息出去，与 Toast 分开配。范围和广播每态独立。
		//    scope     = 谁弹：all 所有页面 / origin 只有发起页
		//    broadcast = 走不走跨页通道：plugin 同项目 / global 跨插件 / 不写 = 不广播
		notify: {
			success: {
				message: "结案完成",
				detail: { taskId: input.taskId },
				scope: "all",
				broadcast: "plugin",
			},
			failure: {
				message: "结案失败，请重跑",
				detail: { taskId: input.taskId },
				scope: "origin",
				broadcast: "global",
			},
		},

		// ③ 列表行按钮：文案和 when 在这里配，画面由核心控件画
		rowButtons: [
			{ id: "open-session", text: "查看",   when: "running" },
			{ id: "open-log",     text: "看日志", when: "done" },
			{ id: "retry",        text: "重跑",   when: "done" },
			{ id: "open-log",     text: "看日志", when: "failed" },
			{ id: "retry",        text: "重跑",   when: "failed" },
		],
	});
}
```

## 参数能力清单（消费方视角）

只列「我们要用到什么、希望它支持什么」。具体怎么实现、叫什么名字由核心定。

| 参数 | 期望支持 |
|---|---|
| `startTask.project` / `group` | 任务归属；决定哪些页面收得到 |
| `startTask.title` / `key` | 列表标题；业务键（同键再发就地更新，不堆两条） |
| `startTask.kind` / `args` | 执行体名字 + 纯数据参数；参数不能带函数 |
| `toast.success` / `toast.failure` | 两态完全对称；不写 = 该态不弹卡 |
| `toast.<态>.title` | 卡片主行 |
| `toast.<态>.button` | 该态一个按钮：`{ id, text }`，id 对应 handlers；跨页/跨项目时只有发起页显示按钮，核心自己处理，消费方不配 |
| `toast.<态>.scope` | `'all'` 所有页面都弹（跨页/跨项目）/ `'origin'` 只有发起页弹；两态可不同 |
| `notify.success` / `notify.failure` | 两态完全对称；不写 = 该态不发通知 |
| `notify.<态>.message` / `detail` | 通知正文 + 附带的纯 JSON，接收端自己取 |
| `notify.<态>.scope` | 与 toast.scope 同语义，两态可不同 |
| `notify.<态>.broadcast` | `'plugin'` 只给同项目消费者 / `'global'` 跨插件 / 不写 = 不广播；两态可不同 |
| `rowButtons[]` | 列表行按钮声明（不是 Toast 按钮）：`{ id, text, when }`，跟着记录走 |
| `rowButtons[].when` | `'running'` / `'done'` / `'failed'` / `'always'`（缺省 always）；同一 id 可按状态重复声明 |
| `mountTaskUI.project` | 字符串 = 只收该项目；`null` / 省略 = 收所有项目（跨项目） |
| `mountTaskUI.groups` | 只收这些分组；省略 = 该项目下全收 |
| `mountTaskUI.handlers` | 按钮 id → 本页函数；列表与 Toast 共用；没注册的 id 不画 |
| `mountTaskUI.onSettled` | 终态回调，成功失败都调；只给消费方刷自己的数据，核心列表刷新不靠它 |
| `mountTaskList.project` / `groups` | 与 `mountTaskUI` 同一组过滤条件 |
| `mountTaskList.handlers` | 必须显式传（函数在页面内存里）；不传则按钮只显示、点了没反应 |
| `mountTaskList` 的画面 | 列表行、筛选、进度展示都由核心控件负责；消费方不传渲染配置、不自己画 |

## 需要核心给到的能力（不规定实现方式）

1. **Toast 跨页、跨项目**：`scope: 'all'` 时每个开着的页面都弹；`'origin'` 时只有发起页弹。
   跨项目时卡片照弹，但按钮只在发起页显示 —— 核心自己按 origin / handler 处理，消费方不配。
2. **成功失败能完全不一样**：文案、按钮、scope、broadcast 各自独立；不写某一态就是该态不做。
3. **Toast 与通知分开**：toast 管弹卡，notify 管发一条消息（`message` + `detail`），各自都能配 scope 和 broadcast。
4. **广播范围**：`'plugin'` 只让同项目消费者处理，`'global'` 跨插件。广播不带按钮（函数跨不了页）；
   谁要响应谁自己监听，核心不替消费方决定收到后干什么。
5. **列表按钮跟着记录走**：文案和 `when` 在发起时声明、原样存进记录；核心控件负责按状态筛选、画按钮、画进度。
6. **跨项目接收**：`mountTaskUI` / `mountTaskList` 的 `project` 写 `null` 即收所有项目；
   本页没有对应 handler 的按钮自动不画。
7. **刷新边界**：核心任务列表由核心自己刷；`onSettled` 只刷消费方自己的数据，没有就不写。

## 已澄清的几个点

- `field()` 只是消费方从 `detail` 安全取字符串的小工具，不是核心 API。
- `await startTask(...)` 等的是登记成功，不是任务跑完。
- 终态 `done` / `failed` 的按钮，只有记录还在列表里时才看得到；保留多久是核心/列表的展示策略。
- 本插件当前不需要自建广播通道；真有「改了东西让所有页面跟着变」的需求再说。
