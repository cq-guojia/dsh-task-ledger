## Process

已核实的代码事实（2026-11-01，均为当前 HEAD）：

- **身份闸门是一刀切且覆盖只读命令**：`packages/skill/src/internal/shell/runner.go:83-92` 所有命令先 `actions.CurrentIdentity(repo)`；例外只有 `whoami` / `root` / `init`，它们走 `packages/skill/src/internal/shell/cli.go:592-602` 的提前返回。`list` / `stats` / `owners` / `history` / `show` / `validate` 未初始化时全部报错退出。
- **固定错误句**：`packages/skill/src/internal/env/env.go:70-86`，未初始化输出 `这台机器还没有初始化身份。` 并附 init 指引，退出码 1。skill 侧 agent 的行为判据就是这一整句（SKILL.md「身份闸门」）。注意这是**文本**约定，没有机器可读错误码。
- **`whoami` 是例外**：未初始化返回 `{"uuid":null,"name":null}`、退出码 0（`packages/skill/src/internal/shell/render.go:323-336`，插件侧对应 `packages/plugin/src/host/repositories/identity.repository.ts:9-19`）。
- **插件首屏在没身份时是 500 而不是空板**：每个工作区 list/stats/owners 全失败 ⇒ `packages/plugin/src/host/errors.ts:89` 在「一个都没成功」时抛首个错误 ⇒ `packages/plugin/src/host/routes.ts:90-98` 转 500。
- **快照里的 `identities` 跟着 list 一起消失**：两者在同一个 `Promise.all` 里（`packages/plugin/src/host/services/stats.service.ts:79-85`），所以「先取快照、从快照里看身份」在没身份时走不通。
- **没有「未初始化」错误码**：`packages/plugin/src/host/errors.ts:12-17` 只有 5 个码（脚本不可用/超时/失败/非 JSON/数据非法），前端要判「是不是没身份」只能匹配 stderr 文本。
- **`init` 非 TTY 硬拒写身份**：`packages/skill/src/internal/shell/cli.go:694-701`（2026-10-26 事故后加），插件 host 调脚本永远非 TTY ⇒ 界面建/切身份必须另开入口。
- **一台机器一个身份**：`packages/skill/src/internal/actions/init_identity.go:64-75`，已初始化后再 `--claim` 别的 uuid 直接拒绝；`--new --name` 是幂等空转。即「换用户」在脚本层面**目前不存在**，只能手改 `~/.taskledger/identity.json`。
- **只改本机 name 改名无效**：`packages/skill/src/internal/env/env.go:80-84` 显示名优先取该工作区名册里同 uuid 的 name，名册有值就盖掉本机 name。
- **切身份后不需要手动入册**：任何写命令前的 bootstrap 会把自己登记进该仓库名册（`packages/skill/src/internal/actions/bootstrap.go:17`），只读浏览不入册。
- **台账身份与 git 账号无关**：`identity.json` 只影响 `ledger/*.json` 的 owner / creator 字段，不碰 git commit author。

第 1 项的落地口径（2026-11-01 拍板「等同登录闸」后推导）：

- 面板的渲染由**一个身份状态位**决定：为 null 时整个面板（看板 / 历史都在内，两者都过身份闸门）渲染引导页，不做局部提示。
- 因此身份为 null 时**连数据请求都不发**：并发一次打十几个请求再各自报「没身份」的场景从源头消失，不需要错误去重。
- 只有已经带着身份在跑、中途身份被外部删掉时，才会先失败一次；那一次把身份位置 null，面板自然变成引导页，即用户说的「啪就跳」。
- 代价：跳转会丢掉当前页的筛选 / 滚动状态，按登录页语义接受。
