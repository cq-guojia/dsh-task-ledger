## Background

现状：台账目录只能从 DSH `workspaceRegistry` 里来，插件全量扫一遍、只留含 `ledger/` 的（`packages/plugin/src/host/workspace.ts:23` `resolveWorkspaces`），后续所有数据全以这个列表为起点（`packages/plugin/src/host/routes.ts:121` `workspacesOf`）。

用户 2026-11-01 提出的问题（原话要点）：

1. 有些东西需要台账，但项目不在 DSH 的工作空间下；以后还可能单独包成 APP 或文件，那时根本没有「工作区」可找，就找不到台账目录了。
2. 有些项目在本机存在但长期不关心，希望在看板上能**隐藏**，让它在所有数据里都不出现。

诉求形态：机器级一份台账目录清单。手工能加（看板里选目录、自己取名）；打开看板时自动扫 DSH 全部工作区，发现台账就登记进去；隐藏 = 看板不显示。任何看板（DSH 插件、以后的网页端 / 应用端）都读同一份。

|---|---|
| 清单归属 | **机器级**（`~/.taskledger/` 同域，与 `identity.json` 并列） |
| 隐藏语义 | **只看板不显示，不是停用**：功能全部正常，agent 照常读写 |
| 删除 | 界面**只给隐藏，不给删除**。手动删了记录也正常 —— 只要那个目录还有台账、只要他再用一次 / 再进 DSH 点台账，它就会回来；这是预期行为，不做「永久忽略」 |
| 读时清理 | 进台账界面时逐个校验：目录已不存在（项目被移除）或已不是台账 ⇒ **自动把这条记录删掉**。清单本来就是程序生成的，不需要用户维护 |
| 路径写法 | 文件里**只存绝对路径**；显示层再缩成 `~/…`。比对前展开（`~` 由各读取方自实现的话必错，所以不进文件）。Windows：统一 `path.resolve/normalize`、比对前小写、家目录用 `os.homedir()` |
| 文件落点与形状 | `~/.taskledger/ledgers.json`；**路径当 key**（天然去重，不需要额外 id）：`{"/abs/path": {}, "…": {"name": "自取名"}, "…": {"hidden": true}}`。`name` 缺省用目录名 / DSH 工作区标题；`hidden` 缺省 false；删一行 = 记录没了，下次扫到会回来 |
| 写者分工 | **写只走 skill**（新增 `dirs` 子命令），插件 / 将来的 APP 只读文件。进看板时一次 `dirs sync` 合并「登记新路径 + 删失效 + 返回清单」，首屏只多一次进程调用 |
| 登记时机 | 不只在进看板时：**每次读写台账都比一次**（定位到台账根时看清单里有没有，没有就补）。效率不计较，一个文件的读写 |
| 与身份无关 | 未 init 的本机也必须能读写这个文件 —— 它跟身份没关系 |
| 隐藏的作用面 | **全局忽略**：八张统计卡、趋势、在办列表、历史列表、工作区下拉、**执行人下拉（`owners` 名册）全部不算它**。唯一能看到隐藏项的地方是「管理」界面 |
| 写失败 | 只读命令顺带登记清单失败 ⇒ **跳过 + 一行提示**，绝不改变命令结果（宁可清单少一条，也不能让查任务失败） |
| 并发 | 两个进程同时写要上锁：直接用 `store.ProgressLock`（`internal/store/locks.go:20`，按绝对路径 hash 开锁文件） |

### 2026-11-01 核实（源码事实）

- 身份闸门只在 `env.Current(repo)` 里（`packages/skill/src/internal/env/env.go:72-79`），action 不调它就不受约束 —— `dirs` 不调即可，`root` / `whoami` 已是先例，不需要新机制。
- 机器级文件的锁与原子写都是现成的：`store.ProgressLock(path)` 对任意绝对路径按 hash 开锁（`internal/store/locks.go:20`），写盘走 `internal/store/atomic.go`。不需要为它另造一套。
