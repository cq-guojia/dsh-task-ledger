## Background

现状：台账目录只能从 DSH `workspaceRegistry` 里来，插件全量扫一遍、只留含 `ledger/` 的（`packages/plugin/src/host/workspace.ts:23` `resolveWorkspaces`），后续所有数据全以这个列表为起点（`packages/plugin/src/host/routes.ts:121` `workspacesOf`）。

用户 2026-11-01 提出的问题（原话要点）：

1. 有些东西需要台账，但项目不在 DSH 的工作空间下；以后还可能单独包成 APP 或文件，那时根本没有「工作区」可找，就找不到台账目录了。
2. 有些项目在本机存在但长期不关心，希望在看板上能**隐藏**，让它在所有数据里都不出现。

诉求形态：机器级一份台账目录清单。手工能加（看板里选目录、自己取名）；打开看板时自动扫 DSH 全部工作区，发现台账就登记进去；隐藏 = 看板不显示。任何看板（DSH 插件、以后的网页端 / 应用端）都读同一份。

## To Do

- **待用户真机验收**：进 DSH 看板 → `~/.taskledger/ledgers.json` 应自动出现 DSH 各工作区（有台账的那些）；`--hide` 之后数据面全部不含它。
- 管理界面（隐藏开关 / 加目录 / 改名入口）：位置已定，挂「身份与设置」页，另开任务。
- 目录选择器：宿主有没有能选「工作区之外目录」的原生能力，未核实。

## Next

### 2026-11-01 核实（源码事实）

- 身份闸门只在 `env.Current(repo)` 里（`packages/skill/src/internal/env/env.go:72-79`），action 不调它就不受约束 —— `dirs` 不调即可，`root` / `whoami` 已是先例，不需要新机制。
- 机器级文件的锁与原子写都是现成的：`store.ProgressLock(path)` 对任意绝对路径按 hash 开锁（`internal/store/locks.go:20`），写盘走 `internal/store/atomic.go`。不需要为它另造一套。

## Conclusion

### 命令扩展与分层修正（2026-11-01 第二轮，用户指出三处）

用户原话要点：① 列出**默认就不该带隐藏项**，要看隐藏另给开关，否则每次都得自己过滤；② 外部台账删了不会自己回来，`--remove` 必须做，不能靠手改文件；③ 检查三层结构别写乱。

| 改动 | 内容 |
|---|---|
| 默认只列可见 | `ListDirs(includeHidden)`；`--all` 才是含隐藏。写命令回执仍给全量（调用方靠它判「已登记」，少给会让隐藏项每轮被重复补登记） |
| `--rename <新名>` | 改名；空串 = 清掉自定义名、回落目录名 |
| `--remove` | 从清单删一条，**不动磁盘目录**；目录还在宿主工作区里的话下次开看板会回来（预期行为） |
| 默认名归属 | 从外壳 / 插件里的 `filepath.Base` / `basename` 挪到 `actions.dirs.rowsOf` —— 「默认叫什么」是业务规则，只算一次 |
| host 分层修正 | `host/workspace.ts` 删掉：编排（读清单 → registry 补登记 → 过滤 hidden → 映射）挪到 `services/workspaces.service.ts`；清单读写留 `repositories/dirs.repository.ts`；`RegistryWorkspace` 类型归 `host/types.ts`。原 `workspace.ts` 既调 repository 又做编排，越过了 services 层 |

验证：`--all / --rename / --remove` 端到端跑过（含改名回落默认名、移除后清单为空、隐藏项不被重复登记且名字不被覆盖）。
