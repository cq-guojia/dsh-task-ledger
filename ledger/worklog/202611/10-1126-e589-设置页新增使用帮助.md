- **口径纠正（用户 2026-11-11）**：skill 有独立 npm 包 `task-ledger`（当前 1.3.58，2026-11-08 仍在发），`packages/skill/package.json:17` 的 `files` 就是整个 skill 目录（`SKILL.md` + `scripts/` + `references/` + `assets/`），所以安装说明应以 **npm 包**为入口，GitHub 仓库只是源、不是唯一装法。
- 但 `skills` CLI 的 `add` **不接受 npm 包名**（vercel-labs/skills 的 `docs/commands.md` 只列 Git / tree 子目录 / 本地路径 / 下载 URL；npm 来源只走实验性的 `experimental_sync`，且落点是项目级 `.agents/skills/`）。所以「用 CLI 一条装好」只能走 GitHub tree URL；「用包」就得 `npm i -g task-ledger` 后把目录复制/软链到各 agent 技能目录。
- 页面可复用件：`Surface` / `SectionHead` / `Table` / `ListRow` / `Tip` / `IconButton` / `notify`，以及现成的复制路径模式 `copyPath`（`settings-page.ts:405`）与 `GithubMark`（`:34`）；文案必须中英双份（`locales.ts`），键名集中列在 `SettingsLocaleKey`（`settings-page.ts:1379`）。
- 排版风险：现有各块正文最长只到一句 hint（`locales.ts:439-443`），本块文字量明显更大；已有的 `MarqueeText` 单行方案（`settings-page.ts:625`）会把命令截断，命令类内容不能用它。
- 实现落点（2026-11-11）：`settings-page.ts` 新增 `SKILL_SRC` / `SKILL_ADD` 常量与 `agentsBlock`（挂在规则注入 Surface 之后、`userModal` 之前）；复制逻辑由 `copyPath` 泛化成 `copyText(value, done)`，路径与命令共用一个 `copied` 状态；提示词文案用 `{cmd}` 占位，命令不两处硬编码。
- 事实分歧（未改 README，仅记录）：skills CLI 的 `docs/agents.md` 里 agent 标识符**没有 workbuddy**（只有 `codebuddy`），且 `codex` 的全局目录是 `~/.agents/skills/`，与 `README.zh-CN.md:61-63` 手写表的 `~/.codex/skills/`、`~/.workbuddy/skills/` 不一致 —— 页面因此不写目录、只写「应用内市场导入」。
- 实测（2026-11-11，`npx skills@1.8.1`）：
  - `add task-ledger` → 当 git 仓库克隆，`repository 'task-ledger' does not exist`；`add npm:task-ledger` 同样失败；`add --help` 里没有任何 npm 来源开关。**CLI 不认 npm 包名**。
  - `add https://registry.npmjs.org/task-ledger/-/task-ledger-1.3.58.tgz --list` → 识别出 1 个 skill（`task-ledger`），可用。
  - registry 不提供无版本 tarball（`-latest.tgz` / 无版本均 404）⇒ URL 必须带精确版本，改为构建期从 `packages/skill/package.json` 注入（`tsdown.client.config.ts` 的 `__SKILL_VERSION__`），产物里已确认是 `task-ledger-1.3.58.tgz`。
  - skillhub.cn 搜不到本仓的 `task-ledger` ⇒ 「应用内市场一键导入」不成立；「导入本地技能」必须先有本地目录，页面不写这条路。
