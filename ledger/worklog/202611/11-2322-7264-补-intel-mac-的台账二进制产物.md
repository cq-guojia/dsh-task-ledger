## Process

- 选路逻辑本来就对：`packages/skill/scripts/progress:18-25` 已把 `uname -m` 的 `x86_64|amd64` 映射成 amd64、拼出
  `bin/ledger-$os-$arch`，缺的只是这个文件，不是判断。
- 插件侧无需改 JS：`packages/plugin/src/host/repositories/runner.ts:18-27` POSIX 只起 shim，Windows 才直连 `ledger-windows-amd64.exe`。
- 产物：`GOOS=darwin GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w"` → Mach-O 64-bit x86_64、4194832 B；
  `go version -m` 与既有三份同规格（go1.27.1 / trimpath / CGO_ENABLED=0），源码无 `import "C"`。
- 校验（本机 go1.27.1 linux/amd64）：四平台全部编过（产物落 `/tmp`，不覆盖已入库三份：linux-amd64、darwin-arm64、windows-amd64.exe）；
  `go vet ./...` + `go test ./...` 全过。
- 模拟 darwin/x86_64（PATH 前置假 `uname`）：选中 `bin/ledger-darwin-amd64` 并 exec（linux 上 `Exec format error`、退 126 ⇒ 选路正确）；
  缺产物分支输出新提示语退 1；「文件在但不可执行」（假 `chmod` 退出 1）走另一条提示语退 1；本机 linux 原生路径照常退 0。
- 根因拦截：`packages/plugin/scripts/copy-skill.mjs` 构建期校验四份产物矩阵，移走 `ledger-darwin-amd64` 时构建 exit=1，
  补齐后 exit=0；`packages/plugin/skill/` 副本与 `packages/skill/` 源 sha256 逐份一致，`progress` / `SKILL.md` diff 为空。
- 文档同步：`SKILL.md:317`、`docs/api/ledger-api.md:55`、`docs/development/code-conventions.md:53` 三平台 → 四平台；`docs/README.md` 补更新日志。
