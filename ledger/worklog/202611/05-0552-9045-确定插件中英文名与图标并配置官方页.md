### 图标来源（2026-11-05 查证，仍未落码）

官方 Plugins 页有两个 tab：**Installed**（已装）与 **Discover**（市场），两者图标来源**完全不同**，不能混为一谈。

- **Installed 列表 / bundle 详情页 / 组件行** —— 读**包根 manifest 的 `icon` 字段**，或包导出的 `./icon` 子路径；两者都没有或图片解不出来就用默认图（`@deepseek-ai/dsh-client-ui-plugin-manager@0.2.2-rc.1` `README.md:38`）。对应本插件 ⇒ 查 `packages/plugin/package.json`。
- **Discover 卡片 / 条目详情 / 安装确认框** —— 读**插件索引 JSON 条目里的 `icon`**，值为 base64 `data:` URL 或绝对 URL，相对引用按索引 URL 解析，内联解码上限 32 KiB；请求失败回落默认图（`@deepseek-ai/dsh-plugin-market-index@0.2.2-rc.1` `lib/types/types.d.ts:71` + `README.md:47`；列表行为见 `@deepseek-ai/dsh-client-ui-plugin-market@0.2.2-rc.1` `README.md:31`）。索引是宿主 `pluginMarket` 服务抓的远程文档，**不在本仓库**。
- 本项目仓库内没有任何插件索引文件（无 `index.json` / 市场清单），Discover 那条路若要覆盖，得先有索引归属。
- 官方自家包（manager / market / inventory / market-index / settings）的 `package.json` **都没写 `icon` 字段**，没有可直接照抄的范例。
- 仍未证实：manifest `icon` 的取值形态（相对路径还是 data URL）与 SVG 是否被接受（"undecodable images" 暗示要能解码成位图）。host 侧解析实现尚未定位到包名。
