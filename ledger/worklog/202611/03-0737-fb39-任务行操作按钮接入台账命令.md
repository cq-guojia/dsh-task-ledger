- 「继续」为什么不做「塞进现有会话输入框」（2026-11-03 晚核实，宿主 0.2.0-rc.1）：
  - 写草稿的 `setDraft(text)` 只挂在**会话作用域**的门面上（`dsh-client-ui-conversation`

  - 本插件是根级 client 插件（`client/index.ts:36 PANEL_ID` 非 session 槽），拿不到某个会话的 `actx`。
  - 更根本：任务↔会话之间没有绑定字段，任务行只知道工作区；一个工作区有 N 个会话，
    「往哪个会话塞」没有答案，塞当前正在看的那个属于语义错位。
    结论：方案一的前置条件是先引入「任务↔会话」绑定，属另一个功能，本期不做。

  （preset 必须 mount / provider-model 不能留空走宿主缺省 / 建完必须 `attachSession` 才进工作区），
  兄弟插件同款实证 `dsh-task-dispatch-table/src/dispatch.ts:519`（create）、`:562`（attach）、`:627`（send）。
- 提示词的解耦原则（用户 2026-11-03 三次纠正后定）：注入文本里**不许出现**文档章节名、
  具体命令、脚本路径、工作区路径、环境自述。只允许依赖「任务号」与「task-ledger skill 存在」两件事，
  否则 skill 或过程文档模板一改，提示词就得跟着改。
- 「完成」为什么用官方客户端会话面，而不是自己造轮子（2026-11-03 晚核对
  `@deepseek-ai/dsh-api-session-controller@0.2.0-rc.1`，与本机宿主同版本线）：
  - `ctx.sessions.create({workspaceId|cwd|sessionId}) → SessionId`（`lib/types/client/contract/sessions.d.ts:88-93`）
    —— 宿主自己归组工作区，**不需要** host 侧 `agents.create` + preset mount + `attachSession` 那套；
  - `retain(id,{source})` / `using(...)` 拿 `SessionReference`（`.ready`、`.binding.session`）（同文件 `:52`、`:63`）；
  - `face.prompt(parts,'queue'|'steer')`（`contract/session.d.ts:82-84`）、`face.rename(title)`（`:117`）；
  - **回调面**：`SessionFace = ISession & ObservableSnapshot<SessionSnapshot>`（`:156`），快照带
    `running: boolean`（宿主流驱动）与 `lastAgentError: string | null`（`contract/snapshot.d.ts:62`、`:75`）；
  - 客户端 `Context` 上直接有 `sessions: ISessions`（`lib/types/client/index.d.ts:24-27`），
    `source` 标签可用 declaration merging 自己加（`:18-25`）。
  - 由此**撤回**本轮早前两版建议：① 自建 host 路由 + 定时轮询（判据靠猜，垃圾）；

    模型自述可能幻觉，权威判据是台账本身；`running` / `lastAgentError` 只回答「跑完没 / 为什么挂」。

## Conclusion

- 认领：点击 → `confirmModal` 确认 → `POST /task/action` → skill `claim` → 绿色 Toast「已认领：{标题}」→ `refresh()` 重读首屏。
- 释放：点击 → `confirmModal` 确认 → `POST` → skill `set --release` → Toast「已释放：{标题}」→ 同上重读。
  两个动作共用同一段确认逻辑，只是标题 / 正文 / 确定键三处文案按动作取 key。
- 失败：红色 Toast，正文是 host 转发的人话（如「公共池里没有任务 X（已经被人认领或不存在）」）。
- 取消：点叉 → 弹窗（正文点名任务 + 理由输入框，可留空）→ 确定 → skill `close --cancel --summary`；
  成功关窗 + 绿 Toast「已取消归档：{标题}」→ 重读首屏；失败红字留在弹窗里（不关窗），改完理由可直接重试。
- 请求在途时该行整排动作钮（含取消、继续 / 完成）disabled，连点不会重复发写命令。
- loading 不写死宽度：有 icon 的（刷新 / 保存名 / 保存重命名 / 创建用户）交给核心换图标位；
  无 icon 的（使用此人 / 添加目录 / 取消弹窗确定键 / 认领释放确认框）传 `loadingText: false`，
  核心自己锁宽。图标钮（移除目录 / 删除用户）核心 CSS 已定宽定高，换圈不跳。
  `ConfirmModal` 也支持 `loadingText`（0.23.0 起透传给两颗钮）。
- 设置页异步按钮全部补 loading：目录保存/移除走 `dirBusy === rename:path / remove:path`，
  添加目录走 `dirBusy === "add"`（`addDirFromPicker` 选完目录才进忙态），删除用户走
  `pending === forget:uuid`。`ui.ts` 的 `IconButton` 包装补了 `loading` 透传（原来没接）。
- 本包 `npm run verify`（build + typecheck）通过；真机未点。

   会话 cwd = 该工作区路径；随后客户端跳转到该会话。
4. **注入提示词定稿**（只读 → 汇报 → 停下；不含任何章节名 / 命令 / 路径）：
   「请先只读了解任务 `{{id}}` 的当前进度，汇报完停下。」+ 三步（读 / 报 / 停）+ 四条硬约束。
   两条反编造要求：报告首行写过程文档路径；查不到就贴错误停下，不许模糊搜、不许猜任务号、
   不许另找文档顶上、不许当成已完成汇报。硬约束含「不写文件 / 不装依赖 / 不跑构建 / 不动 git /
   不执行 skill 的任何写操作 / 不新建会话与子 agent / 不新建台账任务」。
5. **会话标题**：原提议 `继续：{任务名}`，**本轮没做** —— 宿主建会话时只有 `meta.cwd` / `agentPreset`，
   改名要另调 sessions 接口，留作待定。
