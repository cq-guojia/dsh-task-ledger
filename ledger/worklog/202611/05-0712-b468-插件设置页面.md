## Background

用户 2026-11-05 原话开题：「在官方的插件界面点开，里面有设置，就是我们现在要做设置页面的功能」——即在设置页补齐**插件自身的配置项与对外链接**，分四块：

1. **项目链接**：设置页里给出本仓库 GitHub 的链接。
2. **友情链接**：另加一个 UI 基础控件包（组件库）的 GitHub 链接，形似「友情链接」。用户暂称「蓝鲸组件库」，明确说这个名字不好，要几个备选再定。
3. **设置项 A —— 插件入口位置**：可选「一级菜单」（= 现状，侧栏 `sidebar.panellist` 条目）或「更多」（收进「更多」菜单里）。用户说这段逻辑跟 `dsh-plugin-core` 那个 demo 差不多。
4. **设置项 B —— 自定义显示名**：默认「蓝鲸任务台账」；用户自己设了就用他的覆盖掉默认值；**若他设的内容与默认字面相同，则不落盘，仍走默认**。

版式口径（同一条消息里定的）：

- 设置页的**版式 / 规格参考 `dsh-session-title-pattern`**（含它前面的标题推送与存放规格），不参考 `dsh-plugin-core` 的 demo。
- **组件不得自绘**、也不用 `dsh-plugin-core` 的自绘控件 —— 直接用宿主官方 primitives。

## Process

已核实（2026-11-05）：

- 现状入口 = `sidebar.panellist` 一条 + `main` 整页，label 走 `runtimeT("panelTitle")`：改动前 `packages/plugin/src/client/index.ts:133`-`156`。
- 「更多」菜单槽 = **`sidebar.panellist.actions`**，注册一行 `MenuItemButton`（owner 给 `onDismiss`）：`dsh-plugin-core/packages/demo/src/client/index.tsx:113`-`137`。
- 配置区槽 = **`plugins.bundle.config`**（keyed，key = 包名，只渲染 `view: 'page'`）：`@deepseek-ai/dsh-client-ui-plugin-manager@0.2.0-rc.1` `lib/types/client/slot-contract.d.ts:100`、`lib/client.js:2527`。
- 存放规格 = 宿主设置文档：host 侧 `export const Config = z.object({...volatile()})`（命名空间 = entry id = 包名），client 侧 `ctx.configForms.get(ns)` + 官方 `SettingsFormModel`；参考 `dsh-session-title-pattern/src/client/index.tsx:611`-`662`。槽位 owner 直接投喂的 `form` 只有 `{state, mutate}`、不可订阅 ⇒ 必须走 `configForms`。
- 官方设置表单**没有单选/布尔字段工厂**（只有 `settingsTextField` / `settingsNumberField`），两选一自己拼 `SegmentedControl`，值仍走文本字段：`primitives@0.2.0-rc.1` `lib/types/settings-form/*.d.ts`。
- `SettingsFormModel.resetField()` 同步 stage `{clear:true}`、`save()` 当场读 staged ⇒ 「保存前折成清空」成立（实现见 `primitives` `lib/index.js:7116`、`save()` 段）。
- 坑：`schemastery` 静态 import 会拖垮整个 server entry（demo 2026-10-25 真机事故）⇒ 本仓用动态 import + `Config = undefined` 兜底。
- 坑：本仓 host 侧开 `declaration: true`，本地 `schemastery.d.ts` 里的类型必须 `export`，否则 TS4023（`Config` 的类型无法命名）。
- **真机现象（2026-11-05）**：本地 link 装进宿主后，插件详情页那块显示「设置当前不可用」——client 与槽位都对（这句就是 `SettingsForm` 的 `unavailable` 文案），缺的是 host 侧 schema：`ctx.configForms.get(ns)` 的 `status` 不是 `ready`。
- **根因实测**：`cd packages/plugin && node -e "import('@deepseek-ai/schemastery')"` → `ERR_MODULE_NOT_FOUND`。插件从自己的 `node_modules` 往上找，到不了宿主 profile，所以 `Config` 兜底成 `undefined`、宿主不派生命名空间。
- **修法**：照 `dsh-plugin-core/packages/demo/package.json:62` 的口径加依赖并安装 —— `@deepseek-ai/schemastery@^3.18.5`（pnpm，落到本包 `node_modules`）。装后 `import('./dist/index.js')` 的 `Config` 是真 schema：wire 里 `entryMode` 默认 `first`、`displayName` 默认 `""`，两者都 `volatile`。
- 另：client 侧 ⑥ 块补了 `resolveSettingsNamespace`（问宿主 `describe()` 取实际登记的 ns，取不到回落包名）与三条控制台日志，下次再出问题看日志就能定位。
- **版式返工（用户 2026-11-05：「我让你去抄」）**：照 `dsh-session-title-pattern/src/client/model-pair.tsx` + `style.ts` 的 `.stp-*` 一套（用户指定）：两字段一行各半、入口位置由分段控件改**下拉**（官方 `Menu` + 触发按钮，官方表单体系没有下拉字段工厂）、保存与两个链接同排且保存最前、改没改的提示照官方字段（「已自定义」徽标 + 「恢复默认」）。
- 由此**弃用官方 `SettingsForm` 外壳**：它的保存按钮固定在自己的 footer 里，没法与链接同排。保存按钮改官方 `Button`，`dirty/invalid/saving/failed` 仍来自 `SettingsFormModel`；外壳原本管「离开页面丢弃草稿」，改在本组件卸载时自己调 `discard`。样式 `.dtl-config__*` 写进 `ui.ts` 的 `UI_BASE_CSS`（同一注入器），详情页不经过看板，故组件里唤一次 `ensureUiBase()`。
- **样式统一 + 分隔线（用户 2026-11-05 二轮）**：两处「已自定义」原来一彩色小字、一官方件，用户要求统一 —— 查官方 `fields.js` 得知那是 `Tag`（`tone: 'neutral'`），入口位置字段改为同一件官方 `Tag`，未改过时整组（徽标 + 恢复默认）都不渲染，与官方字段完全同形；`.dtl-config__overridden` 删除。字段区顶部 `border-top`、保存行 `border-bottom`（实线 `--dtl-border`），保存行上方间距 36px（字段内距 12 + 外边距 24）。
